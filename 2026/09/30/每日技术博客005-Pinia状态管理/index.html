七、组合式写法

两种写法怎么选

选项式 组合式
写法 传对象 { state, getters, actions } 传函数，返回变量和函数
心智模型 类似 Vuex 和 <script setup> 完全一致
复用逻辑 较难 可以调用其他 composable
适合 简单 store、团队已有 Vuex 习惯 复杂 store、要复用逻辑

组合式写法的最大优势：和你已经熟悉的 <script setup> 是同一套心智模型，不用再学一遍。

八、store 和 props 怎么选

数据特征 用什么
只给一个子组件用 props
父子之间来回改 v-model
隔好几层才能用到 provide / inject
多个页面 / 多个组件共享 pinia
需要持久化 pinia + $subscribe

判断标准：这份数据有几个「不相关」的组件在用？ 超过一个就该考虑 store。

常见坑清单

  • 直接解构 store 导致丢响应式（要用 storeToRefs）
  • 用 storeToRefs 去解构 action（拿不到，action 直接从 store 取）
  • action 写成箭头函数，this 拿不到 store
  • defineStore 的 id 重复，导致多个 store 串数据
  • 把本该用 props 传的局部数据塞进全局 store，导致状态来源难以追踪
  • 持久化只写了 $subscribe 存，忘了初始化时读回来
  • 在 store 里直接改另一个 store 的 state，形成隐式耦合

开场：组合式函数就是普通函数

没有任何特殊语法。 一个用到 Vue 响应式 API 的普通函数，命名以 use 开头，就是组合式函数（composable）。

mixin 的坑它天然免疫 —— 因为数据来源是显式 import 的，不是隐式合并的。

一、为什么不用 mixin

mixin 的三个经典问题：

问题 表现
来源不明 组件里出现一个 loading 变量，不知道是哪个 mixin 注入的
命名冲突 两个 mixin 都有 loading，后注册的静默覆盖
隐式依赖 mixin 依赖组件的 data 字段，删掉组件字段就崩

组合式函数的做法：要什么就 import 什么，返回值自己起名。

三、四个真实场景

1. 数据请求：useRequest

用 shallowRef 装接口数据：整体替换，不需要深层代理，性能更好。

2. 本地存储：useLocalStorage

3. 防抖：useDebouncedRef

4. 事件监听：useEventListener

关键点：onMounted / onBeforeUnmount 可以在组合式函数里调用，它们会绑定到当前组件实例。所以清理逻辑可以封在函数内部，调用方不用管。

四、组织约定

目录与命名

约定 说明
命名以 use 开头 一眼看出是组合式函数
文件名与函数名一致 useCounter.ts 导出 useCounter
一个文件一个函数 除非是紧密相关的一组
参数用对象 useRequest(fn, { immediate: true }) 比位置参数好扩展

⚠️ 不要在组合式函数里调用 onMounted 之后再做 await。 组件实例只在同步执行阶段可用，异步之后调用生命周期钩子会失效。

五、几个边界

组合式函数 vs 工具函数

组合式函数 纯工具函数
用 Vue API ✅ ❌
能调生命周期 ✅ ❌
例子 useRequest、useLocalStorage formatDate、debounce

纯计算逻辑不要写成组合式函数，放 utils/ 就行。

组合式函数 vs Pinia store

组合式函数 Pinia store
状态作用域 每个调用者一份独立状态 全局共享一份
适合 组件内部逻辑复用 跨组件共享数据

要共享状态就用 Pinia。 组合式函数默认是「一次调用一份状态」。

常见坑清单

  • 返回值里写了 count.value，导致丢响应式
  • 在组合式函数里 await 之后再调用 onMounted（组件实例已失效）
  • 需要跨组件共享状态却用组合式函数，结果各自一份数据
  • 纯计算逻辑也写成组合式函数（应该放 utils/）
  • 事件监听 / 定时器在组合式函数里注册了却没清理
  • 参数用一长串位置参数，后续没法扩展
  • 在模块顶层创建共享状态，SSR 下跨请求污染
  • 组合式函数里直接 import 某个 store，导致函数只能在有该 store 的场景用

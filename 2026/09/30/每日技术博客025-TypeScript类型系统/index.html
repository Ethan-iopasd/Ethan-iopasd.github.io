TypeScript 的类型系统只有两个动作：组合（联合 / 交叉 / 泛型）和收窄（把宽类型缩到窄类型）。其余都是这两件事的语法糖。

开场：type 还是 interface

官方手册的原话是「多数情况下按个人偏好选」，给的启发式规则是：**先用 interface，遇到它做不到的再用 type**。

能力 interface type
描述对象 / 函数签名 ✅ ✅
extends 继承 ✅（可多继承） ✅（用交叉 &）
声明合并（同名自动合并） ✅ ❌ 重复声明直接报错
联合类型 A | B ❌ ✅
交叉类型 A & B 仅 extends 形式 ✅
元组、映射类型、条件类型 ❌ ✅
模板字面量类型 ❌ ✅
编译性能 更好（有缓存，extends 快） 交叉类型需要展开计算
错误信息 更清晰（保留名字） 复杂别名会展开成一大坨

⚠️ 不要用 interface 描述联合或元组，写不出来只能绕。反过来，对外暴露的公共 API 优先 interface —— 交叉类型 A & B 冲突时不会报错，而是把冲突字段推成 never，排查起来很痛苦。

一、联合、交叉与字面量类型

运算符 语义 赋值要求
A | B 并集 满足任一个即可
A & B 交集 必须同时满足

不加 as const 时 ROUTES.home 的类型是 string，加了大不一样。

⚠️ as const 会让对象递归只读，ROUTES.home = '/x' 直接报错。另外它也会让数组变成 readonly 元组，push 不可用 —— 需要可变副本时用 [...arr] 展开一份。

二、类型收窄

收窄 = 编译器根据控制流把宽类型缩到窄类型。**typeof / in / instanceof / 判别联合是内置的，其余靠自定义守卫。**

手段 适用 例子
typeof 原始类型 typeof v === 'string'
instanceof 类实例 e instanceof RangeError
in 判断属性存在 'radius' in shape
真值收窄 剔除 null / undefined if (user) user.name
相等收窄 字面量比较 if (s === 'done')
判别联合 靠公共字面量字段 switch (s.kind)
自定义守卫 返回 x is T function isUser(v): v is User
断言函数 返回 asserts x is T assertIsUser(v)
satisfies 校验但不改推断 {...} satisfies Config

判别联合（discriminated union）

最实用的一个模式：每个成员带一个公共字面量字段，switch 它就能自动收窄。

⚠️ 判别字段必须是字面量类型。写成 kind: string 就收窄不了 —— 联合会退化成「每个成员都可能匹配」。用 as const 或 satisfies 保证字面量不丢。

自定义类型守卫与断言函数

形式 返回类型 调用点效果
守卫 v is T 放进 if 里生效
断言 asserts v is T 调用之后整个作用域生效
断言（非空） asserts v 只能断言真值，常用于 assert(x != null)

⚠️ 类型守卫是你对编译器的承诺，编译器不会验证实现。function isUser(v): v is User { return true } 也编译通过 —— 守卫写错等于关掉了类型检查。

satisfies：校验但不改推断

用 const config: Record<...> = {...} 的话，config.port 会被宽化成 string | number，.toFixed 报错。

三、泛型：约束、默认值与推导

位置 写法 作用
约束 <T extends U> 限制可传入的类型
默认值 <T = string> 不传时兜底
同时 <T extends U = U> 有默认值但默认值也要满足约束
推断位 只在参数里出现 由实参反推

keyof、typeof、索引访问

运算符 输入 输出
keyof T 类型 键的字面量联合
typeof v 值 值的类型
T[K] 类型 + 键 对应属性的类型
T[number] 数组类型 元素类型

⚠️ keyof 和 typeof 的方向相反：typeof 是值 → 类型（只能用在值上），keyof 是类型 → 键联合（只能用在类型上）。keyof typeof obj 是常见组合写法。

泛型推导失败的两个原因

现象 原因 修法
推断成 unknown 参数没出现在任何泛型位 显式传 <T>，或改签名
推断过宽 用了 as const 之外的普通对象字面量 加 as const / satisfies
泛型被合并成联合 多个参数用同一个 T 拆成 <T, U>
想保留字面量但被宽化 约束写成 string 而非 extends string 用 T extends string

四、unknown 与 any

维度 any unknown
能赋值给任意类型 ✅ ❌ 需要收窄
能读任意属性 / 调用 ✅ ❌ 编译报错
能接收任意值 ✅ ✅
传染性 强，一路污染下去 无，必须显式收窄
定位 关闭检查 类型安全的 any

⚠️ **strict 下 catch 的变量是 unknown**（useUnknownInCatchVariables，TypeScript 4.4 起默认随 strict 开启）。catch (e) { e.message } 会报错，得先 e instanceof Error。

几个容易混的顶层类型

类型 含义 常见误用
unknown 任意值，用前必须收窄 —
never 不可能存在的值 被用来当「任意类型」
void 函数无返回值 与 undefined 混用
object 非原始类型（不含 null） 以为是「任意对象」
{} 除 null / undefined 外的任意值 能接收 string、number
Object 几乎等于 {} 别用

⚠️ {} 是「非空值」的意思，'a'、1、true 都满足它。想表达「任意对象」用 object 或 Record<string, unknown>。

常见坑清单

  • 用 type 写公共 API 类型，报错信息展开成一大坨，不如 interface
  • 用 A & B 合并两个有同名字段但类型不同的接口，字段被推成 never
  • 判别联合的 kind 写成 string 而不是字面量联合，收窄失效
  • 忘了 as const，对象的键类型被宽化成 string
  • as const 之后直接改数组，忘了它是 readonly 元组
  • 类型守卫实现写错，v is T 说谎，等于关掉检查
  • 用 as 断言代替收窄，绕过检查而不是证明类型
  • keyof 用在值上、typeof 用在类型上，方向搞反
  • 泛型参数没出现在参数列表里，推断成 unknown 却以为是 bug
  • 用 {} 表示「空对象」，结果 string、number 都能赋进去
  • 用 any 图省事，污染扩散到整条调用链
  • catch (e) 里直接访问 e.message，strict 下 e 是 unknown

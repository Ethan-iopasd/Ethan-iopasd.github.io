开场：组件测试只有三件事

挂载、交互、断言。 90% 的失败不是断言写错，而是没有等 DOM 更新或没有 mock 外部依赖。

Vitest 是 Vue 官方文档推荐的测试运行器（基于 Vite，原生处理 .vue 文件）。

⚠️ environment 默认是 node。组件要操作 DOM，必须切成 jsdom（或 happy-dom），否则 document is not defined。

一、mount 与 shallowMount

mount 是 @vue/test-utils 的主要方法：创建一个 Vue 应用并渲染被测组件。

API 行为 适用
mount(Comp) 渲染组件及其全部子组件 集成测试，验证父子联动
shallowMount(Comp) 子组件替换为 stub 单元测试，隔离被测组件

最常用的断言入口：

调用 返回
wrapper.text() 去标签后的文本
wrapper.html() 渲染出的 HTML
wrapper.find('.btn') 首个匹配的 DOMWrapper（不匹配不会报错）
wrapper.findAll('li') DOMWrapper[]
wrapper.findComponent(Child) 子组件实例 wrapper
wrapper.emitted('change') 该事件所有 emit 参数数组
wrapper.vm 组件实例（仅 mount 有真实实例）

⚠️ wrapper.find() 找不到元素时不抛错，返回一个空的 DOMWrapper。后面 .trigger() / .text() 才炸，堆栈指向错误行。断言前先确认 exists()。

二、异步更新必须 await

Vue 的响应式更新是异步批处理的：改数据后 DOM 不会立刻变，要等微任务队列清空。

@vue/test-utils 里几个方法本身就返回 nextTick 的 Promise，await 它们等于顺带等更新：

方法 返回
wrapper.trigger('click') Promise<void>，resolve 于 nextTick
wrapper.setValue('abc') 同上
wrapper.setChecked(true) 同上
wrapper.setProps({ x: 1 }) 同上（内部也 nextTick）
wrapper.vm.count = 1 ❌ 同步赋值，不返回 Promise

三、Mock：vi.mock / vi.fn / vi.spyOn

API 作用 典型场景
vi.fn(impl?) 造一个可断言的假函数 回调、props 传参
vi.spyOn(obj, 'm') 包装已有方法，保留原实现（可选） 断言 console.error 被调用
vi.mock(path, factory) 整个模块替换，会被提升到文件顶部 替换 @/api/*、vue-router
vi.hoisted(fn) 把变量也提到顶部 factory 里要引用外部变量

⚠️ vi.mock 的工厂函数会被提升到所有 import 之前。factory 里直接引用顶层 const 会报 Cannot access before initialization —— 这就是 vi.hoisted 存在的理由。

Pinia 与 Router 的测试替身

⚠️ stubActions: true 时 action 不会真的改 state。要测真实逻辑就传 stubActions: false，否则会看到「调了 action 但 state 没变」。

四、常见「改了数据但断言失败」的原因

按排查顺序：

现象 原因 修法
断言旧值 没等 nextTick await nextTick() 或 await wrapper.trigger(...)
数据没变 解构丢了响应式：const { count } = props 用 toRefs(props) 或直接 props.count
state 没变 createTestingPinia 的 stubActions 默认拦截 stubActions: false
元素找不到 shallowMount 把子组件 stub 掉了 换 mount，或给 stubs 传真实组件
wrapper.vm 报错 用了 shallowMount，或组件用了 <script setup> 断言 DOM / emitted，不要依赖 vm
emitted 为空 事件名大小写不匹配 模板里用 kebab-case 时 emitted('my-event')
整个组件为空 忘了装插件（pinia / router / i18n） global.plugins
时序随机 依赖真实时间 vi.useFakeTimers() + vi.advanceTimersByTime()
环境报错 environment: 'node' 改 jsdom
泄漏到别的用例 没 restoreAllMocks / 没 wrapper.unmount() 加 beforeEach / afterEach

⚠️ <script setup> 的组件默认是 closed 的实例，wrapper.vm 拿不到内部变量。测试请面向渲染结果和 emitted 事件，而不是内部实现 —— 这样重构也不会碎。

假定时器

⚠️ 假定时器会冻结 nextTick 的微任务调度时机（它依赖 Promise，不受影响，但 debounce 用的宏任务受影响）。advanceTimersByTime 之后仍要 await nextTick()。

五、Vue DevTools 调试响应式

Vue DevTools v7 只支持 Vue 3（Vue 2 需要旧版 v6）。调试要点：

面板 用途
Components 查看组件树、选中组件后实时编辑 props / setup state
Pinia 查看每个 store 的 state / getters，可手动改 state 触发更新
Router 当前路由、路由表、参数
Timeline 事件、性能、组件渲染的时间轴
Inspector 检查注入的 provide/inject、自定义 inspector

关键开关

自定义 inspector：把业务状态挂到面板

用 @vue/devtools-api 的 setupDevtoolsPlugin，可以给自己的状态管理/数据层做一个专属面板。

⚠️ 页面用的是生产构建的 Vue（vue/dist/vue.runtime.esm-bundler.js 且 NODE_ENV=production）时，DevTools 面板默认不显示。本地调试务必跑 vite dev，别用 vite preview 排查响应式问题。

排查响应式失效的固定套路

症状 根因
模板不更新 改了 toRaw() 出来的原始对象
数组 push 不更新 用的是 reactive 之后解构出来的普通数组副本
props 变了但 watch 不触发 watch(() => props.obj.x) 写法对，但 watch(props.obj, ...) 只是取了一次值
computed 不重算 内部依赖了非响应式来源（如模块级 let、Date.now()）
组件不重渲染 v-once、v-memo 命中，或列表 key 用了 index 导致复用

常见坑清单

  • test.environment 没设成 jsdom，组件一渲染就 document is not defined
  • 改完 wrapper.vm.xxx 直接断言，忘了 await nextTick()
  • 用 await nextTick() 等 fetch，应该用 await flushPromises()
  • vi.mock 的 factory 里引用外部变量，没包 vi.hoisted
  • createTestingPinia 保持默认 stubActions: true，却断言 state 变化
  • shallowMount 把要断言的子组件 stub 掉了
  • 对 <script setup> 组件用 wrapper.vm 断言内部变量
  • 断言 emitted('myEvent')，但模板里 emit 的是 my-event
  • 忘了 global.plugins 装 pinia / router / i18n，整个组件渲染为空
  • 用例之间没 restoreAllMocks / 没 unmount，前一个用例污染后一个
  • 用假定时器后没调 vi.useRealTimers()，后续用例时间不走
  • 在 vite preview（生产构建）上排查响应式问题，DevTools 面板根本不显示

开场：排查先看三个数字

磁盘满、内存高、进程不在 —— 线上 80% 的「服务挂了」都能归到这三类。先跑这三条：

一、权限

看权限

数字含义

数字 权限 对文件 对目录
4 r 读取内容 列出文件名
2 w 修改内容 创建/删除文件
1 x 执行 进入目录（cd）

⚠️ 目录的 x 位是「能否进入」。目录只有 r 没有 x，ls 能看到文件名但读不到详情，也 cd 不进去。
目录的 w 位是「能否增删文件」，和文件本身的权限无关 —— 这就是为什么删除文件看的是父目录权限。

所有权

特殊权限位

位 数字 作用 典型场景
SUID 4000 以文件所有者身份执行 passwd
SGID 2000 以文件所属组身份执行；目录下新建文件继承组 共享目录
Sticky 1000 只有文件所有者能删 /tmp

umask：新建文件的默认权限

计算方式：默认权限 − umask

默认 umask 结果
文件 666 022 644
目录 777 022 755

⚠️ 文件默认不带 x（不会出现 777 的文件），这是刻意的安全设计。

sudo 与 su 的区别

su sudo
需要 目标用户的密码 自己的密码
粒度 整个身份切换 可按命令授权
审计 弱 有日志

⚠️ 不要把服务跑在 root 下。 用专用用户 + 最小权限。

二、进程

查看

ps aux 各列：

列 含义
USER 运行用户
PID / PPID 进程号 / 父进程号
%CPU / %MEM CPU / 内存占比
STAT 状态（见下）
START / TIME 启动时间 / 累计 CPU 时间
COMMAND 命令行

STAT 常见值：

值 含义
R 运行中
S 可中断睡眠（等 I/O，最常见）
D 不可中断睡眠（等磁盘 I/O，kill -9 也杀不掉）
Z 僵尸进程（已结束但父进程没回收）
T 停止

⚠️ D 状态杀不掉是正常的，它在等内核 I/O 返回。要查是不是磁盘有问题。
⚠️ 僵尸进程不能直接杀，它已经死了。要么等父进程回收，要么处理父进程。

结束进程

信号 编号 能否被捕获 用途
SIGTERM 15 ✅ 默认，优雅退出
SIGKILL 9 ❌ 强制杀，不给清理机会
SIGINT 2 ✅ Ctrl+C
SIGHUP 1 ✅ 重载配置

⚠️ **优先用 kill 而不是 kill -9**。-9 会让进程没机会关闭连接、刷缓冲、删临时文件。
只有 kill 无效时才用 -9。

常见坑清单

  • 目录没有 x 位，cd 不进去
  • 以为删除文件看文件自身权限（其实看父目录的 w）
  • 用 chmod -R 777 解决权限问题（安全事故的起点）
  • 服务跑在 root 下
  • 习惯性 kill -9，进程没机会清理资源
  • 想杀掉 D 状态进程（杀不掉，得查 I/O）
  • 想杀掉僵尸进程（它已经死了，要处理父进程）
  • 只看 free 那列判断内存不足（要看 available）
  • 磁盘满了只查空间不查 inode（大量小文件场景）
  • rm 掉正在写入的日志文件，空间不释放
  • 用 netstat 而不是 ss
  • uptime 负载高就断定 CPU 不够（可能是 I/O 等待）

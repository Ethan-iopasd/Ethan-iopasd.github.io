开场：路由就是一张「路径 → 组件」的映射表

单页应用只加载一个 HTML，页面切换全靠 JS。路由负责三件事：改地址、查表、把组件渲染到指定位置。

二、history 还是 hash

地址美观度 好，无 # 差，带 #

为什么 history 刷新会 404？ 用户直接访问 /home 时浏览器真的向服务器请求了这个路径，服务器上没有这个文件。

⚠️ GitHub Pages 不支持这种重写规则。部署到 Pages 的 SPA 要用 hash 模式，或加 404.html 跳转 hack。

⚠️ 规则一：对象写法传 params 必须用 name，不能用 path。

七、replace 与重定向

push 是追加历史记录，replace 是替换当前记录。

用在：登录成功后跳转、支付完成后跳转 —— 用户按后退不该回到那些页面。

根路径 / 通常没有对应组件，加一条重定向避免白屏。

八、一个容易忽略的行为：切走的组件会被卸载

点击导航后「消失」的路由组件，实际是卸载了（触发 onUnmounted），再进来时重新挂载。

后果：ref 数据重置、输入框内容丢失、每次进入都重新发请求。

常见坑清单

  • 对象写法传 params 用了 path（参数静默丢失）
  • 路由规则里忘了写 :id 占位符（params 同样丢失）
  • 子路由 path 加了 /，导致不再是嵌套路由
  • 嵌套路由的父组件忘了留 <RouterView>
  • 用 history 模式部署到纯静态托管，刷新 404
  • 混淆 useRoute() 和 useRouter()
  • 登录成功后用 push 而不是 replace，按后退又回到登录页
  • 依赖路由组件内的输入状态，却忘了它切换时会被卸载

开场：状态码是给中间层看的

状态码不只是给前端判断用的 —— 代理、网关、CDN、监控、浏览器缓存都靠它决定行为。用错了，缓存和重试逻辑都会跟着错。

一、状态码分类

区间 含义
1xx 信息，临时响应
2xx 成功
3xx 重定向 / 缓存
4xx 客户端错误
5xx 服务端错误

最常被误用的几个

码 正确含义 常见误用
200 成功 用 200 包着 {code: 500} 返回错误 ❌
201 创建成功 创建接口返回 200
204 成功但无响应体 DELETE 返回 200 + 空 JSON
301 永久重定向，会被缓存 临时跳转用了 301
302 临时重定向 长期迁移用了 302
304 资源未修改，用本地缓存 ——
400 请求格式错误 参数校验失败一律 400
401 未认证（没登录 / token 无效） 和 403 混用
403 已认证但无权限 和 401 混用
404 资源不存在 ——
405 方法不允许 用 404 代替
409 冲突（如唯一键重复） 用 400 代替
422 语义错误（格式对但值不合法） ——
429 请求过于频繁 限流返回 403
500 服务端未预期错误 什么都返回 500
502 网关收到上游的无效响应 ——
503 服务不可用（过载 / 维护） ——
504 网关等待上游超时 ——

⚠️ 401 和 403 的区别：401 = 「你是谁？先登录」。403 = 「我知道你是谁，但你不能做这个」。
搞混会让前端无法决定是跳登录页还是提示无权限。

⚠️ {code: 200, data: {...}, msg: '失败'} 这种设计让所有中间层失去判断依据 —— 代理不会重试 5xx，监控统计不到错误率，CDN 不知道能不能缓存。HTTP 状态码该用就用。

502 / 503 / 504 怎么快速定位

码 通常意味着
502 上游进程崩了、端口没监听、上游返回了非法响应
503 上游过载被限流、正在发布重启、主动熔断
504 上游处理超时（不是网关自己超时）

二、缓存：两个阶段

浏览器缓存分两步：先看强缓存，不命中再走协商缓存。

强缓存

靠 Cache-Control（HTTP/1.1）或 Expires（HTTP/1.0，已过时）。

指令 含义
max-age=3600 3600 秒内直接用本地副本，不发请求
no-cache 可以缓存，但每次都要协商验证
no-store 完全不缓存（敏感数据）
public 允许 CDN / 代理缓存
private 只允许浏览器缓存，CDN 不缓存
must-revalidate 过期后必须验证，不能用过期副本
immutable 有效期内连刷新都不重新验证

⚠️ **no-cache ≠ no-store**，这是最常被搞混的一对。
no-cache 是「缓存但每次验证」，no-store 是「根本别存」。

协商缓存

响应头 请求头 依据
ETag If-None-Match 内容的哈希 / 版本标识，精确
Last-Modified If-Modified-Since 文件最后修改时间，精度只到秒

命中时返回：

**ETag 优于 Last-Modified**：

  • Last-Modified 精度是秒，一秒内改多次无法识别
  • 文件被「碰」了一下但内容没变，Last-Modified 会误判为已修改

两者都返回时，浏览器**优先用 ETag**。

常见资源的缓存策略

资源 策略
带哈希的静态资源（app.a1b2c3.js） max-age=31536000, immutable
HTML 入口文件 no-cache（必须每次验证）
用户私有数据接口 private, no-store
公共不变数据接口 public, max-age=60

⚠️ 关键点：HTML 不能长缓存，静态资源可以长缓存。
因为 HTML 里引用的是带哈希的新文件名，只要 HTML 是新的，资源自然就换新了。这个组合叫内容哈希 + 长缓存。

缓存失效的排查顺序

请求「没生效」时按这个顺序查：

  1. 响应头 Cache-Control 是什么
  2. 是 200 from disk cache / 200 from memory cache 还是真的发了请求
  3. 304 还是 200
  4. CDN 层是否也有缓存（X-Cache、Age 响应头）
  5. 是否被 Service Worker 拦截（DevTools 里可以绕过）

⚠️ DevTools 勾了 “Disable cache” 时看到的不是真实用户行为，排查线上问题一定要用无痕窗口。

三、几个高频细节

Age 与 CDN

表示这个响应在 CDN 缓存里已经放了 1200 秒。Age 加 max-age 能算出还剩多久过期。

Vary

告诉缓存：这些请求头不同时，要当成不同的资源分别缓存。 少写会导致 A 用户看到 B 用户的内容。

⚠️ 涉及内容协商（语言、编码、设备）时**一定要写 Vary**，否则 CDN 会把一份内容发给所有人。

强制刷新行为

操作 强缓存 协商缓存
普通导航 生效 生效
F5 跳过 生效
Ctrl+F5 跳过 跳过

四、状态码与缓存的配合

常见坑清单

  • 用 200 + 自定义 code 字段表达业务错误
  • 401 和 403 混用，前端无法区分「要登录」和「没权限」
  • 临时跳转用了 301，被浏览器永久缓存，改不回来
  • 把 no-cache 当成「不缓存」
  • HTML 设了长缓存，发版后用户拿不到新版本
  • 静态资源没带内容哈希，却设了长缓存
  • 内容协商的接口没写 Vary，CDN 串内容
  • 只在 DevTools 里测缓存（勾了 Disable cache 时行为不同）
  • DELETE 成功返回 200 + 空 body（应该用 204）
  • 限流返回 403 而不是 429，客户端不知道要退避重试

开场：三兄弟一次分清

问题 一句话 表现
穿透 查不存在的数据，请求全打到数据库 数据库压力持续偏高
击穿 一个热点 key 过期瞬间，请求全打到数据库 某个 key 一过期就抖一下
雪崩 大量 key 同时过期，或 Redis 整体挂了 数据库瞬间被打垮

记忆法：穿透是「查不到」，击穿是「一个热点没了」，雪崩是「一片全没了」。

一、缓存穿透

原因：查询一个数据库里也没有的数据，缓存不命中 → 每次都查库 → 缓存永远不生效。

典型场景：恶意用不存在的 id 刷接口。

方案一：缓存空值

优点 缺点
实现简单 大量不同 key 会占用内存
立即生效 数据后来真的存在了，要等过期才恢复

方案二：布隆过滤器

在缓存之前挡一层：

特性 说明
空间 极省（百万级约 1MB 量级）
假阳性 有（可能误判「存在」）
假阴性 没有（说不存在就一定不存在）

⚠️ 布隆过滤器只能加不能删（标准实现）。删除元素需要 Counting Bloom Filter。
如果数据会删除，要考虑重建策略。

⚠️ Redis 8 已内置布隆过滤器（BF.ADD / BF.EXISTS），不必自己实现。

二、缓存击穿

原因：某个热点 key 过期的瞬间，大量并发请求同时穿透到数据库。

和穿透的区别：数据是存在的，只是刚好在这一刻缓存没了。

对确认的热点 key，不设 TTL，靠主动更新维护。简单粗暴但有效。

三、缓存雪崩

原因：大量 key 在同一时刻过期，或 Redis 实例整体不可用。

方案一：过期时间加随机

这是最有效也最简单的一招。 避免「同一批数据同时写入、同时过期」。

方案二：多级缓存

Redis 挂了，本地缓存还能挡一层。

方案三：熔断与降级

⚠️ Redis 挂了不能无脑全部查库，那等于把 Redis 的负载直接转给数据库。
必须有限流或降级。

方案四：集群高可用

主从 + 哨兵，或 Redis Cluster。但要清楚故障转移期间会有短暂不可用。

四、内存满了怎么办

淘汰策略

策略 行为
noeviction 不淘汰，写入报错（默认）
allkeys-lru 所有 key 里淘汰最久未使用的
allkeys-lfu 所有 key 里淘汰使用频率最低的
allkeys-random 随机淘汰
volatile-lru 只从设了过期时间的 key 里淘汰
volatile-lfu 同上，按频率
volatile-ttl 淘汰即将过期的
volatile-random 随机（限有 TTL 的）

⚠️ volatile-* 系列的风险：如果没有任何 key 设了 TTL，这些策略**等同于 noeviction**，
内存满了直接写入失败。

LRU 还是 LFU

LRU LFU
依据 最近是否被访问 访问频率
适合 访问模式随时间变化 有明显热点（少数 key 撑起大部分流量）
缺点 一次全表扫描会污染缓存 新 key 需要时间累积频率

缓存场景通常 LFU 更好，因为热点是稳定的。Redis 4.0+ 支持 LFU。

淘汰不是删除

⚠️ 被淘汰的 key 是「消失」，不是「过期」。所以如果业务依赖 key 存在（比如分布式锁），
淘汰会让锁凭空失效。锁这类关键 key 应该放在独立实例，或调大内存避免淘汰。

五、持久化

RDB：快照

优点 缺点
文件紧凑、体积小 可能丢最后一次快照之后的数据
恢复快 fork 时可能卡顿（数据量大时）

⚠️ RDB 的 save 配置是在主线程 fork 子进程。数据量大（几十 GB）时，
fork 本身会阻塞主线程几百毫秒甚至更久。

AOF：追加日志

appendfsync 行为 丢数据风险
always 每条命令都刷盘 几乎不丢，性能差
everysec 每秒刷一次（默认推荐） 最多丢 1 秒
no 交给操作系统 可能丢较多

⚠️ AOF 文件会越来越大，因为记录了所有写命令。需要重写（rewrite）压缩：

⚠️ Redis 7 起 AOF 变成多文件结构（appendonlydir/），
包含 base 文件和 incr 文件。老教程里的单文件路径已经过时。

怎么选

场景 配置
纯缓存，丢了能重建 RDB 就够，甚至可以不持久化
有业务数据，不能丢太多 RDB + AOF 混合
绝对不能丢 appendfsync always（性能代价大）

实践建议：appendonly yes + appendfsync everysec，
Redis 7+ 默认用混合持久化（RDB 快照 + AOF 增量），恢复快且丢得少。

恢复顺序

Redis 启动时：先加载 AOF（如果开启），没有才加载 RDB。因为 AOF 通常更完整。

六、上线前的检查清单

常见坑清单

  • 把穿透、击穿、雪崩混为一谈，用错方案
  • 缓存空值没设过期时间，内存被垃圾 key 占满
  • 布隆过滤器用在会删除的数据上（它删不掉）
  • 互斥锁的重试没有上限，变成无限递归
  • 缓存 key 的过期时间完全一致，形成雪崩
  • Redis 挂了直接全量查库，把数据库打垮
  • 用了 volatile-lru 但 key 都没设 TTL，内存满了写入直接失败
  • 以为「淘汰」等于「过期」，依赖 key 存在做业务判断
  • 只配 RDB，接受不了丢几分钟数据
  • 开了 AOF 但没配 rewrite，磁盘被 AOF 撑满
  • 用 Redis 7 之前的 AOF 单文件路径去运维新版本
  • 大 key 没提前排查，故障时才用 --bigkeys 发现
  • 生产环境长时间开着 MONITOR

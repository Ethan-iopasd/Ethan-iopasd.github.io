开场：先搞清「改错了」改的是哪一层

判断标准：这个提交推给别人了吗？ 推了就只能 revert。

一、撤销工作区与暂存区

⚠️ git restore 丢弃的改动不在 Git 里，找不回来。 只对被 Git 跟踪过的文件有效，
新建的未跟踪文件不受影响（要用 git clean）。

未跟踪文件

⚠️ **永远先跑 git clean -n**。-x 会删掉 .gitignore 里的文件，
包括 .env、本地数据库文件、构建缓存。

暂存改动：stash

典型场景：正在写功能，突然要切分支修紧急 bug。

二、撤销本地提交

git reset 三种模式

模式 HEAD 暂存区 工作区
--soft 回退 保留 保留
--mixed（默认） 回退 重置 保留
--hard 回退 重置 丢弃

怎么选：

想干什么 用哪个
提交信息写错了，想重新提交 --soft
提交多了文件，想重新挑 --mixed
这个提交完全不要了 --hard

⚠️ --hard 会丢数据。 执行前先 git stash 或确认没有未提交的改动。

只改提交信息

往最后一个提交里补文件

⚠️ --amend 会改变提交 SHA。 已经推送过的提交不要 amend，除非确定要强推。

三、找回丢失的东西：reflog

这是 Git 最救命的命令。 reflog 记录了 HEAD 的每一次移动，包括 reset、rebase、checkout。

⚠️ reflog 默认保留 90 天（未引用的对象 30 天）。发现出事了越早处理越好，
而且别再执行任何写操作，避免对象被 GC。

⚠️ reflog 是本地的，不包含远程仓库的操作，也不会被推送。

四、撤销已推送的提交

git revert：安全的方式

revert 不改写历史，而是新增一个抵消的提交。 别人 pull 下来不会有任何问题。

reset revert
历史 被改写 保留，新增反向提交
已推送的提交 ❌ 需要强推 ✅ 安全
适合 本地未推送 共享分支

共享分支上撤销提交，只能用 revert。

撤销一个合并提交

-m 1 表示「保留第一父提交（通常是主干）」。不写 -m 会报错，因为合并提交有两个父提交，Git 不知道你想保留哪边。

⚠️ revert 掉合并提交后，想再次合并同一分支会被 Git 认为「已合并」而跳过。
需要再次合并时，得先 git revert 掉那个 revert 提交。

五、cherry-pick：挑单个提交

典型场景：在 develop 上修了个 bug，想同步到 release 分支，但不想带上其他改动。

⚠️ cherry-pick 会产生新的 SHA。同一个改动在两个分支上是两个不同提交，
以后合并时可能重复冲突。

六、bisect：二分查找引入 bug 的提交

100 个提交只要约 7 次测试就能定位。 手写排查要试几十次。

七、事故处理清单

事故 处理
改错了文件，还没 add git restore <file>
add 错了文件 git restore --staged <file>
提交信息写错 git commit --amend（未推送时）
提交多了文件 git reset --soft HEAD~1 重新提交
提交完全不要了 git reset --hard HEAD~1（未推送时）
误删分支 git reflog + git branch <name> <sha>
reset 错了 git reflog + git reset --hard HEAD@{n}
rebase 乱了 git reflog 找回，或 git rebase --abort
推了不该推的提交 **git revert**，不要 reset + 强推
提交了密码 / 密钥 改密钥 + git filter-repo 重写历史 + 通知协作方
需要撤掉一个合并提交 git revert -m 1 <sha>

强推的两种方式

⚠️ 永远用 --force-with-lease 而不是 --force。
--force 会无条件覆盖远程，可能把同事刚推的提交冲掉。
--force-with-lease 会先检查远程是否还是你上次看到的状态。

提交了密钥怎么办

顺序很重要：

  1. 立刻作废那个密钥（改密码、吊销 token）—— 即使还没清理历史
  2. 用 git filter-repo 或 BFG 重写历史，彻底移除该文件
  3. 强推（--force-with-lease）并通知所有协作方重新 clone
  4. 检查是否已经被使用

⚠️ 只删文件再提交是不够的 —— 密钥仍然存在于历史提交里，git log -p 就能看到。
也不要以为删了仓库就安全了，fork、clone、CI 缓存里可能都有。

常见坑清单

  • 用 git restore . 丢掉了未提交的工作（无法恢复）
  • git clean -fdx 连 .env 一起删了（先跑 -n）
  • 在已推送的提交上 --amend 然后强推
  • 用 git reset --hard + git push -f 撤销共享分支的提交
  • 不知道 reflog，以为丢了的提交找不回来
  • 出事后还在继续操作，导致对象被 GC
  • git revert 合并提交时忘了 -m 1
  • revert 掉合并后再次合并同一分支，发现改动没进来
  • 用 --force 而不是 --force-with-lease，冲掉同事的提交
  • 提交了密钥只删文件，没作废密钥、没重写历史
  • cherry-pick 同一改动到多个分支，后续合并重复冲突
  • 手工翻提交找 bug（该用 bisect）

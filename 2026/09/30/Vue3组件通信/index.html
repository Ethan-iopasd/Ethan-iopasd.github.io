开场：组件通信只有三条路

把组件想象成一个函数：

  • props = 入参
  • emits = 回调
  • slots = 传入的一段模板（类似 render prop）

所有组件通信方案都是这三者的变体。搞清这个，遇到任何库的设计都能立刻看懂。

一、Props：父 → 子

带默认值：

⚠️ 引用类型的默认值必须用工厂函数

单向数据流是铁律：子组件永远不要直接改 props。

为什么必须这样？ props 的归属权在父组件。子组件擅自修改会让状态变更来源变得不可追踪 —— 这是 Vue 应用后期最难调试的问题之一。

二、Emits：子 → 父

命名约定：模板里用 kebab-case（@update-count），脚本里用 camelCase（updateCount）。

⚠️ $event 在两种事件里含义完全不同：

原生事件 自定义事件
事件名 固定的（click、mouseenter） 随便起
$event 事件对象（pageX、target…） emit 时传的数据，任意类型

@click="x = $event" 拿到的是事件对象，@send-toy="x = $event" 拿到的是子组件传的数据。

七、方案怎么选

场景 方案
父 → 子传数据 props
子 → 父通知 emits
父子双向同步 v-model / defineModel
父决定子怎么渲染 插槽（尤其作用域插槽）
隔代传递 provide / inject
跨组件共享状态 Pinia
父组件要调用子的方法 defineExpose + 模板 ref

八、常见坑清单

  • 在子组件里直接改 props（违反单向数据流）
  • 引用类型的 props 默认值没用工厂函数（导致所有实例共享同一份）
  • defineModel 设了 default 但父组件没传，导致父子不同步
  • 3.4 之前用 v-model 忘了在 emits 里声明 update:modelValue
  • 混淆原生事件和自定义事件的 $event
  • 具名插槽写了 #s1 但子组件 <slot name="s2">，名字对不上
  • 滥用 provide / inject 传业务状态，数据流向无法追踪
  • <script setup> 组件没写 defineExpose，父组件通过 ref 拿到空对象

开场：三个问题的判据

问题 判据
这个属性从哪来 沿 [[Prototype]]（__proto__）向上查找，直到 null
这个 this 是谁 看函数怎么被调用，不看在哪定义；箭头函数例外
这个变量为什么还在 闭包持有对外层作用域链的引用，阻止其回收

一、prototype 与 __proto__ 不是一回事

名称 挂在谁身上 含义
prototype 只有函数有 用 new F() 创建实例时，实例的 [[Prototype]] 指向它
__proto__（= Object.getPrototypeOf） 所有对象都有 该对象自己的原型链接

⚠️ Person.__proto__ 指向 Function.prototype，Person.prototype 指向 Object.prototype。函数的 __proto__ 和 prototype 指向完全不同的东西，这是最容易记混的一处。

属性查找顺序

操作 是否沿原型链查找 是否修改原型链
读 obj.x ✅ —
写 obj.x = 1 ❌（找不到就在自身新建） ❌
in 运算符 / for...in ✅ —
Object.keys(obj) ❌ 只看自有 —
hasOwnProperty ❌ —
delete obj.x ❌ ❌ 只删自有

⚠️ 原型上的引用类型属性是所有实例共享的。Person.prototype.tags = [] 之后，每个实例 push 都进同一个数组。实例属性必须在构造函数里赋值。

class 只是语法糖

区别只有三点：class 内部强制严格模式、方法不可枚举、不能当函数直接调用（必须 new）。

⚠️ Object.create(null) 造出的对象没有原型链，toString、hasOwnProperty 全都没有。它适合做纯字典，但当 map 用时记得 for...in 不再需要过滤原型，而 obj.hasOwnProperty 会直接抛错。

二、this 的四条规则与优先级

优先级从高到低：

优先级 绑定方式 判据 结果
1 new 绑定 new F() 新创建的对象
2 显式绑定 f.call(o) / f.apply(o) / f.bind(o) o
3 隐式绑定 o.f() o
4 默认绑定 f() 严格模式 undefined，非严格 globalThis

隐式绑定丢失

⚠️ this 由调用点决定。 只要函数是「取出来单独调用」的，隐式绑定就丢了 —— 这是回调里 this 为 undefined 的唯一原因。

箭头函数没有自己的 this

箭头函数另外三条限制：

特性 箭头函数
自己的 this ❌ 词法继承
自己的 arguments ❌ 继承外层
能 new ❌ 没有 [[Construct]]
能当 generator ❌
有 prototype 属性 ❌

call / apply / bind

方法 传参 返回
f.call(ctx, a, b) 逐个 函数返回值
f.apply(ctx, [a, b]) 数组 / 类数组 函数返回值
f.bind(ctx, a) 逐个，可偏应用 新函数（永久绑定）

⚠️ bind 的 this 不可再被 call / apply 覆盖，但用 new 调用绑定函数时，bind 的 this 会被忽略，仍以新对象为 this（new 优先级更高）。

三、闭包

闭包 = 函数 + 它定义时所在的作用域。函数被带出原作用域后，仍能访问那里的变量，且那些变量不会被回收。

循环里的经典陷阱

var 是函数作用域，三个回调捕获的是**同一个 i**，循环结束后 i === 3。

let 在每次迭代创建一个新的绑定，并把上一轮的值复制进去，所以每个回调捕获的是各自的 i。

三种修法对比：

修法 代码 说明
let for (let i = ...) 首选，语义最清晰
IIFE (function (i) { setTimeout(() => console.log(i)) })(i) ES5 时代方案
bind setTimeout(console.log.bind(null, i)) 偏应用传值

⚠️ for...of / for...in 用 let 或 const 声明循环变量时，每轮也是新绑定，没有这个陷阱。陷阱只属于 var。

内存泄漏：闭包持有了不该持有的东西

闭包本身不是泄漏，是它把大对象绑定到了一个长生命周期的引用上。

泄漏场景 根因 修法
事件监听未移除 回调闭包持有 DOM / 大数据 removeEventListener，或 AbortController 统一取消
setInterval 未清除 回调闭包常驻 clearInterval
全局缓存无上限 Map 只增不减 用 WeakMap / WeakRef / LRU
闭包捕获整个大对象只为用一个字段 粒度太粗 在闭包外先取出需要的值
已移除的 DOM 节点被变量引用 节点无法回收 引用置 null

⚠️ WeakMap 的键是弱引用，值不是。wm.set(node, bigObject) 里 bigObject 会随 node 被回收而一起回收；但如果 bigObject 还被别处强引用，它不会释放。

常见坑清单

  • 把 F.prototype 和 F.__proto__ 当成同一个东西
  • 在 prototype 上放数组 / 对象，所有实例共享同一份
  • 以为 obj.x = 1 会沿原型链找同名属性并修改，实际是新建自有属性
  • 用 for...in 遍历对象却不过滤原型上的可枚举属性
  • 用 Object.create(null) 造字典后调用 obj.hasOwnProperty(...)
  • 把方法取出来单独调用（const f = obj.m、setTimeout(obj.m, 0)），this 丢失
  • 在需要动态 this 的地方用了箭头函数（对象方法、addEventListener 回调）
  • 以为 bind 之后还能用 call 改 this
  • 用 var 写 for 循环 + 异步回调，拿到循环结束后的值
  • 闭包为了用一个字段，把整个大对象 / 大数组捕获进去
  • 注册了 addEventListener / setInterval 却从不取消
  • 用 Map 做无上限缓存，键对象被回收后条目仍在

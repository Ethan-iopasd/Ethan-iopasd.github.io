开场：这三个东西都是「你以为它会自己跑」

服务不会自己重启、日志不会自己轮转、cron 不会自己继承你的环境变量。都要显式配。

一、systemd 服务

最小可用单元文件

/etc/systemd/system/myapp.service

生效流程（顺序不能错）

⚠️ 改了 .service 文件不 daemon-reload，改动不会生效。 这是最高频的困惑。

Type 的选择

Type 含义 适合
simple 启动命令即为服务（默认） 前台运行的程序
forking 进程会 fork 到后台 老式守护进程
oneshot 执行一次就退出 初始化脚本
notify 程序主动 sd_notify 通知就绪 支持该协议的守护进程
exec 类似 simple，但等 exec 成功 更精确的就绪判断

⚠️ 前台运行是前提。ExecStart 里不要用 &、不要用 nohup、不要用 daemon 模式
—— systemd 需要自己掌控进程，程序自己 daemon 化会让 systemd 认为服务已退出。

Restart 策略

值 行为
no 不重启（默认）
on-failure 非 0 退出 / 被信号杀死才重启
always 总是重启
on-abnormal 超时或被信号杀死才重启

⚠️ **一定要配 StartLimitBurst**。否则配置写错导致启动即崩，systemd 会无限重启，
CPU 打满，日志刷爆。

资源与安全限制

指令 作用
NoNewPrivileges 禁止提权
PrivateTmp 独立的 /tmp，互不可见
ProtectSystem=strict 整个文件系统只读（除 ReadWritePaths）
ProtectHome 看不到 /home /root

二、日志

journald 与 rsyslog

现代发行版有两套并存：

systemd-journald rsyslog
格式 二进制 纯文本
查看 journalctl cat /var/log/syslog
结构化字段 ✅ 支持 ❌
默认持久化 可能只在内存（/run/log/journal） ✅

⚠️ 默认配置下 journald 重启就丢日志。 要持久化：

日志轮转：logrotate

/etc/logrotate.d/myapp

指令 作用
daily / weekly / size=100M 轮转触发条件
rotate 14 保留 14 份
compress 旧日志 gzip
delaycompress 延迟一轮再压缩（避免程序还在写）
missingok 文件不存在不报错
notifempty 空文件不轮转
create 轮转后新建文件的权限
postrotate 轮转后执行的命令

⚠️ create 的权限要和应用需要的权限匹配。权限写错会导致应用轮转后写不了日志。

应用日志的几条经验

做法 原因
输出到 stdout，交给 systemd 收集 不用自己管文件、轮转
结构化（JSON） 便于检索和聚合
带请求 id 串联一次请求的所有日志
日志级别可运行时调整 排查时不用重启
不要打敏感信息 密码、token、身份证号

三、定时任务

cron 的五个字段

⚠️ cron 最坑的地方：环境变量不一样

cron 不读你的 .bashrc / .profile。 它的 PATH 通常只有 /usr/bin:/bin。

排查思路：把命令包成一个脚本，脚本开头 set -x 并重定向输出：

⚠️ cron 的任务默认没有输出去处。不重定向的话，错误信息会进邮件系统（很多机器没配），
你就只能看到「任务没跑」而不知道原因。

% 在 crontab 里要转义

crontab -e 与 /etc/cron.d/

位置 用户 特点
crontab -e 当前用户 存在 /var/spool/cron/crontabs/
/etc/crontab 有用户字段 系统级
/etc/cron.d/* 有用户字段 按应用分文件，推荐
/etc/cron.{hourly,daily,weekly,monthly} root 放脚本即可

/etc/cron.d/myapp：

⚠️ /etc/cron.d/ 里的文件必须带用户字段，且**文件名不能含 .**（会被忽略）。

systemd timer 替代 cron

需要「开机后延迟」「错过补跑」「依赖其他服务」时，timer 更强：

cron systemd timer
环境变量 需要显式设置 继承 unit 配置
日志 需自己重定向 自动进 journald
错过补跑 ❌ ✅ Persistent=true
依赖管理 ❌ ✅
随机延迟 需自己实现 ✅

新项目建议用 timer。 cron 只在需要极简或兼容老环境时用。

常见坑清单

  • 改了 .service 文件忘了 systemctl daemon-reload
  • ExecStart 里用了 & / nohup / daemon 模式（systemd 管不住）
  • 配了 Restart=always 却没配 StartLimitBurst，崩了以后无限重启
  • journald 没开持久化，重启后日志全丢
  • 日志不轮转，把磁盘写满
  • logrotate 的 create 权限不对，轮转后应用写不了日志
  • cron 里用相对路径或没设 PATH
  • cron 任务不重定向输出，出错了也不知道原因
  • crontab 里的 % 没转义
  • /etc/cron.d/ 的文件名带 .，被静默忽略
  • 集群里多个节点同一时间跑定时任务，把下游打挂（该加随机延迟）
  • 用 rm 清日志而不是 logrotate，导致句柄未释放

开场：一句话结论

一个 LLM 的最终行为 = 预训练给的底座 + SFT 给的格式 + 偏好对齐给的倾向。 改底座要几千张卡，改 SFT 要几万条样本，改对齐偏好只需要几百组对比 —— 但没有任何一步能修掉底座里不存在的能力。

一、三段式训练管线

阶段 目标 数据规模 算力占比 典型方法
预训练（Pre-training） 学语言与世界知识 万亿 token ~95% 自回归下一 token 预测
监督微调（SFT） 学会按指令组织输出 万~百万条 ~1% 指令-回答对，只算回答的 loss
偏好对齐（RLHF / DPO） 学会「更好」的回答 千~十万组对比 ~4% PPO / DPO / KTO

⚠️ 顺序不能反。先对齐再微调会让模型「遗忘对齐」，这叫 对齐税（alignment tax）；先微调再预训练则会把微调学到的格式冲掉。实践中 SFT 与 RLHF 常交替多轮，但每一轮都必须在前一轮基础上做。

二、预训练：目标函数简单，工程极难

自回归语言模型的目标就一个：

即「给定前文，预测下一个 token」，全序列并行计算，每个位置都是一个训练样本。

要点 做法 说明
分词 BPE / SentencePiece 词表 32K~150K，直接影响中文效率
序列打包 多条短样本拼成定长序列 避免 padding 浪费
学习率 warmup + cosine decay 峰值通常 1e-4 ~ 3e-4
精度 BF16 / FP8 FP16 需要 loss scaling，BF16 不用
并行 数据 / 张量 / 流水 / 序列并行 大模型必须组合使用
显存 ZeRO / FSDP 分片优化器状态 7B 全量训练至少 8×80G

⚠️ ignore_index=-100 是 PyTorch CrossEntropyLoss 的默认值，padding 位置必须设成它才会被跳过。忘了设会把 padding 也算进 loss，模型学会「预测 padding」。

⚠️ 因果 mask 是下三角。SFT 时如果输入是 [prompt][answer]，prompt 部分也要 mask 掉 loss（设 -100），否则模型会去学「复述用户的问题」，浪费容量且容易导致复读。

三、SFT：把「续写」掰成「对话」

预训练模型只会续写，SFT 教它识别「该我说话了」：

决策点 常见选择 影响
只训 assistant 段 loss mask 掉 user 段 标准做法，省算力
全序列训练 不 mask 会让模型学「扮演用户」，可能更会推理
模板一致性 训练与推理用同一套特殊 token 不一致会导致格式崩坏
数据配比 通用 + 领域 + 安全 混合 决定能力分布

⚠️ SFT 学的是格式，不是知识。想靠 SFT 灌入新知识，效果远不如 RAG 或继续预训练。SFT 数据超过几万条后收益迅速递减，数据质量比数量重要一个量级。

⚠️ 灾难性遗忘是 SFT 的头号风险。只训领域数据几百步，通用能力就明显退化。缓解手段：混入 5%~20% 的通用数据、降低学习率（1e-5 ~ 2e-5）、只训部分层。

四、LoRA：微调的默认姿势

全量微调 7B 模型要 100GB+ 显存。LoRA 冻结原权重，只训练一对低秩矩阵：

参数 典型值 作用
r（秩） 8 / 16 / 64 越大容量越强，显存也越大
alpha 16 / 32 缩放系数，实际学习率 ≈ alpha/r
target_modules q_proj,k_proj,v_proj,o_proj 只挂注意力通常够用
dropout 0.05 小数据集防过拟合

⚠️ B 必须零初始化。这样初始时 B·A = 0，模型行为与原始完全一致，训练从一开始就是「在原模型基础上微调」，而不是「先破坏再学」。A 用随机小值即可。

⚠️ alpha/r 是等效学习率。把 r 从 8 调到 64 而不动 alpha，等效学习率降了 8 倍，训练会明显变慢 —— 调 r 时记得同步调 alpha。

方案 显存 效果 适用
全量微调 最高 最好 数据充足、有卡
LoRA 低（~1/4） 接近全量 默认选择
QLoRA 极低（4bit 量化底座） 略低于 LoRA 单卡 24G 微调 7B
Prefix / P-Tuning 极低 较弱 分类、抽取类任务

五、RLHF：用人类偏好当奖励

SFT 之后模型「会答」，但不知道「哪种答法更好」。RLHF 三步：

步骤 产物 数据
1. 训奖励模型（RM） 一个打分器 人类对同一问题的多个回答排序
2. PPO 优化 策略模型 RM 实时打分
3. 加 KL 约束 防跑偏 与 SFT 模型的 KL 散度惩罚

⚠️ KL 惩罚不能省。没有它，策略会找到 RM 的漏洞疯狂刷分（reward hacking），输出退化成「人类看着像好答案但实际空洞」的文本。β 典型值 0.01~0.1。

⚠️ PPO 需要四个模型同时驻留：策略、参考、奖励、价值。7B 模型下显存约 4 倍，工程复杂度高，这也是 DPO 流行的直接原因。

六、DPO：把 RL 变成分类问题

DPO 绕开奖励模型，直接用偏好对做监督：

维度 RLHF (PPO) DPO
需要奖励模型 是 否
训练稳定性 差，超参敏感 好，像普通 SFT
显存 4 个模型 2 个模型
在线采样 是（on-policy） 否（off-policy）
上限 更高 略低，但足够

⚠️ DPO 对偏好数据质量极度敏感。标注噪声会被直接学进去，且没有奖励模型这层「平滑」。实践中 DPO 之前通常先做一轮 SFT，否则 π_ref 太差会让 loss 无意义。

七、效果与成本对照

想解决的问题 首选方案 成本 风险
模型不知道内部文档 RAG 最低 检索质量
输出格式不对 SFT（几百条） 低 过拟合
领域术语不熟 继续预训练 / LoRA 中 遗忘
回答风格/倾向不对 DPO 中 偏好数据噪声
推理能力不足 换更大底座 最高 ——

⚠️ 能力问题不要用对齐解决。模型根本不会的题，SFT 一万条也学不会，只会学会「假装会」。先确认是知识缺失（用 RAG）、格式缺失（用 SFT）还是底座能力不足（换模型）。

常见坑清单

  • 用 SFT 灌知识，数据堆到十万条还是不会
  • prompt 段没 mask loss，模型学会复述问题
  • padding 没设 ignore_index=-100，loss 被稀释
  • 训练/推理的特殊 token 模板不一致，输出格式崩坏
  • LoRA 的 B 没零初始化，训练初期性能断崖
  • 只调 r 不调 alpha，等效学习率被悄悄改掉
  • LoRA 只挂 q_proj，容量不够却以为是数据问题
  • 灾难性遗忘：纯领域数据训几百步，通用能力退化
  • RLHF 不加 KL 惩罚，reward hacking
  • 以为 DPO 一定优于 RLHF（上限更低但更稳）
  • 用噪声大的偏好数据跑 DPO，把错误偏好学死
  • 想用对齐修掉底座根本没有的能力

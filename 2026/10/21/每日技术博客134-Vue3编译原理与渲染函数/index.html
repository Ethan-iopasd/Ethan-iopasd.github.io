十二 编译原理与模板到渲染函数 本篇

开场：一句话结论

Vue 3 的性能优势大半来自编译器：它在编译期就知道「哪个节点是动态的」，于是运行时只需要 diff 那一小块。 这也是为什么 h() 手写渲染函数反而可能更慢 —— 你丢掉了编译器的静态分析信息。

一、三个阶段

阶段 输入 输出 做什么
parse 模板字符串 AST 词法 + 语法分析，产出节点树
transform AST 增强后的 AST 遍历打补丁：静态提升、patchFlag、指令转换
generate AST 渲染函数代码字符串 拼接 createElementVNode 调用

⚠️ 编译发生在构建时，不是运行时。vue-loader / @vitejs/plugin-vue 在打包阶段就把它转成渲染函数。只有用运行时 + 模板字符串（CDN 全量版）时才在浏览器里编译。

⚠️ vue 包有多个构建产物。vue.runtime.esm-bundler.js 不含编译器（更小），vue.esm-bundler.js 含编译器。用 SFC 时走的是 runtime-only，模板已在构建期编译完。

二、静态提升（hoistStatic）

优化 条件 收益
静态节点提升 节点及其子节点完全静态 只创建一次，后续复用
静态属性提升 属性值静态（如 class="btn"） 属性对象只创建一次
字符串化 纯文本静态子树 直接产出 HTML 字符串，跳过 vnode

⚠️ 静态提升的 vnode 是共享的。这意味着你不能修改它的属性 —— 所以对静态节点做 DOM 操作要小心，Vue 认为它永远不变。

⚠️ -1 /* HOISTED */ 这个 patchFlag 表示「永不 diff」。运行时看到它就跳过整个子树，这是收益最大的一处优化。

三、patchFlag：精确到属性级

flag 含义 运行时行为
1 TEXT 文本是动态的 只比 el.textContent
2 CLASS class 动态 只比 class
4 STYLE style 动态 只比 style
8 PROPS 有动态属性（带 key 信息） 只比指定 key
16 FULL_PROPS 动态 key 未知 全量比属性
32 HYDRATE_EVENTS 有事件监听 SSR 水合专用
64 STABLE_FRAGMENT 子节点顺序稳定 跳过 fragment 的特殊处理
128 KEYED_FRAGMENT 带 key 的 fragment 走 keyed diff
512 NEED_PATCH 有 ref / 指令 需要额外处理

⚠️ 8 后面那个字符串数组就是「需要比对的属性名」。所以 <div :class="a" :id="b" :title="c"> 只比这三个属性，其余全部跳过 —— 这就是 Vue 3 diff 快的原因。

⚠️ v-bind="obj" 会退化成 16 /* FULL_PROPS */。因为编译器不知道 obj 里有哪些 key，只能全量比对。能写具体属性就别用对象展开。

四、Block Tree：把动态节点拍平

Vue 2 的问题：模板嵌套多深，diff 就要递归多深。Vue 3 的解法：用一个数组收集所有带 patchFlag 的动态节点。

概念 含义
Block 一个 openBlock() / closeBlock() 之间的节点集合
dynamicChildren Block 内所有动态节点的扁平数组
v-if / v-for 会创建新的 Block（因为结构可能变）

⚠️ v-if / v-for 会打断 Block 的拍平。因为它们让子结构不确定，编译器只能退回到「逐个 diff」。所以把 v-if 放在动态节点越内层越好，能保留更多外层优化。

⚠️ v-for 的 key 依然重要。Block Tree 优化的是「跳过静态节点」，但列表内部的复用仍然依赖 key。没有 key 会退化为就地复用，状态会错位。

五、编译器的可配置项

选项 作用 影响
hoistStatic 静态提升 关闭后包体积略小，运行稍慢
cacheHandlers 事件处理函数缓存 避免每次渲染创建新函数
prefixIdentifiers 变量加 _ctx. 前缀 runtime-only 必须开启
mode: 'module' 输出 ESM 默认
isCustomElement 自定义元素白名单 避免被当成组件解析

⚠️ cacheHandlers 默认开启，它把 @click="handler" 缓存成同一个函数。但如果你写 @click="() => doSomething(id)"（内联箭头函数），缓存会失效，每次渲染都创建新函数。

⚠️ 自定义元素不注册 isCustomElement 会报错。编译器会把它当成未注册组件去解析，控制台出现 “Failed to resolve component”。

六、手写渲染函数 vs 模板

维度 模板 h() / JSX
编译期优化 有（patchFlag、Block） 无（全量 diff）
可读性 高（贴近 HTML） 中（灵活但啰嗦）
动态性 受模板语法限制 完全自由
适用 95% 的场景 高度动态、需要程序化生成结构

⚠️ h() 里没有 patchFlag，运行时只能全量比对。能用模板就用模板，除非确实需要程序化生成结构。

⚠️ 渲染函数里访问响应式数据必须在 render 期间，否则依赖收集不到。在 setup 顶层提前读出来存成普通变量，后续更新不会触发重渲染。

七、调试编译产物

手段 用法
@vue/compiler-dom 在线编译 看生成的渲染函数
Vue DevTools 看组件树与更新原因
__VUE_PROD_DEVTOOLS__ 生产环境开启调试
源码 packages/compiler-core 研究 transform 的具体实现

⚠️ 生产构建里模板会被内联成渲染函数，DevTools 看不到原始模板。想看编译产物就单独跑 compile()。

常见坑清单

  • 以为模板是运行时解释执行的
  • 用 v-bind="obj" 导致退化为 FULL_PROPS 全量 diff
  • v-if 写在最外层，打断 Block 优化
  • v-for 不写 key，列表状态错位
  • 内联箭头函数事件，破坏 cacheHandlers 缓存
  • 修改被静态提升的 vnode 属性
  • 自定义元素没配 isCustomElement，报组件未注册
  • 在渲染函数里提前读取响应式数据，依赖收集不到
  • 用 runtime-only 构建却写模板字符串
  • 以为手写 h() 一定比模板快（丢了编译期优化）

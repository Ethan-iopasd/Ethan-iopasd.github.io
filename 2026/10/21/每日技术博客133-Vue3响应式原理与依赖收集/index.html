开场：一句话结论

响应式的全部机制就是两个 Map：target → key → dep，以及 dep → 一组 effect。 读取时把当前 effect 塞进对应 dep，写入时把 dep 里的 effect 全跑一遍。所谓「响应式系统」，就是这套订阅关系的维护代码。

一、Proxy 相比 defineProperty 解决了什么

维度 Vue 2 defineProperty Vue 3 Proxy
新增属性 检测不到，需 $set 天然支持
删除属性 检测不到，需 $delete 天然支持
数组下标 需重写数组方法 天然支持
索引越界 不支持 支持
初始化成本 递归遍历所有属性 惰性，访问到才代理
拦截范围 只能拦截 get/set get/set/has/delete/ownKeys 等

⚠️ Proxy 是惰性的。只有被访问到的嵌套对象才会被代理，这大幅降低了初始化成本。Vue 2 在 data 初始化时要递归遍历所有属性，大对象上启动明显更慢。

⚠️ Reflect 不能省。Reflect.get(target, key, receiver) 里的 receiver 保证了 getter/setter 里 this 指向代理对象，否则继承场景下会读到原始对象、绕过代理。

二、三个全局容器

结构 键 值 作用
targetMap 原始对象 Map<key, Set<effect>> 最外层索引
depsMap 属性名 Set<effect> 该属性被谁依赖
dep —— effect 集合 触发时全部重跑

⚠️ **用 WeakMap 而不是 Map**。这样对象被回收时，其依赖记录能被 GC 自动清理，否则会造成内存泄漏（响应式对象永远不释放）。

⚠️ activeEffect.deps 的反向记录是为了清理。每次重新执行 effect 前要先清空旧依赖，否则条件分支切换后（if (flag) use(a) else use(b)）会残留无效依赖，导致 b 变化时也触发更新。

三、effect 与调度器

机制 作用
effectStack 支持嵌套 effect，恢复外层 activeEffect
cleanup 每次执行前清空旧依赖，避免残留
e !== activeEffect 防止 effect 内部修改自己的依赖导致无限递归
scheduler 把「立即执行」换成「放进队列」，组件更新就靠它
new Set(dep) 拷贝一份再遍历，避免执行中修改集合导致死循环

⚠️ trigger 里必须拷贝 dep。如果在遍历 Set 的过程中 effect 又触发 track 往同一个 Set 里加元素，会无限循环。Vue 3 源码里用 new Set(dep) 或按索引遍历规避。

⚠️ scheduler 是组件更新与 watch 的分水岭。组件渲染 effect 的 scheduler 会把任务推进微任务队列（合并同一轮多次修改），watch 的 scheduler 则决定是同步还是异步回调。

四、ref 与 reactive 的真实区别

对比 ref reactive
支持类型 任意（含基本类型） 仅对象/数组/Map/Set
访问方式 .value 直接访问
模板中 自动解包 直接访问
解构 保持响应（因为是一个对象） 丢失响应
替换整个对象 x.value = {} 生效 Object.assign 或重新赋值变量
实现 get/set value 拦截 Proxy

⚠️ reactive 解构会丢响应。const { count } = reactive({ count: 0 }) 拿到的是普通数字，后续更新不会反映。需要解构时用 toRefs，或者直接用 ref。

⚠️ reactive 对象整体重新赋值会断链。let state = reactive({...}); state = reactive({...}) 之后，模板里绑定的是旧代理。要么用 Object.assign(state, newObj)，要么改用 ref。

五、shallowRef / markRaw / toRaw

API 作用 场景
shallowRef 只有 .value 替换才触发，内部不深层代理 大数组、第三方实例
shallowReactive 只有顶层属性响应 扁平配置对象
markRaw 永久标记为不可代理 类实例、图表实例、路由对象
toRaw 拿到原始对象 传给不兼容 Proxy 的库
readonly 只读代理，写入警告 对外暴露的配置

⚠️ shallowRef 里 push 不触发更新，这是最常见的困惑。要么整体替换数组，要么用 triggerRef(list) 手动触发。

⚠️ 把第三方实例放进 reactive 是定时炸弹。ECharts、地图、Monaco 这类库内部有大量 DOM 引用和私有字段，被 Proxy 包裹后行为异常。一律 markRaw。

六、计算属性与侦听器的底层

API 本质 缓存机制
computed 带缓存的 effect（ComputedRefImpl） _dirty 标记，依赖变化才重算
watch 手动指定源的 effect + scheduler 无缓存，源变化即回调
watchEffect 自动收集依赖的 effect 无缓存，立即执行一次

⚠️ computed 的缓存是「脏标记」而非「值比较」。依赖变了就标脏，下次读取才重算 —— 所以多次读取只算一次，但依赖变化本身不立即计算。

⚠️ computed 里不要写副作用。它可能被缓存、可能不被求值、可能被多次重算。副作用放 watch 或 watchEffect。

⚠️ watch 的 deep: true 有性能代价。它会递归遍历整个对象来建立依赖，大对象上开销明显。能监听具体路径就不要 deep。

常见坑清单

  • reactive 解构后丢失响应
  • reactive 对象整体重新赋值，模板绑定断链
  • shallowRef 内部 push 不触发更新
  • 把 ECharts / Monaco 等实例放进 reactive
  • computed 里写副作用（发请求、改状态）
  • watch 无脑 deep: true，大对象上性能崩
  • 在 trigger 遍历 dep 时不拷贝，导致死循环
  • 以为 Proxy 是深度监听的（实际是惰性按需）
  • 用 Map 而非 WeakMap 存依赖，造成内存泄漏
  • effect 执行前不清理旧依赖，条件分支残留
  • 忘了 Reflect 的 receiver，继承场景绕过代理

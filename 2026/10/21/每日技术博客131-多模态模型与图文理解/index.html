开场：一句话结论

图像进入模型的方式是「切成 patch、编码成向量、当成 token」。 所以分辨率越高、切得越细，token 越多、成本越高；而「看不清小字」不是模型笨，是那些像素压根没被编码成独立的 token。

一、视觉编码器：把图变成向量

组件 作用 典型实现
图像分块（patchify） 把图切成 14×14 或 16×16 的小块 固定切分，不重叠
视觉编码器 每块编码成一个向量 ViT / SigLIP / CLIP
投影层（projector） 把视觉向量映射到语言模型维度 MLP 或 Q-Former
融合 视觉 token 与文本 token 拼成一条序列 早期融合 / 交叉注意力
模型 视觉编码器 特点
CLIP ViT + 文本塔对比学习 图文对齐强，细粒度弱
SigLIP Sigmoid 损失替代 softmax 训练更稳，小 batch 也能学
原生多模态 无独立编码器，统一 token 视频、音频可统一处理

⚠️ 投影层决定了「视觉信息能保留多少」。简单的线性投影便宜但信息损失大，Q-Former 用一组可学习 query 压缩视觉 token（能大幅降低 token 数），但也丢细节。需要细粒度识别（读小字、看表格）时，压缩率越低越好。

⚠️ patch 大小是硬性权衡。14×14 的 patch 在 1024×1024 图上产生约 5300 个 token；patch 翻倍到 28×28，token 数降到 1/4，但小目标就识别不了了。

二、token 成本：分辨率直接换算成钱

分辨率 patch=14 patch=16 约合文本 token（按 4 字符/token 粗比）
512×512 1369 1024 ~5K 字符
1024×1024 5476 4096 ~20K 字符
2048×2048 21904 16384 ~80K 字符
优化手段 做法 代价
降分辨率 长边缩到 1024 小字丢失
动态分辨率 按内容裁剪 / 切块 实现复杂
token 压缩 Q-Former / 池化 细节损失
只送关键区域 先检测再裁剪 需要额外模型
图片转文字 先 OCR 再送文本 丢失版面信息

⚠️ 一张 4K 截图可能比一篇长文还贵。批量处理图片任务前，先算清楚 token 账单。很多团队以为图片便宜，实际按 1024×1024 = 4000+ token 计，一次 100 张就是 40 万 token。

⚠️ 降分辨率是最容易踩的坑。把截图缩到 512 宽，里面的 8 号字直接糊成一团。读文档、读表格的场景必须保持原始分辨率或做切块。

三、图文任务的实际能力边界

任务 表现 注意
整体场景描述 好 容易漏细节
物体计数 差（>5 个就不准） 别依赖
小字 OCR 中等，取决于分辨率 重要场景配专用 OCR
表格结构还原 中等 复杂合并单元格易错
图表读数 差 数值常有偏差
空间关系（左/右） 中等偏差 方位词易混
手写识别 差 别用于正式场景
多图对比 中等 图越多越容易串

⚠️ 计数和读数是最不可靠的两类任务。模型是在「描述」，不是在「测量」。需要精确数值时，用 OCR + 规则解析，或者让它输出结构化字段后再校验。

⚠️ 模型可能「看到」训练集里的相似图片。给一张常见图表，它可能凭记忆报出错误的具体数值，且语气非常自信。涉及数字的场景一律要求给出依据位置，或者干脆不信任。

四、多图与视频

输入形态 处理方式 token 量
单图 直接编码 1×
多图 各自编码后拼接 线性叠加
视频 按帧采样 帧数 × 单帧 token
长视频 关键帧 + 音频转写 取决于采样策略

⚠️ 多图必须显式编号，否则模型分不清「第一张」「第二张」，对比类任务会答非所问。用 [图 1] 这类标记比「第一张图片」自然语言描述更可靠。

⚠️ 视频按固定帧率采样会漏掉关键瞬间。常见做法是场景切换检测 + 均匀采样混合，音频轨单独转写成文本一起送。纯视觉采样对「说了什么」几乎无效。

五、工程落地要点

关注点 做法
图片预处理 统一转 JPEG/PNG，控制长边，剥离 EXIF
缓存 相同图片哈希 → 复用编码结果
并发 图片下载与编码都是 IO/GPU 密集，分开池化
失败降级 图片解析失败时回退到纯文本
隐私 图片可能含人脸、证件，需脱敏与合规审查
可观测 记录分辨率、token 数、耗时

⚠️ **base64 内联会让请求体膨胀 33%**。大图优先用 URL 引用，只有内网或需要签名时才内联。

⚠️ EXIF 里可能带 GPS 和拍摄设备信息。对外发送前务必剥离，这是真实的隐私泄露路径。

六、什么时候该用专用模型

场景 通用多模态 专用方案
文档版面还原 一般 版面分析模型 + OCR
发票/证件识别 一般 专用抽取模型
工业质检 差 专用视觉模型
图表数值提取 差 图表解析库
通用问答、描述 好 不必要

⚠️ 通用多模态模型是「通用」不是「全能」。结构化文档、质检、医学影像这类高精度场景，专用小模型往往更准、更便宜、更快。先问：这个任务需要理解语义，还是只需要精确提取？

常见坑清单

  • 截图降分辨率后小字全糊，却以为是模型能力问题
  • 不算图片 token 成本，批量处理账单爆炸
  • 依赖模型做物体计数（超过 5 个就不准）
  • 从图表里读数值并直接采信
  • 多图不编号，对比任务答非所问
  • 视频按固定帧率采样，漏掉关键帧
  • 期望多模态模型做高精度 OCR / 版面还原
  • 图片 base64 内联导致请求体膨胀
  • 不剥离 EXIF，泄露 GPS 信息
  • 不缓存相同图片，重复编码浪费算力
  • 图片解析失败没有纯文本降级路径
  • 以为通用多模态能替代专用视觉模型

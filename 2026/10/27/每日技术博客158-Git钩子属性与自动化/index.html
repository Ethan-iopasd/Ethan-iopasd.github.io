开场：一句话结论

客户端钩子不随 clone 分发，且能用 --no-verify 跳过 —— 它只是「善意提醒」。 真正的门禁必须在 CI 或服务端钩子上。把 eslint 只放 pre-commit，等于没有。

一、钩子的两半

类别 位置 是否分发 能否绕过
客户端 .git/hooks/ 不随 clone --no-verify
服务端 服务器 hooks/ 由服务端管理 不能
客户端钩子 触发时机 典型用途
pre-commit 提交前 lint、格式、密钥扫描
commit-msg 写好消息后 校验提交信息格式
pre-push 推送前 跑快速测试
post-checkout 切分支后 自动装依赖
post-merge 合并后 提示 lock 文件变化
prepare-commit-msg 生成默认消息后 自动加 ticket 号
服务端钩子 触发时机 典型用途
pre-receive 接收推送前 全局策略校验
update 每个分支更新前 分支保护
post-receive 接收后 触发部署、通知

⚠️ .git/hooks/ 不纳入版本控制。团队成员 clone 下来是空的。要用 core.hooksPath 指向仓库内的目录。

⚠️ --no-verify 会跳过 pre-commit 和 commit-msg。紧急提交时很有用，但也意味着任何本地检查都不可信。

二、让钩子随仓库分发

方案 优点 缺点
core.hooksPath 原生、简单 需要每人配一次
husky（Node） 自动安装 依赖 npm install
pre-commit（Python） 生态丰富、跨语言 需要 Python
lefthook 快、并行 额外依赖

⚠️ core.hooksPath 是本地配置，不随 clone 传递。仍需在 README 或初始化脚本里说明，或靠 husky 这类工具在 npm install 时自动设置。

⚠️ 钩子脚本要处理「无匹配文件」的情况。grep 没匹配会返回非 0，set -e 下直接失败，导致空提交也被拦。

三、pre-commit 该做什么、不该做什么

该做 不该做
格式检查（prettier） 完整单元测试
lint 暂存文件 构建整个项目
密钥/凭证扫描 集成测试
提交信息格式校验 依赖安装
大文件检测 网络请求

⚠️ pre-commit 超过 3 秒，团队就会开始用 --no-verify。只做增量检查（暂存文件），把全量检查放 CI。

⚠️ 不要在网络请求里做钩子。断网时提交会卡住，体验极差。

四、.gitattributes：跨平台一致性

属性 作用
text / -text 是否做换行转换
eol=lf / eol=crlf 强制换行符
binary 等价 -text -diff
merge=ours 冲突时保留当前分支
diff=<driver> 自定义 diff 工具
filter=lfs 交给 LFS 处理
export-ignore git archive 时排除

⚠️ * text=auto eol=lf 是跨平台项目的基础。不加的话，Windows 提交会把换行改成 CRLF，导致整文件 diff。

⚠️ **merge=ours 要配 git config merge.ours.driver true**。只写属性不生效，很多人卡在这里。

五、.gitignore 的常见误区

写法 含义
*.log 任意层级的 .log
/build 只忽略根目录 build
build/ 任意层级名为 build 的目录
!a.log 取消忽略（父目录未被忽略才生效）
**/temp 任意深度的 temp

⚠️ 已被跟踪的文件加进 .gitignore 不会自动取消跟踪。必须先 git rm --cached <file>。

⚠️ ! 取反有前提。如果父目录被忽略，子文件的 ! 不会生效。要先 !parent/ 再 !parent/file。

六、提交信息规范与自动化

type 用途
feat 新功能
fix 修复
docs 文档
refactor 重构（不改行为）
perf 性能
test 测试
chore 构建/工具

⚠️ 提交信息规范要有实际消费者。如果没人用它生成 CHANGELOG 或判断版本号，规范就只是形式主义。

⚠️ subject 控制在 72 字符内。git log --oneline 和多数 UI 会截断。

七、服务端钩子与分支保护

保护手段 实现
禁止直推主干 服务端钩子 / 平台分支保护
必须通过 CI 平台必需状态检查
必须 review 平台审批规则
禁止强推 receive.denyNonFastForwards
禁止删除分支 receive.denyDeletes

⚠️ 服务端钩子只在自建 Git 服务可用。GitHub/GitLab 用平台的「分支保护」功能，效果等价。

⚠️ receive.denyNonFastForwards=true 会影响正常的 rebase 流程。开了之后所有强推都失败，要配合平台的白名单机制。

常见坑清单

  • 只在 .git/hooks/ 放脚本，团队成员 clone 后没有
  • 以为本地钩子能做强约束（--no-verify 可绕过）
  • pre-commit 跑全量测试，慢到没人用
  • 钩子里做网络请求，断网时提交卡住
  • 钩子脚本没处理「无匹配文件」，空提交也失败
  • 不配 .gitattributes，跨平台换行符满屏 diff
  • merge=ours 没配 merge.ours.driver，不生效
  • 文件已跟踪才加 .gitignore，忘了 git rm --cached
  • .gitignore 里 ! 取反因父目录被忽略而失效
  • 大文件直接提交，没走 LFS
  • 提交信息规范没人消费，纯形式主义
  • 服务端 denyNonFastForwards 挡住正常 rebase 流程

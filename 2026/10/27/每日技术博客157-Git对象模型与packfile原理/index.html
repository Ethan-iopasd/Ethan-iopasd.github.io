开场：一句话结论

Git 存储的是「每个版本的完整快照」，不是差异。 每个文件内容变成一个 blob，目录结构变成 tree，提交变成 commit —— 全部按 SHA-1（或 SHA-256）内容寻址。所以分支只是一个 41 字节的文本文件。

一、四种对象

对象 存什么 指向
blob 文件内容（不含文件名） 无
tree 目录列表（名字 + 模式 + 对象 ID） blob / tree
commit 快照 + 元信息 一个 tree + 父 commit
tag（附注） 标签对象 一个 commit

⚠️ blob 不含文件名。改名不会产生新 blob，只是 tree 里的名字变了。这就是 Git 能自动识别重命名的原因 —— 它比较的是内容。

⚠️ 相同内容只存一份。两个文件内容完全一样，只有一个 blob，tree 里两条记录指向同一个 SHA。复制大文件不占额外空间。

二、内容寻址：SHA 怎么算

特性 含义
确定性 相同内容永远得到相同 ID
不可逆 无法从 ID 反推内容
防篡改 内容变了 ID 必变
全局唯一 不同仓库同内容 ID 相同

⚠️ SHA-1 已被证明存在碰撞攻击。Git 加了碰撞检测（sha1dc），但新仓库建议用 --object-format=sha256。目前生态兼容性还有限，迁移要谨慎。

⚠️ 「同内容同 ID」意味着可以跨仓库去重。fork 时不会重复存储，这是 GitHub 存储效率高的原因之一。

三、引用与分支

引用类型 位置 说明
分支 refs/heads/* 可移动
远程分支 refs/remotes/* 本地缓存
标签 refs/tags/* 通常不动
HEAD .git/HEAD 指向当前分支或 commit
符号引用 ref: ... 指向另一个引用

⚠️ detached HEAD 就是 HEAD 直接指向 commit。此时提交不在任何分支上，切走就可能「丢失」（其实还能用 reflog 找回）。

⚠️ 分支没有「重量」。创建分支 = 写一个 41 字节文件，所以 Git 鼓励频繁建分支。

四、packfile：为什么 .git 不会爆炸

机制 作用
增量压缩（delta） 相似对象只存差异
zlib 压缩 每个对象再压一次
索引（.idx） 快速定位对象偏移
位图（.bitmap） 加速克隆与拉取

⚠️ delta 是「存储层的差异」，不是「模型层的差异」。Git 逻辑上存完整快照，物理上为了省空间才存 delta。概念上别混。

⚠️ git gc 会自动清理不可达对象。跑之前确认没有需要保留的悬空提交（reflog 默认保留 90 天）。

五、commit 到底改了什么

操作 对象层面发生了什么
commit 新建 commit + tree（未变文件复用旧 blob）
branch 新建一个 ref 文件
reset --soft 只移动 ref，index 与工作区不动
reset --mixed 移动 ref + 重置 index
reset --hard 移动 ref + 重置 index + 覆盖工作区
rebase 新建一系列 commit（新 SHA）
merge 新建一个双父 commit

⚠️ reset --hard 不删对象。旧 commit 仍可达（reflog），只要没 gc 就能找回。这就是「Git 几乎不会真的丢数据」的原因。

⚠️ rebase 会重写 SHA。所有被 rebase 的 commit 都变成新对象，已推送的分支 rebase 后必须 force push，且会打乱别人的历史。

六、reflog：最后的安全网

场景 恢复方式
reset --hard 丢提交 git reflog 找 SHA
误删分支 git reflog + git branch new <sha>
误 rebase git reflog 回到 rebase 前
误 commit 到错分支 cherry-pick 到正确分支

⚠️ reflog 是本地的，不随 clone 传递。换机器或删了 .git 就没了。

⚠️ reflog 默认保留 90 天（不可达对象 30 天）。超过期限且 gc 过的对象真的找不回。

七、日常能用上的底层命令

命令 用途
git cat-file -p <obj> 查看任意对象内容
git hash-object -w <file> 手动写入 blob
git ls-tree <tree> 列出 tree 内容
git rev-parse HEAD 解析引用为 SHA
git rev-list --count 统计提交数
git fsck --lost-found 找悬空对象
git verify-pack 检查 pack 完整性

⚠️ **大文件一旦进了历史，删掉文件也不会减小 .git**。必须改写历史（filter-repo）并 gc。

⚠️ git fsck 在大仓库上很慢。只在怀疑损坏时跑，别放进日常脚本。

常见坑清单

  • 以为 Git 存的是差异（实际存快照，物理上才用 delta）
  • 以为改名会产生新 blob（内容不变则复用）
  • 用 SHA-1 且不关注碰撞风险
  • 在 detached HEAD 上提交后切走，以为丢了
  • 已推送的分支 rebase 后 force push，打乱他人历史
  • 大文件提交进历史，删了也不减 .git
  • 依赖 reflog 做长期备份（本地、有期限）
  • git gc 前没确认悬空提交是否还要
  • 以为 reset --hard 会删对象
  • 在 clone 出来的仓库找 reflog 恢复（对方没有）

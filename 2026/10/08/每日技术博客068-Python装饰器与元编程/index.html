六 装饰器、元编程与描述符 本篇

开场：一句话结论

装饰器是「接收函数、返回函数」的高阶函数；property / classmethod / staticmethod 全是描述符；描述符决定属性查找顺序。理解这三句，Python 的元编程就没有黑魔法。

一、函数装饰器与 functools.wraps

属性 不 wraps 时 加了之后
__name__ wrapper fetch
__doc__ None "拉取数据。"
__qualname__ timer.<locals>.wrapper fetch
__module__ 装饰器所在模块 原函数模块
__wrapped__ 无 指向原函数

⚠️ 不加 wraps，help()、inspect.signature()、pytest 用例名、FastAPI 路由解析全部错乱。FastAPI 靠签名注入依赖，缺 wraps 会直接报「参数缺失」。

⚠️ wraps 只复制属性，不复制签名。要真让 inspect.signature 看到原签名，wrapper 必须用 *args, **kwargs 透传，或依赖 __wrapped__ 自动解包。

二、带参装饰器：三层嵌套

带参数的装饰器本质是「返回装饰器的函数」，所以必须三层。

⚠️ 写成 @retry 而忘了括号时，times 会是那个函数对象，range(times) 直接 TypeError。带参装饰器最经典的误用。

三、装饰器顺序与类装饰器

@A @B @C def f() 等价于 f = A(B(C(f)))：离函数最近的 C 先应用，A 最后应用。以 @tag("b") 套 @tag("i") 为例，结果是 <b><i>hi</i></b> —— b 后应用、却先执行。

⚠️ 应用顺序自下而上，运行时调用顺序自上而下：外层 wrapper 先跑，再进内层。

⚠️ @staticmethod / @classmethod / @property 必须放在最外层（最上面）。写在别的装饰器里面会拿到 <property object> 而不是值。

类装饰器接收类、返回类，在类定义完成后运行（@add_repr 之类），能加方法/属性但看不到方法内部。需要「在子类定义时介入」用 __init_subclass__，需要「改类的创建过程」用元类。

四、functools 常用装饰器

装饰器 版本 作用
lru_cache(maxsize=128) 3.2 LRU 缓存，参数必须 hashable
cache 3.9 等价 lru_cache(maxsize=None)，无淘汰
cached_property 3.8 首次访问算一次，结果写入实例 __dict__
singledispatch 3.4 按第一个参数类型分派，按 MRO 找最具体实现
singledispatchmethod 3.8 同上，用于方法
partial 2.5 冻结部分参数

@lru_cache(maxsize=1000) 装饰 fib(n) 后，用 fib.cache_info() 看命中率、fib.cache_clear() 清缓存。

⚠️ lru_cache 用参数做 key，参数必须 hashable。传 list / dict 直接 TypeError；传可变对象即使能 hash，也可能因内容变化命中错误缓存。

⚠️ lru_cache / cache 持有参数和返回值的强引用。缓存实例方法时会把 self 也缓存住，实例无法被 GC —— 隐蔽的内存泄漏。

⚠️ cached_property 只在实例有 __dict__ 时能写入，配 __slots__ 会失败；它是非数据描述符，实例 __dict__ 里的值会覆盖它。

五、描述符协议：属性查找的真相

描述符 = 实现了 __get__ / __set__ / __delete__ 中任意一个的类。

方法 签名 触发
__get__ (self, obj, objtype=None) 读取属性
__set__ (self, obj, value) 赋值属性
__delete__ (self, obj) del 属性
类型 定义 优先级
数据描述符 有 __set__ 或 __delete__ 高于实例 __dict__
非数据描述符 只有 __get__ 低于实例 __dict__

属性查找顺序（obj.attr）

  1. type(obj).__mro__ 中的同名属性是数据描述符 → 调其 __get__，结束
  2. 否则看 obj.__dict__['attr'] → 有则返回，结束
  3. 否则回到类属性：非数据描述符 → 调 __get__；普通类属性 → 直接返回
  4. 都没有 → 调 __getattr__（若定义）；再没有 → AttributeError

⚠️ __get__ 的 obj is None 分支必须处理：User.age（类访问）时 obj 是 None，忘了判断会 AttributeError。

⚠️ 数据描述符优先级最高，实例 __dict__ 里塞同名值也盖不住它。反过来非数据描述符会被实例 __dict__ 覆盖 —— 这就是 cached_property 能「首次计算、之后读缓存」的原理。

property / classmethod / staticmethod 都是描述符

内建 描述符类型 说明
property 数据描述符 有 __set__，能拦住赋值
classmethod 非数据描述符 __get__ 把 cls 绑进去
staticmethod 非数据描述符 __get__ 返回原函数，不绑定

⚠️ property 只有 getter 时，**赋值会抛 AttributeError: can't set attribute**。要可写必须补 @x.setter。

六、__slots__：省内存的代价

项 有 __dict__ 用 __slots__
每实例内存 大（一个 dict，约 100+ 字节起） 小（只存指针）
动态加属性 ✅ ❌
多继承 灵活 ⚠️ 多个带 __slots__ 的父类布局冲突会报错
cached_property ✅ ❌ 需要 __dict__
弱引用 ✅ 需手动加 __weakref__

⚠️ __slots__ 只对当前类生效。子类不定义 __slots__ 会重新获得 __dict__，省内存失效。

七、__getattr__ vs __getattribute__

方法 调用时机 风险
__getattr__ 正常查找失败后才调 低，推荐
__getattribute__ 每次属性访问都调 高，易无限递归

__getattr__ 的典型用途是代理：def __getattr__(self, name): return getattr(self._target, name)，让包装对象把未定义的属性转发给内部目标。

⚠️ __getattr__ 里访问 self.xxx 若 xxx 也不存在，会再次触发 __getattr__ → 无限递归。要访问自身状态用 object.__getattribute__(self, ...)。

⚠️ 写 __getattribute__ 必须在某条路径上 super().__getattribute__(name)，否则任何属性访问都爆栈。绝大多数场景用 __getattr__ 就够了。

八、元类与 __init_subclass__

需求 推荐工具
子类注册、校验子类定义 __init_subclass__
描述符要知道自己绑定的属性名 __set_name__
真的需要改类的创建过程 元类
只是加方法/属性 类装饰器

⚠️ 元类是最后手段。多个元类会 metaclass conflict，和 ABCMeta、EnumMeta 混用时组合困难。能用 __init_subclass__ 就别用元类。

⚠️ __init_subclass__ 是隐式类方法，第一个参数是子类 cls，不要加 @classmethod / @staticmethod。

九、dataclass 与 __post_init__

参数 效果
frozen=True 不可变，生成 __hash__
eq=True（默认） 生成 __eq__
slots=True（3.10+） 自动生成 __slots__
order=True 生成比较方法
kw_only=True（3.10+） 全部字段只能关键字传

⚠️ **可变默认值必须用 field(default_factory=...)**。直接写 items: list = [] 会 ValueError；在普通类里则是「所有实例共享同一个 list」的经典 bug。frozen=True 下 __post_init__ 也不能直接 self.x = ...，要用 object.__setattr__(self, "x", v)。

十、上下文管理器与 contextmanager

⚠️ @contextmanager 的生成器里 yield 必须被 try 包住才能捕获块内异常。try/finally 里不 raise 会把异常吞掉，调用方以为成功了。

⚠️ contextmanager 的产物不能被复用（with 两次会报 generator didn't stop）。要复用就写类实现 __enter__ / __exit__，或用 contextlib.ContextDecorator 让它同时能当装饰器。

十一、鸭子类型与 Protocol

方式 检查时机 是否需继承
鸭子类型（不注解） 运行时 否
Protocol（静态） 类型检查器 否（结构子类型）
Protocol + @runtime_checkable 运行时 isinstance 否
抽象基类 ABC 运行时 是

⚠️ @runtime_checkable 的 isinstance 只检查方法是否存在，不检查签名；Protocol 的静态检查要靠 mypy / pyright，且 Protocol 类不能被实例化。

常见坑清单

  • 装饰器不加 functools.wraps，__name__ / __doc__ / 签名全丢
  • 带参装饰器写成两层，range(times) 收到函数对象
  • @retry 忘写括号，参数变成被装饰函数
  • 搞混装饰器「自下而上应用」与「自上而下执行」
  • @staticmethod / @property 放在装饰器链的非最外层
  • 类装饰器想改方法内部实现（做不到）
  • lru_cache 缓存实例方法，self 被强引用导致实例泄漏
  • 给 lru_cache 传不可 hash 的参数
  • cached_property 配 __slots__ 使用
  • 以为实例 __dict__ 能覆盖数据描述符
  • 描述符 __get__ 不判断 obj is None
  • 给 property 赋值前没定义 setter
  • __slots__ 子类未定义 __slots__，省内存失效
  • __getattr__ 里访问不存在的属性导致无限递归
  • 重写 __getattribute__ 不调 super()
  • 为了子类注册硬写元类，和 ABCMeta 冲突
  • dataclass 可变默认值直接写 [] / {}
  • @contextmanager 生成器里 yield 没被 try 包住，异常被吞
  • 复用 @contextmanager 产生的上下文管理器
  • runtime_checkable 的 isinstance 当签名校验用

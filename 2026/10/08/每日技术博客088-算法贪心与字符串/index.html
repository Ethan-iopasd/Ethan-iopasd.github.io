开场：一句话结论

贪心不是「选当前最好的」，而是「能证明选当前最好的不会破坏最优解」——证不出来就不能用。字符串算法几乎全都在做同一件事：预处理一个数组，把匹配失败时的回退从「退一格」变成「退到已知的最长公共前后缀」。

一、贪心的正确性：局部最优凭什么等于全局最优

三种主流证明套路：

方法 思路 适用
交换论证 假设最优解与贪心解第一处不同，交换后不劣 排序类、区间调度
归纳法 前 i 步贪心仍在某个最优解中 结构规整的问题
反证法 假设贪心非最优，推出矛盾 最优子结构明显时

交换论证模板：

⚠️ 「看起来对」是贪心最大的陷阱。 面试里写完贪心先问自己一句：能不能构造一个反例？构造不出再谈证明。

⚠️ 排序键选错，整个贪心就崩。 区间调度按「开始时间」或「区间长度」排序都是错的，只有按「结束时间」才对。

二、贪心 vs DP：判别标准

维度 贪心 DP
决策 每步只做一个选择，不回退 每步枚举所有选择
前提 贪心选择性质 + 无后效性 最优子结构 + 重叠子问题
复杂度 通常 O(n log n) 通常 O(n²) 起
风险 证错就全错 状态设计错才错

硬币找零是最经典的分界点：

⚠️ 人民币/美元面值体系是 canonical 的，所以贪心能用；换个面值体系就失效。 通用解法只有 DP。

⚠️ 「无后效性」是贪心的隐性前提：当前决策不能影响未来可选集合的形状。一旦影响，就得回到 DP。

三、经典贪心题

题目 贪心键 复杂度 证明要点
区间调度（最多不重叠） 按结束时间升序 O(n log n) 交换：结束越早，留给后面的越多
跳跃游戏 II 维护当前能到的最远边界 O(n) 边界内任一点可达性相同
分发糖果 左→右、右→左各扫一遍 O(n) 两个方向约束独立，取 max
会议室安排 按开始时间排序 + 最小堆 O(n log n) 堆顶是最早空闲的会议室
哈夫曼编码 每次取最小两个合并 O(n log n) 最小权值必在最深叶
分饼干 双指针，小饼干先满足小胃口 O(n log n) 交换不劣
加油站 累计油量 < 0 就从下一点重开 O(n) 若总和 ≥ 0，起点必唯一

四、KMP：把回退从 O(m) 降到摊还 O(1)

**暴力匹配为什么是 O(nm)**：文本指针 i 每次失配都回退到 i-j+1，模式指针归零。最坏情况（aaaaab 匹配 aaaaaa...）每个位置都试满 m 次。

KMP 的核心：失配时文本指针 i 永不回退，只回退模式指针 j 到 lps[j-1]。

lps（longest proper prefix which is also suffix，也叫 next、fail）：

指标 值
预处理 O(m)
匹配 O(n)
总计 O(n + m)
空间 O(m)

⚠️ next 数组有两套定义：一套是 lps（长度，next[i] = 最长公共前后缀长度），另一套是「前缀函数 -1 偏移」的写法。两套混用必然越界或死循环，抄代码前先确认是哪种。

⚠️ 单次匹配用 KMP 不如用语言内置的 str.find（Boyer-Moore 类，常数更小）。KMP 的价值在于「不回溯」这个思想，以及能衍生出 AC 自动机。

五、Rabin-Karp 与 Z 函数

Rabin-Karp：把子串哈希成数字，滑动窗口 O(1) 更新。

指标 值
平均 O(n + m)
最坏 O(nm)（哈希全冲突，逐个字符验证）
优势 多模式、二维匹配、最长重复子串（配合二分）

Z 函数：z[i] = s 与 s[i:] 的最长公共前缀长度。整体 O(n)，用「Z-box」复用已有结果。把 pattern + '#' + text 拼起来跑 Z 函数，z[i] == len(pattern) 处就是一次匹配——等价于 KMP 但更好写。

⚠️ 单模哈希会被构造性数据卡掉。竞赛/对抗场景用双模（两个大质数）或随机 base。

⚠️ 哈希值相等 ≠ 字符串相等，验证必须逐字符回查，否则会输出假阳性。

六、Trie 与 AC 自动机

Trie（前缀树）：空间换时间，用公共前缀共享节点。

操作 复杂度
插入 / 查询单词 O(m)（m = 单词长度）
前缀查询 O(m)
空间 O(Σ m × 字母表)，最坏较大

典型用途：自动补全、敏感词过滤、单词搜索（棋盘 DFS + Trie）、异或最大值（01-Trie）。

⚠️ 普通 Trie 的 dict 实现常数大、内存高。节点数上百万时用「压缩 Trie（radix tree）」或「双数组 Trie（Double-Array Trie）」，后者把转移压进两个整型数组，查询快且省内存。

AC 自动机 = Trie + 失败指针（fail）。fail 指针就是「多模式版的 KMP next」：节点失配时跳到「最长后缀且是某模式前缀」的节点。

阶段 复杂度
建 Trie O(Σ m)
建 fail（BFS） O(Σ m × 字母表)（用 dict 则近似 O(Σ m)）
匹配 O(n + 命中数)

⚠️ AC 自动机的 fail 指针和 KMP 的 next 是同一套思想：都是「利用已匹配的最长后缀信息避免重扫」。理解 KMP 再学 AC，成本减半。

⚠️ 多模式匹配别用「N 次 KMP」——那是 O(n × k)。AC 自动机是 O(n + Σm + 命中)。

七、Manacher、字符串哈希与后缀结构

Manacher：最长回文子串 O(n)。关键是把 z/臂长信息在对称点间复用，并用分隔符统一奇偶长度。

字符串哈希：O(1) 判断任意子串相等，是所有「子串比较」类问题的加速器。

结构 用途 构建复杂度
字符串哈希（前缀） 子串相等、LCP 二分 O(n) 预处理 / O(1) 查询
后缀数组 SA 后缀排序、LCP、不同子串数 倍增 O(n log n)
后缀自动机 SAM 不同子串数、出现次数、最长公共子串 O(n)

⚠️ 后缀数组/自动机的实现细节很长，先记「它能干什么、什么复杂度」，需要时再套模板，别硬背。

编辑距离在 DP 那篇已讲过，此处只做衔接：它属于 DP 而非贪心，因为最优解依赖全局而非局部选择。

题型对照表

问题 首选算法 复杂度
单模式串匹配 KMP O(n+m)
多模式串匹配 AC 自动机 O(n+Σm+命中)
最长回文子串 Manacher O(n)
前缀/敏感词 Trie O(m) 每次
子串相等判断 字符串哈希 O(1)
最长公共前缀（多次） 哈希 + 二分 / SA O(log n) 每次
不同子串计数 后缀自动机 O(n)
回文判定 + 双指针 双指针 O(n)

常见坑清单

  • 贪心排序键选错（区间调度按开始时间/长度排）
  • 贪心只在 canonical 面值下成立，却当通用解法用
  • 没做交换论证就宣称贪心正确
  • next / lps 两套定义混用，导致越界或死循环
  • KMP 匹配时让文本指针 i 回退，退化回 O(nm)
  • 以为暴力匹配是 O(n+m)
  • 单模哈希被构造数据卡掉
  • 哈希相等不逐字符验证，输出假阳性
  • 多模式匹配用 N 次 KMP，复杂度写成 O(n)
  • AC 自动机忘建 fail 指针的 BFS 顺序（必须按层）
  • Trie 用 dict 实现还硬撑百万级节点
  • Manacher 忘了插分隔符，奇偶回文漏算
  • 回文子串用中心扩展就以为是最优（O(n²)）
  • 后缀数组复杂度记成 O(n)
  • 把编辑距离归到贪心（它是 DP）
  • 空间复杂度漏算 Trie 的字母表因子

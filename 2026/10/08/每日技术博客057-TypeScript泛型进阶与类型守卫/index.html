开场：一句话结论

TS 的类型只在编译期存在，运行时全是 JS。所有「类型对了运行时还是错」的问题，都源于断言绕过了收窄或运行时数据不满足类型声明 —— 类型守卫是唯一能把两者对齐的机制。

一、泛型约束三件套

语法 作用 示例
T extends U 约束 T 必须是 U 的子类型 K extends keyof T
keyof T 取 T 所有键的联合 keyof {a:1,b:2} → 'a' | 'b'
T[K] 索引访问类型，取属性类型 {a:string}['a'] → string
readonly T[] 只读数组约束 避免误改入参

⚠️ extends 在泛型约束里是「子类型」关系，在条件类型里是「可赋值性」判断 —— 同一个关键字两处语义不同，别混着推理。

⚠️ keyof any 是 string | number | symbol，所以 Record<keyof any, T> 和 Record<string, T> 不等价，后者不允许 symbol 键。

二、条件类型与 infer

分发（distributive）行为：当 T 是裸类型参数且传入联合类型时，条件类型会逐成员分发。

⚠️ 分发只对裸类型参数生效。写成 T extends any 会分发，写成 [T] extends [any] 就不分发。never 在分发时会变成空联合，结果仍是 never。

infer 用来在条件类型里声明待推断的类型变量：

场景 写法
函数返回值 (...a:any[]) => infer R
函数参数 (...a: infer P) => any
数组元素 (infer E)[]
Promise 解包 Promise<infer U>
构造函数实例 new (...a:any[]) => infer I

⚠️ infer 同一位置出现多次会推断成交叉类型（协变位置）或联合类型（逆变位置），行为不直观。要多个候选就分别起名再手动组合。

⚠️ 条件类型在未解析的泛型上会延迟求值，T extends U ? X : Y 在 T 是裸泛型时不会立刻算 —— 这也是 Awaited 这类工具类型能递归展开的原因。

三、映射类型与修饰符

修饰符 含义 语法
+readonly / -readonly 加 / 去只读 -readonly [K in keyof T]
+? / -? 加 / 去可选 [K in keyof T]-?
as 键重映射（TS 4.1+） 改键名 [K in keyof T as `get${K}`]
K & string 过滤非字符串键 [K in keyof T as K extends string ? K : never]

⚠️ 映射类型遇到联合类型会分发；遇到 keyof T 时 T 是 string | number | symbol 的联合，直接 Capitalize<K> 会报错 —— 必须 K & string 或 Extract<K, string> 先过滤。

⚠️ 同态映射（{ [K in keyof T]: ... }）会保留原类型的可选性与只读性；一旦加了 as 子句，就不再是同态映射，修饰符会被重置，需要手动补 ? / readonly。

类型 作用
Uppercase<S> / Lowercase<S> 全大写 / 全小写
Capitalize<S> / Uncapitalize<S> 首字母大写 / 小写
${T} 插值 拼接字面量
infer + 模板 拆分字面量

五、类型守卫

手段 适用 收窄效果
typeof x === 'string' 原始类型 收窄到 string
x instanceof Date 类实例 收窄到 Date
'a' in x 属性存在性 收窄到含 a 的分支
Array.isArray(x) 数组 收窄到 any[]
x !== null / !== undefined 空值 去掉对应分支
is 谓词 自定义 收窄到指定类型
asserts 断言函数 自定义 之后全局收窄

⚠️ is 谓词是你自己写、编译器直接信的 —— 实现写错编译器不会报错。断言函数同理。这两处是「类型对了运行时还是错」的头号来源，务必写成纯粹的、无副作用的判定。

⚠️ 断言函数要求调用目标必须有显式类型标注，且不能是箭头函数赋值给变量，否则报 Assertions require every name in the call target to be declared with an explicit type annotation。

in 的收窄在 TS 4.9 有重要改进：

⚠️ TS 4.9 起 in 的左侧必须可赋值给 string | number | symbol，右侧必须可赋值给 object。以前能过的 'x' in somePrimitive 现在直接报错。

六、可辨识联合与穷尽检查

要点 说明
判别字段必须是字面量类型 kind: string 无法收窄
联合成员必须互斥 否则收窄到交叉而非单一分支
never 赋值做穷尽检查 漏分支 → 编译报错
用 throw 兜底 保证运行时也有保护

⚠️ 判别字段写成 kind: string（而不是 'circle'）会让整个联合失去收窄能力，退化成普通对象联合，switch 里每个 case 都拿到全部字段。

⚠️ 用 _exhaustive: never 时若开了 noUnusedLocals，需给变量加下划线前缀或改写成 s satisfies never，否则会因「声明未使用」报错。

七、unknown / any / never

类型 可赋值给 可读属性 典型用途
any 任意 ✅（放弃检查） 迁移期、逃生舱
unknown 仅 any / unknown ❌（须先收窄） 外部输入、catch
never 任意 — 穷尽检查、永不返回

⚠️ any 会污染：any 参与的任何运算结果也是 any，收窄全部失效。要逐步收紧就用 unknown，它同样接受任何输入但不允许任何读取。

⚠️ catch (e) 的 e 在 strict + useUnknownInCatchVariables（TS 4.4 起随 strict 默认开启）下是 unknown，不是 any。历史代码里直接 e.message 会报错。

八、satisfies（TS 4.9+）

satisfies 校验表达式匹配某类型，但不改变表达式自身的类型。

写法 校验 保留精确类型
const x: T = ... ✅ ❌ 被拓宽为 T
const x = ... ❌ ✅
const x = ... satisfies T ✅ ✅

⚠️ satisfies 只做校验，不做转换。它不会补上缺失的必填属性，也不会把 string 变成字面量类型 —— 想同时获得字面量类型，要配合 as const。

九、协变、逆变与双变

位置 变型 方向
属性 / 返回值 协变 子 → 父 可赋
函数参数（strictFunctionTypes） 逆变 父 → 子 可赋
方法签名（foo(x: T) {}） 双变 两个方向都可赋
readonly 数组 协变 安全
可变数组 协变（不安全） TS 仍允许

⚠️ 方法语法是双变的：{ m(x: Dog): void } 能赋给 { m(x: Animal): void }。这是 TS 为兼容既有 JS 代码做的妥协，类型不安全。要严格就用属性语法 m: (x: Dog) => void。

⚠️ TS 对数组是协变的（Dog[] 可赋给 Animal[]），但运行时可写，因此 Animal[] = Dog[] 后 push 一个纯 Animal 会破坏类型。这是 TS 已知的健全性缺口，只能靠 readonly 修饰规避。

常见坑清单

  • 把泛型约束的 extends 和条件类型的 extends 当成同一件事
  • 条件类型意外分发（裸 T），联合类型被逐成员拆开
  • 想阻止分发却没把类型参数包成元组
  • infer 在同一位置重复出现，得到不直观的交叉 / 联合
  • 映射类型加了 as 子句后忘记它不是同态映射，修饰符丢失
  • 用 Capitalize<K> 时没有先 K & string，遇到 symbol 键报错
  • 模板字面量类型在超大联合上组合，类型检查爆掉
  • 自定义 is 谓词实现写错，编译器完全不报错
  • 断言函数用箭头函数赋值给变量，触发显式标注要求
  • 可辨识联合的判别字段写成 string，收窄彻底失效
  • 用 any 做过渡，污染整条类型链
  • catch (e) 直接访问 e.message，忽略 e 是 unknown
  • 以为 satisfies 会自动补全缺失属性
  • 用 as 断言绕过收窄，运行时数据并不满足该类型

开场：一句话结论

Go 的内存问题只有三类：分配太多（看逃逸分析和 -benchmem）、回收太频繁（调 GOGC）、根本没收（goroutine 泄漏 / 全局容器只增不减）。pprof 负责定位，GOMEMLIMIT 负责兜底。

一、goroutine 栈

项 值
初始栈大小 2KB（Go 1.4 起；此前 8KB）
增长方式 需要时翻倍，由编译器插入的栈检查触发
收缩时机 GC 时，使用量小于 1/4 则收缩
默认上限 64 位平台 1GB（debug.SetMaxStack 可调）

栈是连续内存，翻倍时分配新栈并复制旧内容，指向栈的指针会被调整 —— 所以「栈上变量的地址」在 goroutine 生命周期内会变。

⚠️ goroutine 栈不是「泄漏就无限涨」：上限 1GB，超了直接 fatal error: stack overflow，程序崩溃而非优雅降级。

二、逃逸分析

场景 结果
返回局部变量地址 逃逸到堆
传给 interface{} 参数 逃逸（装箱）
存入全局变量 / map / slice 逃逸
只在函数内使用的局部变量 留栈
闭包捕获但闭包不外传 可能留栈

⚠️ Go 的逃逸分析必须保守：只要无法证明安全就丢到堆上。看 -m 输出比猜有用，别为消灭逃逸写出反直觉代码。

三、三色标记 + 混合写屏障

颜色 含义
白 未访问，回收候选
灰 已发现，其引用未扫描完
黑 已发现且引用已扫描完

标记从根（栈、全局变量、寄存器）出发，灰集合为空时，剩下的白对象全部回收。

并发标记时程序还在改指针，可能把「黑对象指向的白对象」藏起来。Go 1.8 起用混合写屏障解决：

  • 写入时，被覆盖的旧值若为灰/白 → 置灰
  • 写入时，新值若为白 → 置灰

⚠️ 混合写屏障让 Go 1.8 起彻底移除了标记结束阶段的栈重扫描 STW，停顿从「几十毫秒」降到「亚毫秒」。别引用 Go 1.7 及之前的 GC 文章。

GC 阶段与 STW

阶段 是否 STW 干什么
Sweep Termination ✅ 短 确认上一轮清扫完成
Mark Setup ✅ 短 开启写屏障
Marking ❌ 并发 三色标记，占用 25% CPU
Mark Termination ✅ 短 关闭写屏障，重扫
Sweeping ❌ 并发 后台懒清扫

⚠️ GC 期间 Go 会偷 25% 的 CPU 做标记（GOMAXPROCS 的 1/4）。CPU 密集型服务在 GC 高峰掉 25% 吞吐是正常的。

⚠️ runtime.GC() 是阻塞式全量 GC，只用于测试/诊断，生产代码里调用会把 STW 拉满。

四、GOGC 与 GOMEMLIMIT

变量 引入版本 含义 默认
GOGC 远古 堆增长百分比触发 GC 100
GOMEMLIMIT Go 1.19 软内存上限（字节或 1GiB） math.MaxInt64

GOGC=100 的含义：上次 GC 后存活堆 10MB，涨到 20MB 时触发下一次。

⚠️ GOMEMLIMIT 是软限制，不阻止堆超过该值，不适合当 cgroup 硬配额。

⚠️ GOMEMLIMIT 设得太低且存活堆接近该值时，GC 会持续运行（death spiral），CPU 打满。设它之前先测出真实存活堆大小。

⚠️ GOGC=off 与 GOMEMLIMIT 同时关闭 → 一直涨到 OOM。两者至少要留一个生效。

五、内存复用：sync.Pool

特性 说明
用途 临时对象复用，降低 GC 压力
清空时机 每次 GC 可能清空（Go 1.13 起有 victim cache，跨一次 GC）
适用 高频、短生命周期、大小相近的对象

⚠️ sync.Pool 不保证 Get 拿到什么。每次 Get 后必须自己重置状态，不能假设是干净的。

⚠️ 归还大对象（如 1MB 切片）会让池常驻大内存 —— 池化必须限制对象大小，否则等于内存泄漏。

六、slice / map 的扩容与预分配

当前容量 slice 新容量
< 256 翻倍
≥ 256 约 old + (old+3*256)/4，趋近 1.25 倍（Go 1.18+）

⚠️ 扩容会重新分配底层数组并复制。append 返回的新切片必须接住：s = append(s, x)。

⚠️ s2 := s1[1:3] 产生的子切片共享底层数组：改 s2 会影响 s1，且 s2 存活时整个底层数组都无法回收。要独立就 copy。

⚠️ 已知元素数量时一定给 make 传容量。map 扩容要重新哈希全部元素。Go 1.24（2025-02）把 map 换成 Swiss Table，但「必须预分配」的结论不变。

七、unsafe 与零拷贝

操作 是否拷贝 安全性
string(b) / []byte(s) ✅ 拷贝 安全
unsafe.String / unsafe.Slice ❌ 调用方保证原 buffer 不再被改

⚠️ 零拷贝转换出的 string 共享底层数组。原 []byte 被复用（如来自 sync.Pool）时，string 内容会静默变化 —— 最难查的 bug 之一。

八、pprof 实操

Profile 定位什么 需要额外开启
profile CPU 热点 —
heap 内存分配 / 存活 —
goroutine 泄漏、卡死 —
block 阻塞时长 runtime.SetBlockProfileRate
mutex 锁竞争 runtime.SetMutexProfileFraction

⚠️ block / mutex 默认不采样，要显式设置采样率才有数据，且有性能开销，别长期开着。

⚠️ heap 默认看 inuse_space（存活）。要看「谁在疯狂分配又马上回收」，切 -sample_index=alloc_space：

常用交互命令：top10、list FuncName（逐行开销）、web（调用图，需 graphviz）、peek FuncName。

九、benchmark

⚠️ -benchmem 才输出 B/op / allocs/op。只跑 -bench=. 看不到分配，而分配次数往往是根因。

十、runtime.MemStats 关键字段

字段 含义
HeapAlloc 当前堆上存活字节数（最该盯的）
HeapInuse / HeapIdle / HeapReleased 在用 / 空闲未归还 / 已归还 OS
HeapSys 向 OS 申请的总堆内存
StackInuse goroutine 栈占用
NextGC 下次 GC 的堆目标
NumGC / PauseTotalNs GC 次数 / 累计 STW 时间
GCCPUFraction GC 占用的 CPU 比例
Mallocs / Frees 累计分配 / 释放对象数

⚠️ runtime.ReadMemStats 会短暂 STW，高频调用本身就是性能问题。Go 1.19+ 优先用 runtime/metrics（无 STW）。

⚠️ HeapSys - HeapReleased 才是「OS 视角的真实占用」。**HeapAlloc 小不代表进程 RSS 小**。

十一、常见内存泄漏

类型 表现 修法
goroutine 泄漏 goroutine 数持续涨 context 取消 / 加退出条件
time.Ticker 不 Stop 定时器 + goroutine 不释放 defer ticker.Stop()
循环里 time.After 每次新建 timer，等超时才回收 改 Ticker + select
全局 map 只增不减 HeapAlloc 单调上升 定期清理 / 带淘汰的缓存
子切片持有大数组 小切片拖住大底层数组 copy 出独立切片
channel 阻塞无人收 发送方 goroutine 永久阻塞 缓冲 / default / ctx

⚠️ time.After 在 for 循环里是经典泄漏：每个 After 都新建 timer，即使 select 走别的分支也要等超时才回收。高频循环用 time.NewTimer + Reset。

⚠️ 判断 goroutine 泄漏最直接：go tool pprof .../goroutine 看栈聚合，或对比 runtime.NumGoroutine() 在稳定负载前后的值。

常见坑清单

  • 用 Go 1.7 及之前的 GC 资料，以为 STW 还有几十毫秒
  • 相信「goroutine 栈固定 8KB」（1.4 起是 2KB 且可增长）
  • 不看 -gcflags=-m 就猜变量逃逸
  • 为消灭逃逸写出难维护的代码
  • 以为 GOMEMLIMIT 是硬上限，拿它当 cgroup 配额
  • GOMEMLIMIT 设得低于存活堆，GC death spiral
  • GOGC 和 GOMEMLIMIT 同时关闭，等 OOM
  • 生产代码里调 runtime.GC()
  • sync.Pool 取出后不重置状态
  • 池化大对象，池变成内存黑洞
  • append 返回值不接住
  • 已知长度的 slice / map 不预分配
  • 子切片共享底层数组导致内存拖挂或意外修改
  • unsafe 零拷贝转换后原 buffer 被复用
  • 只跑 -bench=. 不加 -benchmem
  • benchmark 里 -count=1 就下结论
  • block / mutex profile 不开采样率，拿不到数据
  • heap profile 只看 inuse，找不到高频分配
  • 高频调用 runtime.ReadMemStats
  • time.Ticker 忘记 Stop
  • 循环里用 time.After 造 timer 泄漏
  • 全局 map 只增不减当缓存

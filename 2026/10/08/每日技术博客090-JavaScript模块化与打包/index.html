每日技术博客 090 · JavaScript（四）：模块化与打包原理

每日技术博客 · 2026-10-08 · 第 090 篇

CommonJS 是运行时同步加载的值拷贝，ESM 是编译期静态分析的引用绑定。这一篇讲两者的硬差异、exports 字段解析、Tree-shaking 条件和打包器到底做了什么。

开场：一句话结论

CommonJS 导出的是值的快照，ESM 导出的是活的绑定——这是所有差异的根源。import 必须在顶层静态出现，打包器才能在编译期画依赖图、做 Tree-shaking；require 是运行时的函数调用，打包器只能整个打进去。

一、模块化演进史

阶段 形态 解决的问题 遗留问题
全局函数 window.foo = ... 无 命名冲突、污染全局
IIFE / 命名空间 (function(){...})() 私有作用域 依赖顺序靠人肉维护
CommonJS require / module.exports Node 服务端模块化 同步、无法静态分析
AMD define([...], fn) 浏览器异步加载 回调地狱、语法啰嗦
UMD 兼容 CJS/AMD/全局 一套代码多环境 体积大、依然非静态
ESM import / export 语言级静态模块 生态迁移期长

⚠️ UMD 是过渡产物，现代库若仍只发 UMD，你的 Tree-shaking 基本为零。优先选 "type":"module" 或带 exports 条件导出的包。

二、CommonJS vs ESM：硬差异对照

维度 CommonJS ESM
加载时机 运行时、同步 编译期解析，静态
解析前提 任何位置都能 require import 必须在顶层
导出语义 值拷贝 实时绑定（live binding）
循环依赖 拿到「半成品」对象，可能 undefined 提升后可能暂时处于 TDZ
this module.exports undefined（模块顶层）
顶层 await ❌ ✅
Tree-shaking ❌ 基本无效 ✅ 有效
动态加载 require(变量) 天然支持 只能用 import() 返回 Promise

值拷贝 vs 实时绑定——最常踩的坑：

⚠️ CJS 里 module.exports = {...} 之后再改内部变量，导出对象不会更新。 这是「为什么我改了配置模块没生效」的头号原因。

⚠️ ESM 的导入是只读绑定，import { n } from ...; n = 5 直接抛 TypeError（严格模式下赋值给常量）。

循环依赖的行为差异

CJS 里循环依赖返回已执行部分的 module.exports，拿到的字段可能是 undefined；ESM 因为先做「实例化」再「求值」，变量存在但可能处于未初始化状态（访问抛 ReferenceError）。

⚠️ 循环依赖能跑不代表对。它让执行顺序变成隐式契约，重构一下就崩。看到循环依赖先想怎么拆。

三、package.json 的入口字段

字段 作用 优先级
type "module" 或 "commonjs"，决定 .js 按哪种解析 基础开关
main CJS 入口（老字段） 低
module ESM 入口（打包器约定，Node 不认） 中
exports 官方条件导出，存在时覆盖 main/module 最高
imports 以 # 开头的内部子路径映射 —
browser 浏览器端替换（打包器约定） 中

⚠️ exports 一旦出现，未被列出的子路径全部禁止访问。 以前能 require('mylib/internal/util')，加了 exports 就报 ERR_PACKAGE_PATH_NOT_EXPORTED——这是最常见的破坏性升级。

⚠️ 条件顺序有讲究：**types 必须放最前**，default 放最后。Node 按对象键顺序匹配第一个命中的条件。

⚠️ 只写了 main 没写 exports 的包，在 Node 里没有子路径导出保护，任何人都能 import 内部文件。库作者请补 exports。

⚠️ 避免双包陷阱的官方建议：要么只发 ESM，要么让 CJS 入口用「包装 ESM」的方式（Node 22.12+ 的 require(esm) 让这条路径可行），要么把状态隔离到显式传入的实例。

四、Node 的 ESM 加载规则

场景 解析方式
.mjs 永远 ESM
.cjs 永远 CommonJS
.js 取决于最近的 package.json 的 type
"type": "module" 下的 .js ESM
无 type 或 "type":"commonjs" 下的 .js CommonJS
  • Node 20.19+ / 22.12+ 默认启用 require(esm)，可以在 CJS 里 require() 一个同步 ESM 模块（含顶层 await 的会报错）。
  • 更早版本需要 --experimental-require-module。

⚠️ require(esm) 只支持同步的 ESM 图。模块里若有顶层 await，require 会抛 ERR_REQUIRE_ASYNC_MODULE，只能改用 import()。

⚠️ ESM 里没有 __dirname / __filename / require。要用 import.meta.url + fileURLToPath 自己拼。

五、浏览器里的 ESM

浏览器原生 ESM 的三条硬约束：

  1. 必须 type="module"，且延迟执行（等价 defer）
  2. 必须带正确的 MIME（text/javascript），否则拒绝执行
  3. 跨源必须 CORS，file:// 协议下直接失败

⚠️ type="module" 的脚本是严格模式，且模块作用域内顶层 this 是 undefined。把老脚本直接改成 module 会踩一堆坑。

⚠️ 原生 ESM 下每个 import 都是一次网络请求，深层依赖树会产生瀑布式请求。生产环境仍然要打包或走 HTTP/2。

六、打包器在做什么

阶段 产物
依赖图 模块间的引用关系
转换 AST 改写（Babel/SWC/esbuild）
Scope hoisting 多个模块合并进同一作用域，减少闭包包装
Chunk 拆分 vendor / runtime / 路由级 chunk
代码生成 最终 JS + 映射

Tree-shaking 生效的三个条件

条件 说明
源码是 ESM CJS 的 module.exports 无法静态分析
无副作用 被删的代码不能有可观测的副作用
正确标注 sideEffects 包的 package.json 里声明

⚠️ sideEffects: false 标错会删掉样式文件。 CSS 导入是典型副作用，忘了在数组里列出 *.css，打包后样式直接消失——这是 Tree-shaking 最经典的翻车现场。

⚠️ Tree-shaking 只删「未被引用的导出」。**import 了但只在运行时用到的、或依赖动态属性的代码，摇不掉。**

七、代码分割、source map 与体积

source map 类型 说明
eval 最快，map 内联在 eval 里，dev 默认
inline map 以 base64 塞进产物，产物变大
hidden 生成 map 但不写 sourceMappingURL，供错误平台用
nosources-source-map 不含源码，只保留位置
cheap-* 只精确到行，构建更快

⚠️ 生产环境该不该上传 source map：上传到错误监控平台（如 Sentry）能定位堆栈，但别把 .map 公开部署，否则源码等于开源。

⚠️ 看体积要看 gzip / brotli 后的大小，不是原始大小。 原始 1MB 的文本压缩后可能只剩 200KB，stats 面板里那个「raw size」参考价值有限。

HMR 的基本原理

HMR 从「接受的模块边界」开始替换，边界内的模块被重新执行，不会刷新整个页面。没有 accept 的模块会一路冒泡到入口，冒泡到顶就退化成整页刷新。

⚠️ 模块里如果保存了闭包状态（定时器、WebSocket、事件监听），HMR 替换后旧状态可能泄漏。要么在 dispose 里清理，要么接受整页刷新。

八、Vite 的 dev 为什么快

阶段 Vite 传统打包器
dev 启动 不打包，直接用浏览器原生 ESM 全量打包，依赖越多越慢
依赖预构建 esbuild 把 CJS/多文件依赖打成单个 ESM 无
模块更新 只重新编译单个模块 重建受影响 chunk
生产构建 Rollup webpack / Rollup

关键点：dev 阶段不打包，浏览器按需请求模块；esbuild 用 Go 写，预构建比 JS 打包器快一到两个数量级。生产环境为了产物体积和兼容性，仍然走完整打包。

⚠️ Vite dev 和 build 走两套解析逻辑（dev 用原生 ESM + esbuild，build 用 Rollup），所以「dev 正常、build 报错」很常见，尤其是依赖的 exports 条件或 CJS 互操作问题。

⚠️ 常见优化：optimizeDeps.include 预构建大依赖、external 把 React/Vue 走 CDN、browserslist 决定降级语法、按需引入组件库。

常见坑清单

  • 以为 CJS 导出是引用，改了内部变量导出对象也跟着变
  • 在 ESM 里用 require / __dirname / __filename
  • 循环依赖导致某模块拿到 undefined
  • 加 exports 后子路径导入全挂（ERR_PACKAGE_PATH_NOT_EXPORTED）
  • exports 里条件顺序写反，default 放前面导致永远命中
  • 同时发 CJS/ESM 造成双包，单例状态不同步
  • import _ from 'lodash' 后抱怨包体积没减
  • sideEffects: false 误标，样式文件被删
  • 以为 import 可以写在 if 里（必须用 import()）
  • 生产部署把 .map 公开，源码泄露
  • 只看 raw size 判断包体积
  • type="module" 脚本里依赖顶层 this
  • 忘了 ESM 跨源需要 CORS，本地 file:// 打不开
  • HMR 不写 accept，每次改动整页刷新
  • require(esm) 遇到顶层 await 报错，没换 import()
  • 老浏览器不支持原生 ESM，dev 正常线上白屏

开场：一句话结论

自定义指令是操作 DOM 的最后手段，不是逻辑复用的手段。 逻辑复用优先用 composable；只有当需求本质是「对某个 DOM 元素做副作用」时才写指令。Teleport 管「DOM 渲染到哪」，插件管「全局能力怎么注入」。

一、自定义指令：钩子与生命周期的对应

指令对象是一组钩子，触发时机与所在组件强相关，作用对象是绑定的元素。

指令钩子 触发时机 对应组件钩子
created 属性应用前，未插入 DOM 早于 onBeforeMount
beforeMount 即将插入 DOM onBeforeMount 附近
mounted 已插入父节点 onMounted 附近，子元素可能未就绪
beforeUpdate 所在组件更新前 onBeforeUpdate
updated 组件与子组件都更新完 onUpdated
beforeUnmount 元素移除前 onBeforeUnmount
unmounted 元素移除后 onUnmounted

简写形式只对 mounted / updated 有效：app.directive('color', (el, b) => { el.style.color = b.value })。

⚠️ mounted 只保证本元素插入了，不保证子节点完成布局。在 mounted 里读 scrollHeight / 子元素宽度可能拿到旧值，用 nextTick 或 requestAnimationFrame 兜一层。

⚠️ updated 在所在组件任意更新时都触发，哪怕绑定的值没变。昂贵逻辑要先判断 binding.value !== binding.oldValue。

binding 三件套

v-demo:foo.bar.baz="someValue" 解析为 { value, oldValue, arg: 'foo', modifiers: { bar: true, baz: true }, instance, dir }。oldValue 仅 beforeUpdate / updated 中有。

⚠️ 指令挂在 el 上的属性与监听器必须自己在 unmounted 清。不 removeEventListener 时，闭包连同组件状态一起泄漏。

⚠️ binding.value 是快照，不是响应式引用。值内部变化不会重跑指令；只有绑定表达式求值结果变化、且组件因此更新时才触发 updated。要响应深层变化得自己在 mounted 里 watch。

二、指令 vs 组合式函数：能不用就不用

需求 指令 composable
自动聚焦 ✅ 直观 可以
数据请求 / 状态 ❌ ✅
需要返回值 / 多个值 ❌ 拿不到 ✅
参与响应式依赖追踪 ❌ 只有 DOM ✅
模板外复用 ❌ ✅
SSR 下工作 ⚠️ 需 getSSRProps ✅
纯逻辑单测 ❌ 要真实 DOM ✅

判断标准：输入输出与 DOM 无关的逻辑，就不该是指令。 指令只能拿 el 和 binding，无法返回值、无法被单测，这是硬边界 —— 比如「曝光时长」这类返回值只有 composable 能给。

v-permission 做按钮级权限

⚠️ 前端权限指令只是 UI 遮挡，不是安全边界。元素被移除，接口照样能被直接调用，真正的校验必须在后端。

⚠️ removeChild 之后元素不会被 Vue 插回。权限异步加载时 mounted 里 store 还是空的，按钮被误删且不恢复 —— 要么等权限就绪再渲染，要么改用 display: none。

⚠️ 多数场景用 v-if + 权限函数比指令更好：条件在模板里显式可见，接手的人不用翻指令定义。

指令在 SSR 下的行为

服务端没有 DOM，所以挂载类钩子（created 之外）在 SSR 期间不执行。

⚠️ 依赖 DOM 测量 / 事件绑定 / 第三方 DOM 库的指令在 SSR 下静默失效 —— 不报错，客户端 hydration 后才有行为，表现为首屏闪烁。别只盯着组件代码排查。

⚠️ 在 beforeMount 里增删 DOM 会导致 hydration mismatch；mounted 里改则不会（它在 hydration 之后跑）。

三、Teleport：把 DOM 渲染到别处

核心场景：模态框、通知、下拉菜单。它们需要脱离父级 DOM 树，否则会被父级 overflow: hidden 裁掉，或被父级的 transform / filter / z-index 创建的新层叠上下文困住。

属性 说明
to 目标选择器 / 元素，如 body、#modal-root
disabled true 时原地渲染，不传送
defer（3.5+） 推迟到本渲染周期之后再解析目标

多个 Teleport 到同一目标：按模板挂载顺序依次追加（先出现的在前），与 z-index 无关。

⚠️ to 的目标必须已存在。目标在同一次渲染里才创建时，3.5 之前直接报错，这就是 defer 被引入的原因。

⚠️ Teleport 只改 DOM 位置，不改组件树的逻辑父子关系。事件冒泡按 DOM 树走（冒到 body 下的祖先，不是模板里的父组件），provide/inject 仍按组件树走。「点击外部关闭」靠冒泡判断时会和直觉不一致。

⚠️ SSR 下 Teleport 内容在服务端不会真的插到 to 位置，客户端 hydration 时才传送，可能布局跳动。

四、Suspense：等待异步依赖

它等待默认插槽内的异步依赖：defineAsyncComponent 的异步组件，或 setup 顶层 await 的组件。事件有 pending（进入挂起）、resolve（默认插槽完成）、fallback（fallback 显示）。

⚠️ Suspense 截至 Vue 3.5 仍是实验性 API，官方标注 API 可能变化，生产使用要有跟版本改的心理准备。

⚠️ Suspense 只等待直接异步依赖，嵌套 Suspense 不向上冒泡；异步失败会抛到边界，需 onErrorCaptured 兜底，否则整棵树崩掉。

五、插件机制：app.use

app.use 是幂等的（同一插件只装一次），返回 app 可链式调用，且必须在 app.mount() 之前完成。

插件里可用的 app API：app.component / app.directive（全局注册）、app.provide（应用级注入）、app.config.globalProperties（不推荐）、app.config.errorHandler / warnHandler（全局错误 / 警告）、app.config.performance（组件性能追踪）、app.runWithContext(fn)（在应用上下文里执行 inject，3.3+）。

⚠️ app.component / app.directive 全局注册会让打包器无法 tree-shaking：注册了哪怕没用也进产物，且全局命名空间容易撞名，能局部导入就别全局注册。

globalProperties vs inject：优先 inject

维度 globalProperties app.provide + inject
Composition API 使用 需 getCurrentInstance() 直接 inject
类型推导 要手写模块扩展 inject 泛型
命名冲突 全局命名空间易撞 Symbol key 不会撞
可测试性 依赖全局实例 可单独 provide
响应式 非响应式，需自己包 传 ref / reactive 即可
推荐度 仅兼容旧代码 首选

app.provide 是应用级注入，与组件树的 provide 层级不同：应用级对整棵树可见，组件级只对子树可见，同名时离得近的覆盖远的。

⚠️ globalProperties 上的属性不是响应式的，模板里改它不触发重渲染。

⚠️ app.use / app.component / app.directive 写在 mount() 之后不报错也不生效 —— 这是「组件 / 指令莫名找不到」的常见原因。

六、组合式 API 的边界

effectScope 与手动清理

⚠️ 在组件 setup 外创建的 watch / watchEffect（全局单例、store 外部）不会自动清理，必须用 effectScope 包起来或手动 stop —— 否则「切页后旧 watch 还在跑」。

useTemplateRef（3.5+）

对比旧写法 const el = ref(null) + ref="el"（3.0+，变量名须与模板 ref 值一致）：useTemplateRef 显式声明名字、变量名自由，抽 composable 更稳。

⚠️ useTemplateRef 的参数是模板里 ref 属性的值，不是变量名。写错就一直拿到 null。

defineModel（3.4+ 稳定）与 useId（3.5+）

defineModel 编译后等价于声明 modelValue prop + update:modelValue emit，3.4 起稳定。

⚠️ defineModel 返回 ref，赋值即更新本地并 emit。要拦截修改用 defineModel({ set }) 自定义 setter，别在 watch 里改。

⚠️ useId 不能在 computed 里调用（实例冲突），必须在 setup 顶层同步调用一次；其值依赖组件树顺序，只在单次渲染内有意义，别当稳定 key 存进数据库。

常见坑清单

  • 在 mounted 里读子元素尺寸，拿到未完成布局的值
  • 把昂贵逻辑放 updated，不判断值是否变化
  • 指令挂在 el 上的属性 / 监听器不在 unmounted 清理
  • 以为 binding.value 是响应式引用，改值指令会自动重跑
  • 用指令做数据请求 / 状态管理（拿不到返回值、无法测试）
  • 前端权限指令当安全边界，以为接口不会被调
  • v-permission 在权限未就绪时误删元素且不恢复
  • 期望依赖 DOM 的指令在 SSR 下生效
  • Teleport 的 to 目标渲染时不存在（3.5 前报错）
  • 以为 Teleport 改变了组件逻辑父子关系
  • 父级 overflow: hidden / transform 裁掉弹层，没想到 Teleport
  • 生产环境用 Suspense 却没意识到它仍是实验性 API
  • app.use / app.component / app.directive 写在 mount() 之后
  • 用 globalProperties 挂工具对象，Composition API 访问别扭且无类型
  • 类型声明文件没写成模块，declare module 扩展失效
  • 组件外的 watch 不用 effectScope，切换后仍在跑
  • useTemplateRef 参数写成变量名而非模板 ref 值
  • 在 computed 里调用 useId

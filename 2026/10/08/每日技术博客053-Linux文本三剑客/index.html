开场：一句话结论

grep 按行筛选、sed 按行改写、awk 按列计算，靠管道串联各做一件事；一旦出现跨行状态机或多维聚合排序，直接换 Python，别在 awk 里硬堆。

一、grep：先选对正则引擎

选项 引擎 元字符 说明
默认 / -G BRE + ? { } | ( ) 需转义 POSIX 基本正则
-E ERE + ? { } | ( ) 直接可用 POSIX 扩展正则，首选
-F 无 全部字面量 固定字符串，最快
-P PCRE 额外支持 \d \w \b、环视 GNU grep 专属

⚠️ -P 不是 POSIX 标准，macOS 自带 BSD grep 不支持。需要 PCRE 用 ggrep（brew install grep）或 rg。

输出控制

选项 作用
-n / -v 行号 / 反向选择
-c 匹配行数，不是出现次数
-o 只输出匹配到的部分
-l / -L 只列匹配 / 不匹配的文件名
-q 静默，命中即退出，只看退出码
-r / -R 递归（-R 跟随符号链接）
-A n / -B n / -C n 后 / 前 / 前后各 n 行上下文
-m n 每文件最多匹配 n 次后停
--include / --exclude / --exclude-dir 按 glob 过滤文件与目录

⚠️ grep -r . 会连 .git、node_modules 一起扫，**递归必须配 --exclude-dir**。

词边界与退出码

写法 含义 可移植性
\b 词边界 GNU 扩展，ERE/BRE 均可
\< \> 词首 / 词尾 GNU 扩展
[[:<:]] [[:>:]] 词首 / 词尾 BSD 风格，GNU 不支持
-w 整词 最保险，两侧自动加边界
退出码 含义
0 至少选中了一行
1 一行都没选中
2 出错（文件不存在 / 正则非法 / 权限不足）

⚠️ 退出码 1 是「没匹配到」，不是错误。set -e 脚本里 grep pattern file
未命中会让整个脚本退出。判断存在性用 grep -q 或 || true。

⚠️ -w 的边界按「单词字符」判定，-w '1.2' 会匹配到 1.23。含标点的模式用 \b 手动控制。

二、sed：默认打印，-n 才静默

替换、分隔符与反向引用

写法 分组语法 备注
默认 BRE \(...\) POSIX
-E / -r (...) GNU 两者等价；BSD 只有 -E

地址范围 + 替换

⚠️ 1,10s/.../ 里的 1,10 是地址，不是替换参数。写成 s/1,10// 会被当成搜索串。

三、sed 多行与增删改

命令 作用
N 把下一行读进 pattern space，用 \n 连接
P 只打印 pattern space 的第一行
D 删掉第一行并重新开始脚本（不读新行）
h / H 复制 / 追加到 hold space
g / G 从 hold space 取回 / 追加
x 交换 pattern space 与 hold space
命令 位置 GNU 写法 POSIX 写法
a 匹配行之后 sed '/p/a text' a\ + 换行 + text
i 匹配行之前 sed '/p/i text' i\ + 换行 + text
c 替换匹配行 sed '/p/c text' c\ + 换行 + text

⚠️ a\ / i\ / c\ 在 POSIX 里后面必须跟一个真实换行，GNU 允许同一行。跨平台写 sed -e 'a\' -e 'text' 最稳。

⚠️ N 是状态机，可读性差、文件末尾无下一行时易报错或死循环。超过两行逻辑用 perl -0777 -pe 或 Python。

四、sed -i：GNU 与 BSD 的分歧点

平台 语法 说明
GNU（Linux） sed -i 's/a/b/' file 后缀可选
GNU 带备份 sed -i.bak 's/a/b/' file 生成 file.bak
BSD（macOS） sed -i '' 's/a/b/' file -i 必须带一个参数，空串表示不备份
BSD 带备份 sed -i '.bak' 's/a/b/' file 后缀要单独一个参数

⚠️ macOS 上 sed -i 's/a/b/' f 报 sed: 1: "f": invalid command code f ——
它把 f 当成备份后缀了，不是正则写错了。

⚠️ sed -i 是原地重写（内部写临时文件再 rename），对硬链接文件会断链，对正在写的日志可能丢数据。日志统计一律用只读的 sed -n。

五、awk：按列计算

变量 含义
$0 整行
$1 … $n 第 n 列
$NF / $(NF-1) 最后一列 / 倒数第二列
NF 当前行的列数
NR / FNR 已读记录数（累计）/ 当前文件内记录号
FS / OFS 输入 / 输出分隔符
RS / ORS 输入 / 输出记录分隔符
FILENAME 当前文件名

⚠️ 多文件判断「是不是第一个文件」用 NR==FNR，但第一个文件为空时会失效；更稳的是比较 FILENAME==ARGV[1]。

BEGIN / END / next / exit

语句 时机
BEGIN{...} 读输入之前执行一次
END{...} 输入读完之后执行一次
next 跳过本行剩余规则，读下一行
exit 跳到 END 块

关联数组与统计

⚠️ for (k in arr) 的遍历顺序不保证。需要有序输出必须接 | sort，或用 PROCINFO["sorted_in"]（gawk 专有）。

⚠️ awk 在不同发行版可能是 gawk / mawk / busybox awk。asort、asorti、gensub、\s 都是 gawk 扩展，Alpine 容器里直接报语法错误。

printf 格式化

格式 含义
%s / %d 字符串 / 整数
%f / %.2f 浮点 / 保留两位
%5s / %-5s 右对齐 / 左对齐，宽度 5
%06d 补零

六、组合实战

⚠️ ... | sh 是任意代码执行。文件名含空格、引号、$(...) 时直接变成注入或误删。先 cat 人工过一遍，或用 for f in *.log; do mv -- "$f" "$f.bak"; done。

⚠️ rename 有两套不兼容实现：Debian 系是 rename 's/a/b/'（Perl 版），RHEL 旧版是 rename a b files。脚本里别依赖它。

七、grep vs ripgrep，以及何时换 Python

维度 GNU grep ripgrep (rg)
引擎 BRE/ERE/PCRE Rust regex / PCRE2
速度 快 明显更快，多线程 + SIMD
递归 需 -r 递归是默认行为
忽略规则 无 自动读 .gitignore、跳过隐藏文件
可移植性 POSIX 环境必有 需单独安装，容器里常没有

⚠️ 默认 UTF-8 locale 下 grep/awk 走多字节字符处理，大文件开销显著。只处理 ASCII 日志时加 LC_ALL=C。

该换 Python 的信号 原因
需要排序后「下一行依赖上一行」 awk 状态机难维护
需要 JSON / CSV 语义解析 引号内逗号会骗过 -F,
需要访问数据库 / 发 HTTP shell 管道做不了
awk 脚本超过 ~15 行 调试成本高于重写

⚠️ awk 的 -F, 不认 CSV 引号规则，"a,b",c 会被切成三列。带引号的 CSV 用 csv 模块或 mlr / xsv。

常见坑清单

  • 用 grep -c 当出现次数（实际是匹配行数）
  • 在 macOS/BSD 上用 grep -P
  • grep -r 没加 --exclude-dir，扫进 .git / node_modules
  • set -e 脚本里 grep pattern file 未命中（退出码 1）导致脚本中断
  • 把退出码 1 当错误处理（2 才是真错误）
  • 递归 grep 二进制文件，输出乱码还慢（加 -I）
  • macOS 上 sed -i 报 invalid command code，其实是少了备份后缀参数
  • sed -i 用在硬链接文件上导致断链
  • 替换路径不换分隔符，写成一串 \/ 转义
  • BRE 里写 s/(\w+)/\1/，忘了分组要转义或加 -E
  • 把 1,10s/foo/bar/ 写成 s/1,10//，地址被当成搜索串
  • a\ / i\ / c\ 后面漏了换行（POSIX 要求）
  • 用 N 合并多行，文件末尾无下一行时报错
  • awk 里混用 NR 和 FNR 判断第一个文件
  • 依赖 for (k in arr) 的输出顺序
  • 在 Alpine / busybox 里用 asort、gensub、\s
  • awk -F, 解析带引号的 CSV
  • ls | sed ... | sh 直接执行，文件名含空格或 $() 时注入
  • 大文件不加 LC_ALL=C，白白多花几倍 CPU
  • 用 rename 却不知道发行版是哪套实现

开场：一句话结论

用 pathlib 代替 os.path，用 encoding='utf-8' 显式替代默认编码，用 timezone-aware 替代 utcnow()，用 decimal 替代 float 算钱 —— 这四条能挡掉 Python 数据处理里绝大多数线上事故。

一、pathlib 取代 os.path

os.path 用字符串拼接，手动拼 \ 或 / 换平台就断；且 os.path.join 返回的是 str，后续还得再套一层。

需求 os.path pathlib
拼接 os.path.join(a, b) a / b
文件名 / 后缀 os.path.basename / splitext .name / .suffix
是否存在 os.path.exists(p) p.exists()
读写文本 手动 open + with p.read_text() / p.write_text()
递归匹配 glob.glob("**/*.csv") p.rglob("*.csv")
绝对路径 os.path.abspath p.resolve()
相对路径 os.path.relpath p.relative_to(base)

⚠️ read_text() / write_text() 默认用平台默认编码。Windows 上是 GBK，Linux 上是 UTF-8 —— 同一份代码换机器就乱码。**必须写 encoding='utf-8'**。

⚠️ Path 与 str 不通用：open() 接受两者，但字符串方法（.split、+）不能用在 Path 上。传给第三方库前确认它要 Path 还是 str，str(p) 显式转换最省事。

⚠️ p.relative_to(base) 要求 p 确实是 base 的子路径，否则抛 ValueError。不确定时用 os.path.relpath 或先判断 base in p.parents。

二、文件读写与编码

参数 作用 常见坑
encoding 文本编码 不写就用平台默认（Windows=GBK）
newline 换行转换 写 CSV 时必须 newline=''
errors 解码失败策略 'replace' / 'ignore' / 'strict'（默认）
buffering 缓冲大小 大文件逐行读时影响性能

大文件必须流式读：

⚠️ for line in f 是行缓冲的，不是逐字节读 —— 内存占用与最长行的长度相关，与文件大小无关。这才是处理大文件的正确姿势。

⚠️ 二进制模式（'rb' / 'wb'）**不能传 encoding**，会抛 ValueError。二进制与文本模式互斥。

BOM：utf-8-sig

⚠️ 用 utf-8 读带 BOM 的文件，首行第一个字段会多出不可见字符 \ufeff，导致 'id' == '\ufeffid' 为 False —— 这种 bug 极难肉眼发现，表现为「列名对不上」。

三、csv 与 json

参数 说明
delimiter 分隔符，默认 ,，TSV 用 \t
quotechar 引号字符，默认 "
quoting QUOTE_MINIMAL（默认）/ QUOTE_ALL / QUOTE_NONNUMERIC
lineterminator 行结束符，默认 \r\n（csv 规范如此）

⚠️ 写 CSV 不加 newline=''，Windows 上 \r\n 会被再转义成 \r\r\n，每行之间多一个空行。这是 CSV 最常见的坑，官方文档专门写了这一条。

⚠️ 大 CSV 不要 list(csv.reader(f)) 一次读进内存，逐行迭代即可；需要批处理就手动按 N 行切块（itertools.islice）。

参数 作用
ensure_ascii=False 保留中文原字符，否则输出 "\u4e2d\u6587"
indent=2 缩进美化
sort_keys=True 键排序，便于 diff
default=fn 处理不可序列化对象（如 datetime）

⚠️ json.load 会把整个文件解析进内存。几 GB 的 JSON 会 OOM —— 改用 ijson 流式解析，或换成 NDJSON（每行一个 JSON 对象）逐行 json.loads。

⚠️ NDJSON 不是标准 JSON，别用 json.load 读。逐行 for line in f: json.loads(line) 才是正确用法。

四、datetime 与时区

写法 返回 状态
datetime.now() naive，无时区 仅用于本地展示
datetime.utcnow() naive，声称是 UTC ⚠️ 3.12 起废弃
datetime.now(timezone.utc) aware ✅ 推荐
datetime.now(ZoneInfo("Asia/Shanghai")) aware ✅

⚠️ utcnow() 返回的是 naive 对象，tzinfo is None。拿它和 aware 对象相减会抛 TypeError: can't subtract offset-naive and offset-aware datetimes。统一用 datetime.now(timezone.utc)。

⚠️ datetime.now() 不带时区信息，跨服务器（一台 UTC 一台 CST）算出来的「现在」差 8 小时却不报错 —— 时间错乱类 bug 的头号来源。

⚠️ strptime 的格式符必须完全匹配，%Y-%m-%d 解析 "2026/10/08" 直接抛 ValueError。解析前先统一分隔符。

五、decimal 与 re

⚠️ Decimal("19.99") 必须传字符串，传 float 会把浮点误差一起带进来（Decimal(19.99) → 19.989999999999998...）。

函数 匹配位置 返回
match 仅开头 Match 或 None
search 任意位置 第一个 Match 或 None
fullmatch 整串 Match 或 None
findall 全局 列表（有分组时只返回分组）
finditer 全局 Match 迭代器

⚠️ re.match 只从字符串开头匹配，这是最高频的误解。要「任意位置找」用 search。Python 3.4+ 可写 re.fullmatch 做整串匹配。

⚠️ re 内部有缓存，但缓存有上限（默认 512 条）。循环里动态拼正则要显式 re.compile 一次，避免反复编译。

⚠️ 默认贪婪：<.*> 会匹配到最后一个 >。用 <.*?> 非贪婪，或更精确的 <[^>]*>。

六、collections 与 itertools

容器 用途 备注
defaultdict(list) 分组聚合 缺 key 自动建默认值，免去 setdefault
Counter 计数 / Top-N Counter("abracadabra").most_common(2)
deque(maxlen=n) 双端队列 / 滑动窗口 超出 maxlen 自动从另一端弹出
OrderedDict 有序字典 3.7+ 普通 dict 已保序，仅 move_to_end 等仍需要

⚠️ itertools.groupby 只合并相邻的相同 key。输入未排序时，同一 city 的记录会被拆成多个组，且不报错 —— 必须先 sorted。

⚠️ zip(a, b) 默认按最短截断，长度不等会静默丢数据。Python 3.10+ 用 zip(a, b, strict=True) 让长度不等直接抛 ValueError。

七、subprocess 与临时文件

参数 作用
check=True 返回码非 0 抛 CalledProcessError（否则静默失败）
capture_output=True 捕获 stdout / stderr 到 r.stdout / r.stderr
text=True 以文本（而非 bytes）返回，等价 encoding='utf-8'
shell=True 交给 shell 解释，有注入风险，尽量避免
timeout 超时抛 TimeoutExpired

⚠️ shell=True 且命令里含用户输入 = 命令注入。列表形式 ["cmd", arg] 不经过 shell，参数不会被二次解释。

⚠️ 不加 check=True 时，子进程失败不会抛异常，只会体现在 r.returncode。忘了检查就会拿到空 stdout 却以为成功。

tempfile.TemporaryDirectory() 作为上下文管理器，退出时自动递归删除；shutil.copy2 复制且保留元数据（mtime 等），shutil.rmtree 递归删目录。

⚠️ shutil.rmtree 无回收站、无确认。路径变量一旦为空或拼错，可能删掉整个目录树。删前先 assert p.is_dir()。

常见坑清单

  • open() 不写 encoding，Windows 默认 GBK 导致乱码
  • 写 CSV 不加 newline=''，Windows 上每行多一个空行
  • 用 utf-8 读带 BOM 的文件，首字段多出 \ufeff
  • 用 readlines() 读大文件，内存直接爆掉
  • 二进制模式传了 encoding 参数
  • json.dump 不加 ensure_ascii=False，中文被转义成 \uXXXX
  • 用 json.load 读超大 JSON，全量载入内存 OOM
  • 用 json.load 读 NDJSON（应该逐行 json.loads）
  • 用 datetime.utcnow()（3.12 起废弃，返回 naive）
  • naive 与 aware datetime 相减，抛 TypeError
  • 服务器时区不同导致「现在」差 8 小时却无报错
  • 金额用 float，0.1 + 0.2 != 0.3
  • Decimal 传了 float 而不是字符串
  • 用 re.match 以为能任意位置匹配（实际只匹配开头）
  • itertools.groupby 前不排序，同组被拆散且不报错
  • zip 长度不等静默截断，没用 strict=True
  • subprocess 不加 check=True，失败被静默忽略
  • shell=True 拼接用户输入，命令注入
  • shutil.rmtree 路径变量拼错，误删整个目录

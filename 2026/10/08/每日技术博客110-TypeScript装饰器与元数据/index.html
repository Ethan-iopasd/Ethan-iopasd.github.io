四 装饰器与元数据 本篇

开场：一句话结论

先确定你用哪一代装饰器：experimentalDecorators: true 是旧版（元数据、DI 靠它），TS 5.0 起的标准装饰器是 (value, context) 签名 —— 两者不能混用。

一、两代装饰器必须分清

维度 旧版（实验性） 新版（标准 / Stage 3）
开关 experimentalDecorators: true TS 5.0+ 默认，需 experimentalDecorators: false
签名 (target, key, descriptor) (value, context)
属性装饰器 能拿到 target / key 拿到 undefined + context
参数装饰器 ✅ 支持 ❌ 不支持
元数据 emitDecoratorMetadata + reflect-metadata 无内置元数据
谁在用 Angular / NestJS / TypeORM / class-validator 新代码、库

⚠️ 两代签名完全不同：旧版方法装饰器收 (target, propertyKey, descriptor)，新版收 (value, context)。把旧写法放进新开关下编译，参数会全错位。
⚠️ 参数装饰器只有旧版有。NestJS 的 @Inject() / @Body() 依赖它 —— 所以 NestJS 必须开 experimentalDecorators: true。
⚠️ emitDecoratorMetadata 只对旧版有效。想要 design:paramtypes 做 DI，就必须留在旧版。

二、旧版五种装饰器

种类 签名 时机
类 (constructor: Function) => Function | void 类定义时
方法 (target, key, descriptor: PropertyDescriptor) => PropertyDescriptor | void 类定义时
访问器 (target, key, descriptor) => PropertyDescriptor | void 类定义时
属性 (target, key) => void 类定义时（拿不到实例）
参数 (target, key, parameterIndex) => void 类定义时

⚠️ 属性装饰器拿不到实例，也无法直接改值 —— 类定义时实例还不存在。要改值只能在构造里配合 Object.defineProperty（见第八节）。
⚠️ 参数装饰器的 key 在构造函数参数上是 undefined（那是构造器参数，不是方法参数）。

三、新版装饰器 (value, context)

装饰目标 value context.kind
类 构造函数 'class'
方法 方法函数 'method'
getter / setter getter / setter 函数 'getter' / 'setter'
字段 undefined 'field'
accessor { get, set } 'accessor'

context 的字段：

字段 说明
kind 上面那张表
name 成员名（字段为 string | symbol，可能为 undefined）
static / private 是否静态 / 是否 #private
access { get, set, has } 访问器对象
addInitializer(fn) 注册初始化钩子
metadata 装饰器间传值（需 TS 5.2+，仍是实验性）

⚠️ accessor 是标准装饰器体系里的新关键字，旧版装饰器场景下没有它。
⚠️ context.name 对字段**可能为 undefined**（比如 #private 或匿名场景），直接拼字符串会踩空。

四、装饰器执行顺序

总原则：求值（evaluate）自上而下，应用（apply）自下而上。

旧版顺序（TS 手册） 新版顺序
① 每个实例成员的参数 → 方法/访问器/属性装饰器 ① 类元素装饰器（声明顺序）
② 每个静态成员同上 ② 类装饰器
③ 构造函数参数的装饰器 ——
④ 类装饰器 ——

⚠️ 旧版里属性/参数装饰器先于方法装饰器应用。依赖顺序做初始化的代码（如把元数据攒起来再读）很容易在这里翻车。
⚠️ 多个装饰器套同一目标时，求值自上而下、应用自下而上 —— 写 @A @B 实际是 A(B(target))。

五、reflect-metadata 与 design:* 元数据

元数据键 含义
design:type 属性/参数声明类型
design:paramtypes 方法/构造函数参数类型数组
design:returntype 返回值类型

⚠️ 必须 import 'reflect-metadata' 一次，否则 Reflect.getMetadata 根本不存在 —— 报错是运行时的 Reflect.getMetadata is not a function。
⚠️ **必须开 emitDecoratorMetadata**，否则 design:paramtypes 全是 undefined。
⚠️ 接口与字面量类型拿不到真实类型：只能发射运行时存在的构造器，interface Foo / {a: 1} 会被降级成 Object。
⚠️ 泛型会被擦除：Array<string>、Repo<User> 在 design:type 里只剩 Array / Object，具体类型参数拿不回来。

六、用装饰器做 DI（NestJS 的思路）

环节 依赖什么
标记 @Injectable()（类装饰器）
类型信息 design:paramtypes（需 emitDecoratorMetadata）
解析 容器递归 resolve + 缓存单例
手动指定 @Inject(TOKEN)（参数装饰器，旧版）

⚠️ DI 全靠 design:paramtypes，所以接口注入必须用 @Inject(TOKEN) 手动给 token —— 接口在元数据里只是 Object。
⚠️ 循环依赖会让元数据在某一侧为 undefined（见第九节），需要 forwardRef 之类的手段打断。

七、用装饰器做校验 / 路由 / 日志 / 缓存 / 重试

场景 切入点 关键 API
日志 / 埋点 方法装饰器 包裹原函数
缓存 方法装饰器 context.name + 参数序列化做 key
重试 方法装饰器 循环 + 退避
路由注册 方法/类装饰器 把 path 存进元数据，框架启动时扫描
事务 方法装饰器 包裹 begin / commit / rollback

⚠️ 校验装饰器不产生编译期类型，@IsEmail() 不会把 string 收窄成「邮箱格式」。运行时校验 ≠ 静态类型安全。
⚠️ AOP 装饰器会改变 this 绑定和函数签名（返回新函数），对 super 调用、Function.length、fn.name 都有影响。
⚠️ 缓存装饰器用「参数序列化」做 key 时，JSON.stringify 对 undefined / 函数 / Symbol / 循环引用都不可靠。

八、打包工具与 useDefineForClassFields

工具 experimentalDecorators 标准装饰器 emitDecoratorMetadata
tsc ✅ ✅ ✅
esbuild ✅（有限） ✅ ❌ 不支持
swc ✅ ✅ ✅（需显式开启）
babel ✅（legacy 插件） ✅ ✅（插件）

⚠️ useDefineForClassFields: true（ES2022+ 默认）会破坏旧版属性装饰器：字段用 [[Define]] 语义创建自有属性并覆盖原型上的描述符，装饰器写进原型的东西被 undefined 盖掉。
⚠️ esbuild 不支持 emitDecoratorMetadata —— 依赖 design:paramtypes 的 DI 用 esbuild 打包会直接失效。NestJS 生产构建通常保留 tsc 或换 swc。
⚠️ 新版装饰器 + emitDecoratorMetadata 无意义：标准装饰器没有 design:* 元数据这一层。

九、常见坑（汇总）

现象 原因 解法
Reflect.getMetadata is not a function 没 import reflect-metadata 入口最顶部 import 'reflect-metadata'
design:paramtypes 全 undefined 没开 emitDecoratorMetadata 打开该选项
接口注入拿到 Object 接口无运行时构造器 用 @Inject(TOKEN)
泛型类型丢失 类型擦除 手动传 token / 显式标注
元数据在循环依赖处为 undefined 模块求值顺序 forwardRef / 拆分模块
属性装饰器改的值被覆盖 useDefineForClassFields 关掉，或改 accessor
esbuild 打包后 DI 失效 不支持 emitDecoratorMetadata 换 swc / 保留 tsc
新旧装饰器混用参数错位 签名不同 统一开关，别混用

⚠️ 循环依赖导致的元数据 undefined 是最隐蔽的一类：A 装饰器求值时 B 还没定义完，design:paramtypes 里就是 undefined，表现是运行时 DI 报「无法解析依赖」。
⚠️ strict 模式下的类型收窄不会穿过装饰器：装饰器是运行时函数，静态类型在它眼里已经退化成 Function / any。

常见坑清单

  • 开了标准装饰器却照抄旧版 (target, key, descriptor) 签名
  • 想在标准装饰器里写参数装饰器（不支持）
  • 依赖 design:paramtypes 却没开 emitDecoratorMetadata
  • 忘了 import 'reflect-metadata'，运行时才炸
  • 用接口做 DI token，元数据里只有 Object
  • 以为泛型类型参数能从元数据拿回来
  • 属性装饰器里直接 this.xxx = ...（没有实例）
  • 属性装饰器改的值被 useDefineForClassFields: true 覆盖
  • 用 esbuild 打包依赖元数据的 DI 代码
  • 多个装饰器时算错应用顺序（求值自上而下、应用自下而上）
  • 旧版里忽略「属性/参数装饰器先于方法装饰器」
  • 循环依赖导致元数据 undefined，DI 启动失败
  • 用装饰器做校验就以为拿到了编译期类型收窄
  • AOP 装饰器里破坏 this / super 语义
  • 缓存装饰器用 JSON.stringify 做 key，遇到 undefined / 循环引用失效
  • 混用新旧装饰器开关，编译产物行为不一致

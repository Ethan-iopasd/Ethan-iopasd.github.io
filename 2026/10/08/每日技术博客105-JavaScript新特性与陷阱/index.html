开场：一句话结论

新 API 解决的是老写法里的默认行为坑（原地修改、|| 吞掉 0、JSON 丢类型），记住「哪些已定稿、哪些还在提案」比记语法更重要。

一、?. / ?? / 逻辑赋值

表达式 0 '' false NaN null
x || fallback fallback fallback fallback fallback fallback
x ?? fallback 0 '' false NaN fallback

⚠️ ?? 与 || 不能不加括号混用：a ?? b || c 是语法错误，必须写 (a ?? b) || c 或 a ?? (b || c)。
⚠️ ?. 只挡 null / undefined，**不挡 0 / '' / NaN**；对未声明的变量用 ?. 仍会 ReferenceError。

二、Object.groupBy / Map.groupBy（ES2024）

方法 返回 键类型
Object.groupBy null 原型对象 string / symbol
Map.groupBy Map 任意（含对象）

⚠️ Object.groupBy 返回的是 null 原型对象 —— 没有 hasOwnProperty，for...in 也安全（无原型链污染）。要方法就 Object.hasOwn(g, k)。
⚠️ 不要用 Array.prototype.group —— 那个名字的提案已被 Object.groupBy / Map.groupBy 取代，未定稿的旧写法别用。

三、不改原数组的那批方法（ES2023）

会改原数组 不改原数组（ES2023）
sort toSorted
reverse toReversed
splice toSpliced
arr[i] = v with(i, v)
—— findLast / findLastIndex
—— at（支持负索引）

⚠️ sort 默认按字符串序：[10, 9, 1].sort() → [1, 10, 9]。数字排序必须 sort((a, b) => a - b) —— toSorted 继承同样规则。
⚠️ with / toSpliced 返回新数组，在 React state 更新里比 splice 安全得多。

四、structuredClone（ES2022）

能力 JSON.parse(JSON.stringify(x)) structuredClone
Date ✗ 变字符串 ✓
Map / Set ✗ 变 {} ✓
undefined 属性 ✗ 丢 ✓
循环引用 ✗ 抛错 ✓
RegExp / ArrayBuffer ✗ ✓
函数 ✗ ✗ 抛 DataCloneError
DOM 节点 ✗ ✗
原型链 ✗ 丢 ✗ 丢（得到普通对象）
类实例 ✗ ✗ 丢原型

⚠️ structuredClone 不支持函数和 DOM 节点，遇到会抛 DataCloneError；它走的是结构化克隆算法，与 postMessage 一致。
⚠️ 克隆类实例会丢失原型 —— 得到的是普通对象，方法全没了。

五、Promise.withResolvers（ES2024）与 Array.fromAsync（ES2025）

特性 定稿版本
Promise.withResolvers ES2024
Promise.try ES2025
Array.fromAsync ES2025
Set 方法（union / intersection / difference / symmetricDifference / isSubsetOf…） ES2025
Iterator helpers（map / filter / take / drop…） ES2025

⚠️ Array.fromAsync 是 ES2025（ECMA-262 第 16 版） 定稿，不是 ES2023 —— 别被二手文章带偏。
⚠️ Promise.withResolvers 把 resolve / reject 拿出来后，忘调就会永久 pending；它只是省了样板，不省心智负担。

六、Object.hasOwn / at / catch {} / #private

写法 私有性 备注
this._x 约定，不强制 外部照样能读写
this.#x 运行时强制 语法级私有，Object.keys 也看不到
TS private 仅编译期 编译后就是普通属性

⚠️ catch {} 省略绑定后，拿不到错误对象 —— 要记录错误就得写 catch (e)。
⚠️ #private 是运行时私有；TS 的 private 编译后只是普通字段，用 obj['secret'] 照样访问。

七、字符串 / 正则 / 数字

特性 说明
replaceAll 全局替换，无需 /g
matchAll 必须带 /g，返回迭代器（不是数组）
命名捕获组 (?<name>...) result.groups.name
d 标志 exec 结果多出 indices
BigInt 123n 任意精度整数

⚠️ BigInt 不能与 Number 混算：1n + 1 抛 TypeError，必须显式 BigInt(1) 或 1n + BigInt(1)。
⚠️ JSON.stringify 不支持 BigInt —— 直接抛 TypeError: Do not know how to serialize a BigInt，得自己 toString()。
⚠️ matchAll **必须带 /g**，否则抛 TypeError；且它返回迭代器，.map 要先 [...] 展开。

八、WeakMap / WeakRef / FinalizationRegistry

API 键/值 可枚举 用途
WeakMap 键必须是对象 否 给对象挂私有数据，不阻止回收
WeakSet 元素是对象 否 标记对象
WeakRef 弱引用单个对象 否 缓存，不阻止回收
FinalizationRegistry 回收回调 否 清理副作用

⚠️ WeakRef / FinalizationRegistry 不可用于确定性清理 —— 回收时机由 GC 决定，完全不可预测。别拿它做资源释放的保证。
⚠️ WeakMap 的键必须是对象，用字符串键会抛错；且不可遍历（没有 size / keys）。

九、Intl / AbortSignal / URL

手写解析 用内置
正则拆 query URLSearchParams
new Date().toLocaleString() Intl.DateTimeFormat
手写超时 setTimeout + abort AbortSignal.timeout()
手写字符串分割 Intl.Segmenter（含中文分词）

⚠️ AbortSignal.timeout() 在 Node 17.3+ / 现代浏览器 才有；旧环境要 AbortController + setTimeout 手写。
⚠️ Intl.Segmenter 需要运行时带 ICU 数据；某些精简构建（如 small-icu 的 Node）行为不同。

十、经典陷阱（十年不变）

表达式 结果
[] == false true
null == undefined true
null === undefined false
'' == 0 true
'0' == false true
[] == ![] true

⚠️ 永远优先 ===。== 的隐式转换表没人能全记住，[] == ![] 这种结果毫无可读性。
⚠️ 0.1 + 0.2 是 IEEE 754 双精度的必然，不是 JS bug；金额用整数分或 BigInt / decimal 库。
⚠️ 稀疏数组的 map / forEach 跳过空位（undefined 元素不跳，真·空位才跳）—— 两者行为不同。
⚠️ setTimeout(fn, 0) 实际有最小延迟（HTML 规范约 4ms 起，嵌套超过 5 层后强制 ≥4ms），不是立即执行。
⚠️ queueMicrotask 插在微任务队列，先于下一个 setTimeout 宏任务执行。

十一、Error 的 cause

⚠️ cause 需要运行时支持（Node 16.9+ / 现代浏览器）。日志里要显式打印 err.cause，否则错误链照样丢。

常见坑清单

  • 用 || 给数字/字符串兜底，把 0 / '' 吃掉
  • ?? 和 || 不加括号混用（语法错误）
  • 以为 ?. 能挡 0 / '' / NaN
  • 用 sort 排数字，忘了传比较函数
  • 直接 splice / sort / reverse 改 React state 里的数组
  • 用 JSON.parse(JSON.stringify()) 克隆，丢 Date / Map / 循环引用
  • 用 structuredClone 克隆函数或 DOM，抛 DataCloneError
  • 克隆类实例后还指望方法还在（原型丢了）
  • 把 Array.fromAsync 说成 ES2023
  • matchAll 忘了 /g，或当数组用
  • BigInt 和 Number 混算，或直接塞进 JSON.stringify
  • 用 WeakRef / FinalizationRegistry 做确定性清理
  • WeakMap 用字符串当键
  • 用 == 比较，被 [] == false 之类结果坑到
  • 用浮点数算金额，出现 0.1 + 0.2 误差
  • 依赖 typeof null === 'object' 之外的值判断空
  • parseInt 不传基数，遇到前导 0 / 0x 语义不明
  • 稀疏数组 map / forEach 跳过空位，以为会处理每个下标
  • 以为 setTimeout(fn, 0) 是同步立即执行
  • catch {} 省了绑定又需要错误对象

四 存储、StatefulSet 与 Operator 本篇

开场：一句话结论

无状态用 Deployment + 任意 Volume；有状态用 StatefulSet + volumeClaimTemplates + Headless Service；而 Operator 的本质是把人的运维判断写成 reconcile 循环。

一、Volume 家族

类型 生命周期 用途
emptyDir 随 Pod 销毁 临时缓存、容器间共享
hostPath 随节点 挂节点目录（不跨节点）
configMap / secret 随对象 注入配置 / 密钥
projected 随对象 把多个来源合并进一个目录
downwardAPI 随 Pod 把 Pod 元数据暴露给容器

⚠️ emptyDir 在 Pod 删除后数据就没了，只适合可重建的临时数据；要持久化必须用 PV。

⚠️ hostPath 不跨节点共享。多副本 Pod 被调度到不同节点时，各自看到的是本机目录，数据不一致 —— 这是最常见的误区之一。

⚠️ configMap / secret 以 Volume 挂载时会自动更新，但以环境变量注入时不会（需重启 Pod）。改配置后没生效，先看注入方式。

二、PV / PVC / StorageClass

三者关系：PVC 是「申请」，PV 是「资源」，StorageClass 是「按需生产的模板」。

字段 取值 说明
accessModes RWO / ROX / RWX 见下方
reclaimPolicy Retain / Delete PVC 删除后 PV 的去向
volumeBindingMode Immediate / WaitForFirstConsumer 何时绑定
allowVolumeExpansion true / false 是否支持在线扩容

⚠️ RWO 是「单节点读写」，不是「单 Pod」 —— 同一节点上的多个 Pod 可以同时挂。要严格单 Pod 需用较新版本的 ReadWriteOncePod。

⚠️ reclaimPolicy: Delete 下删 PVC 会连底层卷一起删，数据直接没了。生产数据盘用 Retain，并配好 PV 回收流程。

⚠️ WaitForFirstConsumer 解决的是跨可用区挂载失败：Immediate 会先建卷（可能建在 zone-a），Pod 却被调度到 zone-b，卷挂不上。延迟绑定让卷跟着 Pod 走。

⚠️ 在线扩容要求 StorageClass 开 allowVolumeExpansion，且只能扩不能缩；扩容后部分文件系统需要重启 Pod 才能识别新容量。

三、StatefulSet 与 Deployment 的差异

维度 Deployment StatefulSet
网络标识 随机 Pod 名 稳定 <name>-0 / -1
存储 共享或临时 volumeClaimTemplates 每副本独立 PVC
创建 / 删除 并行 有序（默认 OrderedReady）
升级 一起滚动 逆序，可用 partition 灰度
Service 普通 ClusterIP 通常配 Headless

⚠️ partition 是灰度升级的关键：partition: N 表示只升级序号 ≥ N 的 Pod。先把 partition 设为 replicas 冻结，再逐步下调验证。

⚠️ 删除 StatefulSet 默认不删 PVC（这是有意的保护）。要清理得手动删 <name>-<ordinal> 的 PVC，否则重建时会挂到旧数据上。

⚠️ podManagementPolicy: OrderedReady 下，0 号 Pod 不 Ready 会卡住整个扩容 / 升级。对等节点（如 etcd、Cassandra）可用 Parallel 提速。

四、有状态应用运维要点

  • 主从选举：多数系统靠应用自身协议（Raft / Paxos）选主，K8s 不参与；只提供稳定标识。
  • 只写主节点：客户端必须知道谁是主，通常通过 Headless DNS 或额外 Service 暴露。
  • 优雅终止：terminationGracePeriodSeconds 要足够长，确保数据落盘 / 摘流完成。

Headless Service：clusterIP: None，DNS 返回所有 Pod 的 A 记录。

⚠️ **terminationGracePeriodSeconds 到了会被 SIGKILL**，正在写的页可能丢。数据库类应用要调大，并配合 preStop 先摘流。

⚠️ Headless Service 的 DNS 不返回 ClusterIP，客户端拿到的是 Pod IP 列表；Pod IP 会变，所以客户端要处理重解析或直接用有状态客户端的协议。

五、Operator 模式

核心思想：把运维知识编码成控制器。CRD 定义「期望状态」，控制器跑 reconcile 循环把实际状态拉齐。

组成 作用
CRD 定义新资源类型与 schema
控制器 watch CR + 关联资源，执行 reconcile
spec 期望状态（用户写）
status 实际状态（控制器写）
finalizer 删除前的清理钩子
ownerReferences 级联删除的依据

⚠️ 不要用 spec 存状态。spec 是用户意图，控制器回写会被下一次 reconcile 覆盖，也会和 GitOps diff 打架。状态一律放 status。

⚠️ finalizer 不删会导致资源「删不掉」 —— 它卡在 Terminating，直到控制器移除 finalizer。控制器挂了就会永久卡住，需人工清。

⚠️ ownerReferences 决定级联删除；不设的话子资源（Service / PVC）会变成孤儿，重建时冲突。

⚠️ status 要能被外部读：用 kubectl get 的自定义列（additionalPrinterColumns）和 conditions 暴露关键状态，否则运维只能猜。

六、CRD 与 Admission Webhook

CRD 设计要点：

要点 说明
schema 校验 用 OpenAPI schema + x-kubernetes-validations（CEL）挡住非法输入
版本与转换 多版本要配 conversion webhook
子资源 开 status / scale 子资源，避免并发写冲突
默认值 用 default 让字段有确定语义

Admission Webhook：

类型 作用 阶段
MutatingWebhook 改对象（补默认值 / 注入 sidecar） 先
ValidatingWebhook 拒绝非法对象 后

⚠️ Webhook 的证书轮换是运维坑：证书过期后 admission 会失败，整个集群可能无法创建任何资源（failurePolicy: Fail 时）。务必配好自动轮换与 failurePolicy 取舍。

⚠️ failurePolicy: Fail 意味着 webhook 挂了就拒绝一切；Ignore 则放行。生产要在「安全」与「可用性」之间明确选一个。

⚠️ MutatingWebhook 频繁改动对象会触发额外 reconcile 循环，注意幂等，避免「改一下、又触发一次」的死循环。

七、Job / CronJob / DaemonSet

字段 取值 含义
concurrencyPolicy Allow / Forbid / Replace 上次没跑完时怎么办
backoffLimit 整数 失败重试上限
activeDeadlineSeconds 秒 超时终止

DaemonSet：每个（或指定）节点跑一个 Pod，toleration 让它能上带污点的节点，updateStrategy 控制滚动。

⚠️ concurrencyPolicy 默认是 Allow —— 上一次任务没跑完，下一次照样起，可能并发改同一份数据。任务不可重入时设成 Forbid。

⚠️ CronJob 不保证「到点必跑」：控制器重启 / 节点故障会错过触发，startingDeadlineSeconds 决定错过多久内还补跑。

⚠️ **DaemonSet 要能上 control-plane 节点必须加对应 toleration**（node-role.kubernetes.io/control-plane 的 NoSchedule），否则日志 / 监控 Agent 少一半节点。

八、存储实践与备份

存储类型 性能 可用性 适用
云盘（EBS / 云硬盘） 中高 高（多副本） 通用持久化
本地盘（Local PV） 高 低（绑节点） 缓存、高吞吐中间件
网络存储（NFS / Ceph / Longhorn） 中 取决于实现 共享读、RWX 场景

数据库该不该跑在 K8s 上的判断依据：

  • 能接受节点故障导致短暂不可用（有选主、有重试）→ 可以。
  • 强依赖本地 NVMe 低延迟且不能容忍重调度抖动 → 谨慎，或上 Local PV + 反亲和。
  • 团队没有 Operator / 备份 / 演练 能力 → 先别上。

⚠️ 没验证过可恢复的备份等于没有备份。定期做恢复演练（恢复到隔离命名空间），确认数据与 PVC 都能回来。

⚠️ velero 的快照依赖云厂商 CSI 或 Restic / Kopia；纯 hostPath / 本地盘往往只能走文件级备份，恢复慢且可能不一致。

⚠️ 有状态服务迁移的难点在数据：跨集群 / 跨可用区迁移要处理卷快照、DNS、客户端连接串，不是改个 image 就完事。

常见坑清单

  • 把 emptyDir 当持久化用，Pod 重建后数据丢失
  • 用 hostPath 让多副本共享数据（不跨节点）
  • 改了 ConfigMap 却用环境变量注入，以为会自动生效
  • 把 RWO 理解成「只能一个 Pod 挂」
  • 数据盘用 reclaimPolicy: Delete，删 PVC 丢数据
  • 跨可用区场景用 Immediate 绑定，Pod 调度后挂不上卷
  • 在线扩容没开 allowVolumeExpansion
  • 用 Deployment 跑有状态服务，Pod 名和存储不稳定
  • 直接删 StatefulSet 以为会连 PVC 一起删（默认保留）
  • terminationGracePeriodSeconds 太短，数据没落盘就被 SIGKILL
  • CronJob 用默认 Allow，任务并发改同一份数据
  • finalizer 不清导致资源卡在 Terminating
  • Webhook 证书过期，failurePolicy: Fail 下集群创建不了资源
  • 有状态服务从不做备份恢复演练

开场：一句话结论

Vue 3 的 diff 不是「全树比对」：编译器把模板标成 block tree + patchFlag，运行时只走动态节点。不理解这层，key、v-if、静态提升的行为就全靠背。

一、渲染管线三段

阶段 做什么 时机
Compile 模板 → render 函数（返回 vnode 树） 构建期（vue）或运行时（vue/dist/*.js）
Mount 执行 render → 建真实 DOM，收集响应式依赖 首次渲染
Patch 依赖变化 → 重新 render → 比对新旧 vnode → 更新 DOM 依赖变更

vnode 是普通对象；手写渲染用 h()：

写法 灵活性 编译期优化
模板 中 ✅ 完整（静态提升 / patchFlag / block）
h() / JSX 高 ⚠️ 基本没有

⚠️ 用 h() 或 JSX 手写渲染逻辑时拿不到编译期优化：每次重渲染都会新建全部 vnode、全量比对。只有高度动态的组件才值得付这个代价。

二、编译优化三件事

1. 静态提升：无动态绑定的节点，vnode 只在首次渲染时创建并缓存，后续复用同一对象；连续多个静态元素还会压成一个 static vnode（内含整段 HTML），挂载时直接 innerHTML。

2. patchFlag：编译期把「这个节点会怎么变」编码成数字，运行时用位运算判断。

常用取值（@vue/shared 的 patchFlags.ts）：

常量 值 含义
TEXT 1 动态文本子节点
CLASS / STYLE / PROPS 2 / 4 / 8 动态 class / style / props
FULL_PROPS 16 含动态键的 props，需全量比对
NEED_HYDRATION 32 SSR 水合时需处理
STABLE_FRAGMENT 64 子节点顺序稳定
KEYED_FRAGMENT / UNKEYED_FRAGMENT 128 / 256 带 / 不带 key 的 fragment
NEED_PATCH / DYNAMIC_SLOTS 512 / 1024 自定义指令 / 动态插槽
HOISTED / BAIL -1 / -2 静态跳过 / 放弃优化走全量 diff

3. block tree 与 tree flattening：整个模板包成一个 block，并收集所有带 patchFlag 的后代节点（非仅直接子节点）到扁平数组：

重渲染时只遍历这个扁平数组，静态部分完全跳过。

⚠️ v-if 和 v-for 会创建新的 block，并挂到父 block 的动态后代数组里 —— 这是结构稳定性的来源。手写 render 时用 openBlock() / createElementBlock() 才能享受同样优化。

⚠️ patchFlag 是编译产物。运行时动态生成的 vnode（如 h(type, props) 里 type 是变量）只能标 BAIL，diff 成本显著高于模板编译结果。

三、v-if vs v-show

维度 v-if v-show
DOM 条件为假时不存在 始终存在
切换成本 高（创建 / 销毁 + 生命周期） 低（改 display）
初始成本 低（假则完全不渲染） 高（无论真假都要渲染）
编译产物 if 分支 + 独立 block v-show 指令 + NEED_PATCH
适用 切换少、初始为假、含重组件 切换频繁

⚠️ v-show 不能用在 <template> 上，也不支持 v-else；v-if 两者都支持。语义不同，不能互换。

⚠️ v-if 的销毁会触发 unmounted 并清空内部状态；v-show 保留组件实例与状态。表单里用 v-show 隐藏再显示，用户输入还在 —— 有时是想要的，有时是 bug。

四、key 的作用

key 是 diff 算法的身份标识。无 key 时用「就地复用 + 尾部优化」，有 key 时用「头尾双端比对 + 最长递增子序列」求最小移动。

场景 无 key 有 key
纯静态列表 ✅ 更快（少移动） 略慢
含输入框 / 组件状态 ❌ 状态错位 ✅ 正确
频繁插入 / 删除 / 排序 ❌ 大量 patch ✅ 最小移动

⚠️ 不要用数组下标当 key。下标在插入 / 删除后会「继承」到别的元素上，等于没 key，还会让 diff 误判为「内容变了」而非「位置变了」。

⚠️ 用 Math.random() 当 key 会导致每次渲染都是全新节点，组件被反复销毁重建，状态全丢、性能极差。

⚠️ key 也能强制重建组件：换一个 key，Vue 会销毁旧的、挂载新的 —— 比手动清空 ref 更彻底，是重置组件内部状态的常用手段。

五、受控与非受控模式

模式 谁持有状态 典型写法
受控 父组件 :value + @update:value
非受控 子组件自己 :defaultValue，内部 ref 持有
半受控 两者 有 value 则受控，否则内部状态

多参数 v-model（Vue 3 支持任意名字）：父写 <UserForm v-model:name="name" v-model:age="age" />，子写 const name = defineModel('name') / const age = defineModel('age', { type: Number })。

⚠️ defineModel 在 Vue 3.4 才从实验转正。3.3 及以前要手写 props.modelValue + emit('update:modelValue')；升级前先确认构建链里的 Vue 版本一致，否则 SFC 编译会报未知宏。

⚠️ 受控组件里不要把 props.modelValue 复制进内部 ref 再双向绑定 —— 父组件更新时子组件不会同步。要么直接绑 props，要么用 watch + computed 显式同步。

六、无渲染组件与组合式函数

无渲染组件（renderless） 只提供逻辑和插槽，不产出自己的 DOM：

用法：<DataFetcher url="/api/user" v-slot="{ data, loading }"> 内自行决定渲染内容。

方案 复用模板 复用逻辑 类型推断
mixin ✅ ⚠️ 命名冲突 ❌
无渲染组件 ✅ ✅ 中
组合式函数 ❌ ✅ ✅ 最好
高阶组件 ✅ ✅ 中

⚠️ 无渲染组件多一层组件实例与插槽渲染开销。纯逻辑复用优先用组合式函数，只有复用内容包含「模板结构」时才值得上无渲染组件。

⚠️ 组合式函数里用 onMounted / onUnmounted 必须在 setup 同步执行期调用。放进 await 之后或异步回调里，生命周期钩子会丢失绑定并告警。

七、defineExpose 与模板 ref

<script setup> 组件默认关闭，父组件拿到的 ref 上什么都没有，需要在子组件里 defineExpose({ count, focus }) 显式暴露。

场景 是否需 defineExpose
<script setup> 子组件 ✅ 必须
选项式 API 子组件 ❌ 默认全部可访问

⚠️ 父组件里 child.value 在**挂载前是 null**。在 setup 顶层直接访问拿不到实例，必须在 onMounted 之后或事件回调里访问。

⚠️ defineExpose 暴露的是引用而非快照。父组件改 child.value.count++ 会直接改子组件状态 —— 双向强耦合，组件库场景应改为 emit 事件。

八、provide / inject 做依赖注入

做法 效果
provide(key, ref) 后代拿到响应式引用
readonly(ref) 禁止后代直接改，只能走方法
Symbol 作 key 避免命名冲突
app.provide() 全局注入

⚠️ inject 默认不做响应式解包：inject('x') 拿到的是 ref 本身，模板里自动解包，但 <script> 里必须写 x.value。用解构会丢失响应性。

⚠️ provide 的值在同一组件实例内不可变绑定 —— 想改就 provide 一个 ref 或一个对象，而不是 provide 原始值。

九、$attrs 透传与 inheritAttrs

项 说明
默认 inheritAttrs: true 未声明的 attrs 自动落到根元素
inheritAttrs: false 关掉自动落点，自己决定往哪放
$attrs 未在 props / emits 中声明的透传属性 + 事件监听
多根组件 自动落点失效，必须手动转发

⚠️ 多根节点（fragment）组件无法自动继承 attrs，Vue 会警告 Extraneous non-props attributes。必须显式 v-bind="$attrs"，否则 class / style / 事件监听全部丢失。

⚠️ $attrs 里的 class 和 style 是合并而非覆盖语义。透传到内层元素时 class 会叠加，做条件样式要注意优先级。

十、异步组件与 Suspense

⚠️ <Suspense> 目前仍是实验性特性（官方文档明确标注 experimental），不保证进入稳定状态，API 可能变动。生产环境用之前先评估升级风险。

⚠️ Suspense 只捕获 setup 顶层的 await。onMounted、事件回调、watch 里的异步操作不会被感知，也不会触发 fallback。

⚠️ 异步组件的 loadingComponent 与 Suspense 的 #fallback 会同时生效，容易叠出两层 loading。二选一，不要混用。

十一、headless 模式

组件只提供状态与可访问性逻辑，样式完全交给使用方：

⚠️ headless 把可访问性（role、aria-*、键盘导航）的责任推给了使用方。组件内部必须把必要的 aria 属性通过 slot props 暴露出来，否则每个使用方都会漏做。

⚠️ 作用域插槽会强制子组件重渲染（Vue 3 已大幅优化，但动态插槽仍标 DYNAMIC_SLOTS）。列表里大量使用作用域插槽时注意压测。

常见坑清单

  • 用 h() / JSX 写高频重渲染组件，丢掉全部编译期优化
  • 手写 render 函数没配 openBlock() / createElementBlock()，退化成全量 diff
  • v-show 用在 <template> 上或配 v-else
  • 用 v-show 隐藏含表单的组件，以为状态会被重置
  • 列表用数组下标当 key，或用 Math.random() 当 key
  • 受控组件里把 props 复制进内部 ref，父更新不同步
  • 组合式函数里在 await 之后调 onMounted
  • <script setup> 子组件没 defineExpose，父组件 ref 全空
  • 在 setup 顶层直接访问模板 ref，拿到 null
  • inject 后解构，丢失响应性
  • 多根组件忘了 v-bind="$attrs"，class / 事件全丢
  • 异步组件 loadingComponent 和 Suspense fallback 叠两层
  • 以为 onMounted / 事件回调里的 await 会被 Suspense 捕获
  • headless 组件没暴露 aria 属性，使用方全部漏做可访问性

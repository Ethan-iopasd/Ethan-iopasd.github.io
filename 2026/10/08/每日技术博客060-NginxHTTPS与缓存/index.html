开场：一句话结论

Nginx 线上事故集中在四处：proxy_pass 尾斜杠改写了 URI、location 优先级猜错、root/alias 用混、证书链没下发全。其余都是细节。

一、HTTPS 与 TLS 加固

项 建议 原因
ssl_protocols TLSv1.2 TLSv1.3 1.0 / 1.1 已被主流合规判死
ssl_ciphers 只留 ECDHE + AEAD 前向保密 + 抗降级
ssl_prefer_server_ciphers off 让现代客户端优先选 ChaCha20
ssl_session_cache shared:SSL:10m 复用会话，省一次完整握手
ssl_stapling on 客户端不必自己去查 OCSP

⚠️ ssl_certificate 必须放证书链（叶子 + 中间）。只放叶子证书时，浏览器常因缓存了中间证书而看不出问题，但 curl / Java / Android / 小程序会报 unable to get local issuer certificate。

⚠️ ssl_stapling 需要能解析 OCSP 地址，没配 resolver 时 OCSP stapling 静默失效，日志里只有一行 warn，握手照常成功。

⚠️ ssl_session_tickets off 会关掉 ticket 复用。TLS 1.3 下会话恢复主要靠 PSK ticket，关掉后恢复率骤降。要前向保密就关，要性能就开，别两头都要。

证书链与 SNI

⚠️ 现代证书用 SAN 列域名，CN 已被浏览器忽略。只填 CN 不填 SAN 的证书在现代浏览器上直接不匹配。

⚠️ 用 IP 直接访问 HTTPS（不带 SNI）会命中 default_server。兜底证书域名和 IP 不匹配时报证书错误 —— 这也是「扫 IP 能扒出你站上第一个域名」的原因。

二、HTTP → HTTPS 跳转与 HSTS

参数 作用
max-age 浏览器强制走 HTTPS 的秒数，必填
includeSubDomains 所有子域一并强制
preload 申请进浏览器内置 HSTS 列表（基本不可撤回）

⚠️ HSTS 一旦下发就无法回退：max-age=31536000 意味着用户在接下来一年里，浏览器拒绝对该域名发起任何 HTTP 连接，也拒绝跳过证书错误页。证书过期或换域名期间，你会彻底失去这批用户。上线前先用小 max-age（如 300）验证。

⚠️ add_header 默认只在 2xx / 3xx 等特定状态码上生效，出错页（500）不会带 HSTS。要所有响应都带，必须加 always。

⚠️ add_header 有继承陷阱：子级 location 只要定义了自己的 add_header，父级（server 块）的所有 add_header 全部失效，不是叠加。

三、proxy_pass 的 URI 替换与 proxy_set_header

规则一句话：**proxy_pass 里有没有 URI（host 后面哪怕只有 /），决定要不要改写路径。**

location proxy_pass 请求 /api/user/1 转发到
/api/ http://backend http://backend/api/user/1
/api/ http://backend/ http://backend/user/1
/api http://backend http://backend/api/user/1
/api http://backend/ http://backend/user/1（/apiuser 会变 /user）
/api/ http://backend/v1/ http://backend/v1/user/1
头 不传的后果
Host 后端拿到 upstream 名或内网 IP，虚拟主机、重定向、签名校验全错
X-Real-IP 后端日志里全是 nginx 的 IP
X-Forwarded-For 拿不到真实客户端，限流 / 风控失效
X-Forwarded-Proto 后端以为请求是 HTTP，生成 http:// 链接 → 混合内容、重定向循环

⚠️ location /api（无尾斜杠）配 proxy_pass http://backend/ 时，/apiuser 会被替换成 /user（剥离的是 /api 而非 /apiuser 的前缀）。location 和 proxy_pass 的尾斜杠要么都带，要么都不带。

⚠️ proxy_pass 里用了变量（如 proxy_pass http://$backend;）时，nginx 不做 URI 替换，无论有没有尾斜杠都原样转发完整 URI。

⚠️ $proxy_add_x_forwarded_for 会把客户端自带的 X-Forwarded-For 原样保留再追加 $remote_addr。取真实 IP 必须从右往左数，取第一个不可信代理之后的那一段，不能直接取最左边的值。

⚠️ Host $host 会丢掉端口号，Host $http_host 保留。后端按带端口的 Host 做签名 / 回调校验时，用 $host 会失败。

四、proxy_cache 反向代理缓存

$upstream_cache_status 含义
HIT / MISS 命中 / 未命中并回源
EXPIRED 缓存过期，回源
BYPASS 被 proxy_cache_bypass 跳过
STALE 用了过期副本（use_stale）
UPDATING 正在后台更新，先返回旧值
REVALIDATED 协商缓存确认未变

⚠️ proxy_cache_key 默认含 $scheme 但**不含 $host**。多站点共用一个 keys_zone 且 key 没带 $host 时，A 站的响应会喂给 B 站 —— 串站。key 里务必带 $host。

⚠️ 只按 $request_uri 做 key 时，?utm_source=... 这类垃圾参数会让命中率趋近 0。key 里应剔除无关 query。

⚠️ 缓存默认不缓存带 Set-Cookie 的响应，也不会自动按 Cookie 区分。带登录态的接口被缓存 = 串号。这类 location 要么 proxy_cache_bypass $cookie_session，要么直接不缓存。

五、浏览器缓存与 gzip

写法 生成的响应头
expires 1y; Expires: <绝对时间> + Cache-Control: max-age=31536000
expires -1; / expires epoch; Cache-Control: no-cache
expires max; Cache-Control: max-age=315360000

⚠️ expires 本身就会生成 Cache-Control，再 add_header Cache-Control "public, immutable" 会出现两个 Cache-Control 头。要么只用 expires，要么只用 add_header。

⚠️ HTML 入口文件被强缓存时，前端发新版本用户永远看不到 —— 入口都不刷新，带指纹的文件名更无从谈起。HTML 用 no-cache，带 hash 的静态资源才用长缓存。

⚠️ no-cache 不是「不缓存」，是「每次必须向服务器确认」。真正禁用缓存是 no-store。

⚠️ gzip_types **默认只含 text/html**，application/json、application/javascript 都要手动加，否则 API 响应一点没压。

⚠️ 没开 gzip_vary 时，中间缓存可能把压缩版发给不支持 gzip 的客户端（或反之），产生乱码。

六、动静分离：location 优先级、try_files 与 root/alias

顺序 匹配方式 说明
1 location = /path 精确匹配，命中即停
2 location ^~ /path 最长前缀命中后跳过所有正则
3 location ~ /re、~* /re 正则，按配置文件出现顺序，第一个命中即停
4 location /path 普通前缀，取最长者兜底

⚠️ 正则按书写顺序匹配，前缀按最长匹配。两条 location ~ 谁在前面谁赢，和长度无关 —— 顺序写反是「配置明明对了却不生效」的头号原因。

⚠️ ^~ 一旦命中最长前缀，后面的正则一律不评估。给 /static/ 加了 ^~ 后，~* \.js$ 那条 expires 对 /static/*.js 就再也不生效了。

⚠️ try_files $uri /index.html; 对所有未命中路径返回 index.html（HTTP 200），包括本该 404 的路径。静态资源也走这条会掩盖 404，让前端错误变成「页面白屏」。

⚠️ alias 的 location 必须以 / 结尾，且 alias 路径也以 / 结尾，否则 /img/a.png 会被拼成 /data/images//a.png（多一个斜杠）。

⚠️ root 写在 server 块会被所有 location 继承，但**任何一个 location 里写了自己的 root**，那个 location 就只用它自己的，不会合并。

七、限流与 return/rewrite

指令 是否重新匹配 location 适用
return 否 跳转、直接响应
rewrite ... break 否 当前 location 内改写 URI
rewrite ... last 是 需要换 location 处理

⚠️ 不加 nodelay 时，burst 里的请求会被延迟排队（按 rate 逐个放行），表现为接口偶发变慢而不是被拒 —— 排查时容易误判成后端慢。

⚠️ 用 $remote_addr 限流，在 nginx 前面还有一层 LB / CDN 时，所有请求都来自同一个 IP，等于给整站上了一把锁。需先用 real_ip 模块还原 $remote_addr。

⚠️ rewrite ... last 在 server 块里会重新走一遍 location 匹配，规则互相指向时直接死循环（报 rewrite or internal redirection cycle）。

⚠️ return 301 https://$host$request_uri; 里的 $request_uri 带原始 query，**不要用 $uri**（$uri 是解码后的规范化路径，query 丢失）。

常见坑清单

  • 只配了叶子证书，没拼中间证书，导致部分客户端验证失败
  • 开了 ssl_stapling 但没配 resolver，OCSP stapling 静默失效
  • HSTS 一上来就 max-age=31536000，出事后一年内无法回退
  • add_header 忘加 always，或子 location 顶掉了 server 块的公共头
  • proxy_pass 尾斜杠写错，路径整体错位
  • proxy_pass 里用了变量，以为会做 URI 替换，实际原样转发
  • 漏传 Host / X-Forwarded-Proto，后端虚拟主机与跳转全错
  • 直接取 X-Forwarded-For 最左边的 IP 当真实 IP（可伪造）
  • proxy_cache_key 没带 $host，多站点缓存串站
  • 缓存了带 Set-Cookie 的登录态接口，用户之间串号
  • HTML 入口文件被长缓存，发版后用户永远看不到新版本
  • 把 no-cache 当成「不缓存」
  • gzip_types 没加 application/json，API 响应没压缩
  • 两条 location ~ 顺序写反，正则规则不生效
  • 给静态前缀加了 ^~，把后面正则的 expires 全屏蔽
  • alias 两端漏写尾斜杠，路径拼出双斜杠
  • limit_req 不加 nodelay，突发请求被排队延迟而不是被拒
  • 前置有 LB 还用 $remote_addr 限流，等于给全站上锁
  • rewrite ... last 规则互相指向，触发重定向死循环
  • 用 $uri 代替 $request_uri 做跳转，query 丢失

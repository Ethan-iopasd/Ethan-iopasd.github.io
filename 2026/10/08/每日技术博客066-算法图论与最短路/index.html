四 图论与最短路 本篇

开场：一句话结论

无权最短路用 BFS，非负权用 Dijkstra，有负权用 Bellman-Ford，全源用 Floyd；依赖解析和判环用拓扑排序，判连通用并查集 —— 这四个覆盖了 90% 的工程场景。

问题 首选
无权图最短路 BFS
非负权最短路 Dijkstra + 优先队列
有负权 / 判负环 Bellman-Ford
全源最短路 Floyd-Warshall
依赖顺序 / 判环 拓扑排序
动态连通性 并查集

一、图的三种表示

表示 空间 判断边 (u,v) 遍历邻居 适用
邻接矩阵 O(V²) O(1) O(V) 稠密图、V 小
邻接表 O(V + E) O(deg) O(deg) 稀疏图（默认选它）
边集 O(E) O(E) O(E) Kruskal、Bellman-Ford

⚠️ V = 10⁵ 时邻接矩阵是 10¹⁰ 个格子，直接内存爆炸 —— 稀疏图（E ≪ V²）必须用邻接表，V > 2000 基本告别矩阵。另外无向图的邻接表要加两条边，用链式前向星时靠 i ^ 1 取反向边，忘记加反向边是最常见的低级 bug。

二、DFS 与 BFS

维度 DFS BFS
结构 栈 / 递归 队列
空间 O(V)（递归深度） O(V)（队列宽度）
最短路 ❌ 不保证 ✅ 无权图最短路
典型用途 连通块、拓扑、SCC、回溯 无权最短路、层序、多源扩散
递归风险 可能爆栈（V = 10⁵） 无
变体 说明
多源 BFS 初始把多个源点全入队，求「到最近源点」的距离
双向 BFS 从起点和终点同时扩展，状态数从 b^d 降到 2·b^(d/2)
0-1 BFS 边权只有 0/1 时用双端队列，O(V+E)，比 Dijkstra 快

⚠️ BFS 只对无权图（或等权图）给出最短路。 边权不等时必须用 Dijkstra —— 用 BFS 求带权最短路是错的，且错得很隐蔽。

⚠️ 双向 BFS 要求「能反向搜索」：有向图里反向边不存在就用不了，且两边扩展要交替进行，只扩一边会退化成单向。

三、拓扑排序

只适用于 DAG（有向无环图），输出一个「所有边都从前指向后」的线性序。

方法 做法 特点
Kahn（入度法） 反复取入度为 0 的点，出队时把邻居入度 −1 天然能判环（输出不足 V 个即有环）
DFS 后序 DFS 完成后逆序输出 实现简单，判环要看有没有回边

⚠️ Kahn 的结果不唯一：多个入度为 0 的点谁先出队都行。想要字典序最小，把队列换成小顶堆（O((V+E) log V)）。

⚠️ 拓扑排序前必须确认无环。 依赖解析、构建系统（Make / Bazel）、包管理器（npm / pip）都靠它 —— 出现环就是「循环依赖」，必须报错而不是给个残缺顺序。

四、并查集（Union-Find / DSU）

维护一组不相交集合，支持合并和查询代表元。

优化 效果
路径压缩 查询近乎 O(1)
按秩 / 按大小合并 树高 O(log V)
两者同时用 均摊 O(α(n))，α 是反阿克曼函数，实际 ≤ 4
应用 说明
判连通 find(a) == find(b)
判环（无向图） 加边时两端已连通 → 有环
Kruskal 按边权排序后逐条合并
带权并查集 维护到根的距离 / 异或，处理「关系」类问题

⚠️ union 前必须先 find 两端，直接改 parent 会破坏结构；判环的返回值必须来自 find 比较，不能靠边数判断。

⚠️ 路径压缩会让 rank 不再等于真实高度，但它仍是个有效的合并依据，不用去修正。

五、最小生成树（MST）

算法 结构 复杂度 适用
Kruskal 边排序 + 并查集 O(E log E) 稀疏图，实现简单
Prim 优先队列 + 已选点集 O(E log V)（堆） 稠密图，或点少边多

⚠️ MST 只对「连通无向图」有定义 —— 不连通时得到的是「最小生成森林」，别硬说它是最小生成树。而且 MST 与最短路是两回事：MST 最小化「所有边权之和」，最短路最小化「两点间路径」，MST 上两点路径不一定是它们之间的最短路。

⚠️ Prim 用「已访问」标记避免重复入队，否则同一节点会被多次入堆，复杂度退化。堆里允许有陈旧条目，出堆时判 visited 即可。

六、最短路四件套

算法 适用 复杂度 能否负权 能否判负环
BFS 无权 / 等权 O(V + E) ❌ ❌
Dijkstra 非负权、单源 O(E log V)（堆） / O(V²)（朴素） ❌ ❌
Bellman-Ford 可负权、单源 O(V·E) ✅ ✅
Floyd-Warshall 全源、V 小 O(V³) ✅ ✅（对角线为负）

⚠️ Floyd 的 k 必须是最外层循环。 写成 i, j, k 嵌套就错了 —— 这本质是「以 k 为中转点的 DP 阶段」，阶段必须在外层。

⚠️ Bellman-Ford 的 V-1 轮不是随便取的：无负环时最短路最多 V-1 条边，第 V 轮还能松弛才说明有负环。有负环时「最短路」不存在（可以无限小），这时要报错而不是给个数字。

⚠️ Dijkstra 不能处理负权，原因是它基于贪心：一旦出堆就认定该点已确定最短，负权边会让「已确定」的点之后还能被改小，贪心前提破裂。

⚠️ **Dijkstra 判重靠 if d > dist[u]: continue**，不要用 visited 数组在入队时判 —— 同一节点可能先以较大距离入堆、后以更小距离再入堆，出堆时取第一个才是最优。

七、A*、SPFA 与 0-1 BFS

算法 说明
A* Dijkstra + 启发式 h(v)，按 f = g + h 出堆；h 必须可采纳（不高估）才保证最优
SPFA Bellman-Ford 的队列优化，平均快，最坏 O(V·E)
0-1 BFS 边权只有 0/1，用双端队列：0 边入队头，1 边入队尾，O(V+E)

⚠️ **SPFA 已被证明能被构造数据卡到 O(V·E)**，是「最坏退化」的代名词 —— 能用 Dijkstra 就别用 SPFA，只有需要负权时它才有价值。同理 A 的 h 一旦高估，就失去最优性保证*：要求最优就必须可采纳（admissible）+ 一致性（consistent），只要求「快、不要求最优」时才允许高估。

⚠️ 0-1 BFS 不能用普通 BFS 替代：权重为 0 的边不增加距离，普通 BFS 按层扩展会得到错误结果，必须用双端队列。

八、强连通分量与二分图

强连通分量（SCC）

算法 特点
Tarjan 一次 DFS，靠 dfn（时间戳）+ low（能回溯到的最小时间戳）+ 栈
Kosaraju 两次 DFS：第一次在原图求后序，第二次在反图上按逆后序 DFS

二分图

概念 判据
二分图判定 能 2-染色（BFS/DFS 交替染色），无奇环
匈牙利算法 求二分图最大匹配，O(V·E)
Hopcroft-Karp 优化到 O(E√V)

⚠️ Tarjan 的 low 更新要区分「树边」和「回边」：树边用 low[v] 更新，回边用 dfn[v] 更新（且不能走回父边）。用混了会算错 SCC 和割点。

⚠️ 二分图判定要处理非连通图，对每个未染色点都要起一次 BFS，否则漏判。匈牙利算法要维护 match 数组并支持「增广路回溯」，不能只做一次贪心匹配 —— 贪心得到的是极大匹配，不是最大匹配。

九、建模套路与工程差异

常见建模转换：

套路 做法
虚拟源点 多起点 → 加一个超级源 S，S 到各起点连 0 边
拆点 点有容量限制 → 拆成「入点 → 出点」，中间连容量边
分层图 有「最多用 k 次免费」→ 建 k+1 层，跨层边权 0
反向建图 求「所有点到某点」的距离 → 建反图跑单源
场景 竞赛 工程
最短路 Dijkstra / SPFA / A* 地图导航、路由、依赖成本
拓扑排序 判环、DP 顺序 构建系统、依赖解析、任务调度
并查集 判环、Kruskal 网络连通、账号合并、集群分组
SCC 缩点 循环依赖检测、模块分层

⚠️ 工程里最常被用到的是拓扑排序和并查集，不是最短路。构建系统（Bazel / Make / Turborepo）、包管理器、CI 任务编排，核心都是拓扑排序 + 环检测。

⚠️ 工程图规模常到 10⁶ 以上，递归 DFS 会爆栈。 生产代码里要么改成显式栈的迭代 DFS，要么用 BFS —— 竞赛里 sys.setrecursionlimit 那一套在服务端不管用。另外别迷信「复杂度更低的一定更快」：V = 100 的稠密图上，朴素 Dijkstra O(V²) 往往快过堆优化的 O(E log V)，常数因子和堆开销在小规模下是主导 —— 先测再优化。

常见坑清单

  • 稀疏图用邻接矩阵，V 一大就内存爆炸
  • 无向图邻接表漏加反向边
  • 用 BFS 求带权图最短路，或用普通 BFS 处理 0-1 权图
  • 双向 BFS 只扩一边，或用于无法反向搜索的有向图
  • 拓扑排序不判环，直接输出残缺顺序；要字典序最小却用普通队列
  • 并查集 union 前不 find，或用边数而不是 find 结果判无向图环
  • 对不连通图求「最小生成树」，或把 MST 当成最短路树
  • Floyd 的三重循环把 k 放在内层
  • Bellman-Ford 只跑 V-1 轮却不做第 V 轮判负环
  • 对含负环的图求「最短路」并给出一个数字
  • 用 Dijkstra 处理负权边
  • Dijkstra 用入队时的 visited 判重（应该出堆时判 d > dist[u]）
  • A* 的启发式高估，还声称结果最优；或在能被卡的图上用 SPFA
  • Tarjan 混淆树边和回边的 low 更新
  • 二分图判定只从一个点起 BFS，漏掉非连通分量
  • 匈牙利算法只做一次贪心匹配，当成最大匹配
  • 工程代码里用递归 DFS 处理 10⁶ 规模图，栈溢出
  • 不看常数因子，盲目选「复杂度更低」的算法

开场：Vue3 只解决两个问题

Vue3 是重写，不是增量更新。它要解决 Vue2 架构上的两个天花板：

  1. 响应式有监听盲区 —— Object.defineProperty 拦不住「新增属性、删除属性、数组下标」
  2. 逻辑被拆散 —— Options API 按「选项类型」切分代码，同一个功能的代码散落在 data / methods / computed 里

对应的两个答案是 Proxy 和 Composition API。其余所有改动（性能、TS、新组件）都建立在这两条之上。

一、Vue3 改了什么

1.1 响应式：Proxy 取代 defineProperty

Vue2 的做法是遍历对象每个属性，逐个改写成 getter/setter：

问题在于它只处理初始化时已存在的属性。三个盲区：

这就解释了 Vue2 里两个「莫名其妙的规定」的由来：

  • 为什么必须用 this.$set() 新增属性 —— 因为要手动补一次 defineProperty
  • 为什么必须用 splice 改数组而不是直接改下标 —— 因为 Vue2 只重写了数组的 7 个方法（push / pop / shift / unshift / splice / sort / reverse），没重写的操作拦不住

Vue3 换成 Proxy，代理整个对象：

defineProperty Proxy
拦截方式 逐个属性打补丁 整个对象套壳
新增属性 ❌ ✅
删除属性 ❌ ✅
数组下标 ❌ ✅
深层对象 初始化时递归全量改写 惰性代理，访问到才代理

最后一条是性能关键：Vue2 启动时要递归遍历整个数据对象，数据量大就卡；Vue3 是访问到哪层才代理哪层。

1.3 性能与体积

指标 提升
打包体积 减少 41%
初次渲染 快 55%
更新渲染 快 133%
内存占用 减少 54%

体积变小主要靠 Tree-Shaking：Vue3 的 API 都拆成了独立模块，没用到的不会进包。Vue2 是 new Vue() 一把梭，整个运行时都得带上。

1.4 TypeScript

Vue3 源码本身用 TS 重写，类型推导是原生的：

  • 模板里 {{ user.nmae }} 拼错，编辑器直接飘红
  • props 可定义类型，父组件传错会提示
  • 组合式函数返回值类型能自动推导

即使不写类型注解，也建议保留 lang="ts" —— 编辑器的提示能力完全不同。

1.5 新特性清单

  • Composition API —— setup / ref / reactive / computed / watch
  • 内置组件 —— Teleport（传送 DOM）、Suspense（异步占位）
  • 多根节点组件 —— 模板不再强制单个根标签
  • v-model 增强 —— 组件上可多次使用，取代 Vue2 的 .sync
  • 全局 API 迁移 —— Vue.component() → app.component()

3.2 reactive

⚠️ reactive 只能接对象，传基本类型会报错。基本类型必须用 ref。

⚠️ 整体替换会丢响应式：

因为 reactive 返回的是原对象的代理，整体替换后变量指向新的普通对象，模板还拿着旧代理。

3.3 ref 还是 reactive

ref reactive
能定义 基本类型 + 对象类型 只能对象类型
.value JS 里要 完全不要
深层响应式 ✅ ✅
整体替换 ✅ 改 .value 即可 ❌ 会失去响应式

ref 接收对象时，内部会自动调用 reactive 把 .value 变成响应式对象 —— 所以 ref 是 reactive 的超集。

选择建议：

场景 用什么
基本类型 ref（必须）
对象，层级不深 ref（风格统一，能整体替换）
对象，层级很深 reactive（少写很多 .value）

一个项目里统一用 ref 是最省心的做法：规则简单（JS 里一律加 .value），不用在两种模式间切换思维。

4.3 watch 监视对象的两个坑

坑一：ref 对象默认只监视「地址值」

坑二：新旧值可能一模一样

操作 newValue / oldValue
改内部属性 person.value.name = 'x' 两者相同，都是新值
整体替换 person.value = {...} 一个是新对象，一个是旧对象

改属性时新旧值相同，因为它们是同一个对象 —— 你改了它的属性，「旧值」也跟着被改了。

reactive 更彻底：newValue 和 oldValue 永远是同一个对象（reactive 没法整体替换）。

结论：不要依赖对象 watch 的 oldValue。要对比新旧值，就监视基本类型或getter 函数。

4.4 watchEffect

5.5 生命周期

阶段 Vue2 Vue3
创建 beforeCreate / created setup
挂载 beforeMount / mounted onBeforeMount / onMounted
更新 beforeUpdate / updated onBeforeUpdate / onUpdated
卸载 beforeDestroy / destroyed onBeforeUnmount / onUnmounted

两个变化：

  • 创建阶段的两个钩子被 setup 取代（setup 执行更早，没必要分两个）
  • destroy 改名 **unmount**（组件是「卸载」不是「销毁」）

最常用的只有三个：

钩子 用来干什么
onMounted 发请求、初始化 DOM 操作
onUpdated 更新后的副作用
onBeforeUnmount 清理定时器、解绑事件

90% 的场景只需要 onMounted。别为了「完整」把所有钩子都写一遍。

六、常见坑清单

  • 以为 ref 变量本身是响应式的 —— 响应式在 .value 上，name = ref('x') 不会更新页面
  • 在模板里写 .value（不用写，编译器自动补）
  • 用 reactive 定义基本类型（报错，要用 ref）
  • reactive 对象整体替换，响应式静默丢失（用 Object.assign）
  • 解构 reactive 或 props 后忘了响应式会丢（用 toRefs）
  • 用 methods 代替 computed 做派生数据（每次都重算，白白浪费性能）
  • watch 监视 ref 对象忘了 deep: true，改内部属性不触发
  • 依赖对象 watch 的 oldValue（新旧值可能完全相同）
  • 在 #app 里写静态内容（挂载时会被清掉）
  • <script setup> 组件忘了 defineExpose，父组件通过 ref 拿到空对象
